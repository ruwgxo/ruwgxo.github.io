Dataset Curation: Building Labelled Security Datasets from Scratch

Section Overview

One Line Summary

A trained classifier is only as good as its training data -- Section 12.04 builds the dataset curation pipeline that makes every subsequent training section credible: rigorous sources, temporal splits, imbalance treatment, and versioned reproducibility.

Why This Section Exists

Sections 12.05 through 12.08 train classifiers. Those classifiers are evaluated with accuracy metrics, precision-recall curves, and ROC-AUC scores. Those metrics are only meaningful if the dataset they are computed on was constructed correctly. A randomly split security dataset produces evaluation metrics that overstate real-world performance by 10-20 percentage points. A dataset trained on public jailbreak corpora and evaluated on the same corpus produces a classifier that fails immediately on production traffic because the public corpus attack distribution does not match the deployment context. Section 12.04 is the infrastructure section that makes every subsequent training section honest. It addresses four requirements that security ML datasets have and standard ML tutorial datasets ignore: source diversity (production traffic, red team exercises, and public corpora with known distribution limitations), temporal splitting (the only evaluation methodology that prevents leakage between training and test sets collected at the same time), class imbalance treatment (security datasets are structurally skewed at 1 attack per 100-1000 requests), and versioned reproducibility (a dataset that cannot be reconstructed exactly produces unreproducible evaluation metrics).

Position In Chapter

Section 12.04 sits between the anomaly detection that seeds labelled data (Section 12.03) and the supervised classifiers that consume it (Section 12.05). It is the data engineering section of Chapter 12. Every line of training code in Sections 12.05 through 12.08 imports the dataset builder and the temporal split from this section.

Prose Content

Part 1

Title

The Dataset Problem in Security ML

Body

The standard advice for an ML practitioner who needs a training dataset is to search Hugging Face, Kaggle, or the relevant academic literature for an existing labelled corpus. For image classification, sentiment analysis, or named entity recognition this is sound advice: the public corpus is large, diverse, and collected from a distribution that resembles the deployment context. For LLM security detection, this advice fails in a specific and dangerous way. Public jailbreak corpora (JailbreakChat.com, the AdvBench dataset, OWASP LLM examples) contain attack examples that were collected from public forums, research papers, and crowdsourced red team exercises. They represent the attack distribution of the past -- the techniques that were novel enough to document publicly before adversaries moved on to the next generation. A classifier trained exclusively on public corpora learns to detect documented historical attacks with high accuracy on those same corpora and fails on the current production attack distribution, which has already adapted past the documented techniques. More critically, the production deployment context determines the benign traffic distribution. A customer support LLM, a code assistant, and a general-purpose chatbot have different benign request distributions: different sequence lengths, different vocabulary, different contextual feature distributions. A benign sample collected from a general-purpose chatbot does not correctly represent the benign distribution of a code assistant -- the classifier trained on it will have a miscalibrated decision boundary for the code assistant deployment. The correct dataset construction methodology has four data sources ranked by distribution fidelity. Production traffic annotation (the anomaly alert labeller output from Section 12.03) is the highest-fidelity source: it contains real attacks against the real system and real benign traffic from the real user population. Red team exercises against the production integration are the second-highest-fidelity source: the attacks are crafted specifically for the deployment context, even if they are not fully representative of adversary behaviour. Public corpora are the third source: useful for padding early training sets when production data is sparse, but with known distribution limitations that must be documented in the dataset card. Synthetic generation is the fourth source: appropriate only for underrepresented attack sub-classes where no real or red team examples exist.

Part 2

Title

Label Schema Design: Binary, Multi-Class, and Multi-Label

Body

The label schema determines what the classifier learns to predict and what operational decisions the prediction can support. Three schema options exist: binary, multi-class, and multi-label. The choice is not arbitrary -- it depends on whether the detection system needs to distinguish between attack families for alert routing and remediation. Binary labelling (attack=1, benign=0) is the simplest schema and the correct starting point when the labelled dataset is small (under 200 total positives) or when the detection system does not need to route alerts to specialist analysts by attack family. Binary labels are easier to assign with high inter-annotator agreement, produce a simpler classifier, and require less training data per decision boundary. The trade-off is that the classifier cannot tell an analyst whether a flagged request is a prompt injection or a jailbreak attempt, limiting the specificity of the operational response. Multi-class labelling (injection / jailbreak / pii_extraction / model_extraction / benign) is appropriate when the labelled dataset has 200+ examples per attack class and the operations team has defined different response procedures for different attack families. Multi-class labels require more annotation effort and produce a more complex decision boundary, but they enable attack-family-specific alert routing, specialist analyst assignment, and family-specific remediation actions (blocking vs rate limiting vs flagging for review). Multi-label classification allows a single request to carry multiple labels simultaneously -- a request can be both a prompt injection and a jailbreak attempt, or both a jailbreak and a PII extraction probe. Multi-label labelling is the most expressive but also the most expensive: annotators must consider all attack families for every example, inter-annotator agreement is harder to achieve and measure, and the classifier requires a separate binary head per label rather than a single softmax output. Multi-label is appropriate only when compound attacks are documented in the threat model and when the annotation team has sufficient domain expertise to identify compound attack patterns reliably. The recommendation for Chapter 12 is to start binary and migrate to multi-class after the 200-per-class threshold is crossed for at least three attack families. The dataset builder in deliverable_1 supports all three schemas with a schema_version tag so that the migration from binary to multi-class is tracked as a dataset version change.

Part 3

Title

Temporal Splits: The Non-Negotiable Methodology

Body

The most consequential dataset construction decision in security ML is the train/test split methodology. Standard ML tutorials use scikit-learn's train_test_split with shuffle=True (the default). This is incorrect for security datasets. The data leakage mechanism is specific and reproducible. A security dataset is collected over time: the earliest examples in the dataset are from the first weeks of the anomaly detector's operation; the most recent examples are from the last few days before the dataset was frozen for training. An adversary who was active in week 2 of the collection period may have sent the same jailbreak attempt multiple times. If those attempts are randomly distributed between the training set and the test set by a shuffled split, the classifier is evaluated on examples from the same adversary campaign as the training examples -- essentially evaluated on near-duplicates of its training data. The measured accuracy of a classifier trained and evaluated on a randomly split security dataset is optimistic by 10-20 percentage points relative to its performance on future production traffic. The evaluation appears to show a highly accurate classifier; the production deployment reveals a less accurate one. The difference is the leakage. Temporal splitting prevents this by sorting the dataset by collection timestamp and assigning the earliest examples to training, the middle window to validation, and the most recent examples to the test set. The test set contains only examples collected after all training examples. The classifier is evaluated on future-relative-to-training data, which is the only meaningful measurement of its generalisation to production traffic. The practical implementation uses three parameters: training fraction (default 70%), validation fraction (default 15%), and test fraction (default 15%). For a dataset with 1000 examples collected over 8 weeks, the training set contains examples from weeks 1-6, the validation set from week 7, and the test set from week 8. The split boundaries are computed by sorting on the collected_at timestamp field and slicing at the cumulative fraction boundaries. One practical complication: early production datasets have sparse attack examples in the earliest weeks (before the anomaly detector has had time to surface many positives) and denser attack examples in later weeks. A strict temporal split may produce a training set with very few attack examples and a test set with more, making the training set unrepresentative of the full attack distribution. The correct response is to use a stratified temporal split that maintains the approximate attack class distribution in each split while preserving the temporal ordering -- not to revert to a random split.

Part 4

Title

Class Imbalance: SMOTE and Class Weighting

Body

Security datasets are structurally imbalanced. In a well-protected production LLM API, the attack rate is between 0.1% and 5% of total traffic -- 1 attack per 20 to 1000 legitimate requests. The labelled dataset reflects this ratio: after 8 weeks of anomaly alert collection with 50% analyst review capacity, a typical dataset has 200-500 labelled attacks and 2000-5000 labelled benign examples. The imbalance ratio is 1:10 to 1:25. A classifier trained on an imbalanced dataset without treatment learns the path of least resistance: predicting the majority class (benign) for every request. This produces accuracy of 90-99% on the training and test sets (because 90-99% of examples are benign), zero recall on the attack class, and zero operational value as a detection system. The accuracy metric looks excellent; the detector catches nothing. Two treatments are standard. SMOTE (Synthetic Minority Oversampling Technique, Chawla et al., 2002) generates synthetic attack examples by interpolating between existing attack examples in the feature space. For each existing attack example, SMOTE selects k nearest neighbours from the attack class and creates a new synthetic example at a random point on the line segment connecting the original to one of its neighbours. The synthetic examples increase the attack class size to a configurable sampling_strategy fraction of the benign class -- typically 0.5 to 1.0 (50% to 100% the size of the benign class). SMOTE is applied exclusively to the training set. The validation and test sets must contain only real examples at the original imbalanced ratio. Applying SMOTE to the test set produces an artificially balanced evaluation that overstates performance on imbalanced production traffic. Class weighting is the alternative treatment that does not generate synthetic examples. Scikit-learn classifiers accept a class_weight parameter that upsamples minority-class gradients during training: the loss function applies a higher weight to misclassified attack examples than to misclassified benign examples. class_weight='balanced' computes weights inversely proportional to class frequency -- a 1:20 imbalance produces an attack class weight of 20 relative to the benign class weight of 1. Class weighting is preferable to SMOTE when the feature space is sparse (SMOTE interpolations in sparse high-dimensional spaces produce unrealistic synthetic examples) or when the training dataset is small (fewer than 100 attack examples makes SMOTE interpolations unreliable). For the security feature vector from Section 12.02 with 20 features and 200+ attack examples, SMOTE is appropriate. Below 100 attack examples, use class_weight='balanced'. Run both and compare on the validation set; the imbalance treatment that produces the higher recall at matched precision on the real imbalanced validation set is the correct choice for the current dataset size.

Part 5

Title

Annotation Quality: Inter-Annotator Agreement

Body

A labelled dataset is only as reliable as its annotation process. An annotation process where different analysts would assign different labels to the same example produces a training set with systematic label noise: the classifier is trained to predict an inconsistently defined concept and its decision boundary is blurred by the inconsistency. Inter-annotator agreement measures the consistency of the annotation process. For binary labelling (attack/benign), Cohen kappa is the standard metric: it measures the agreement between two annotators above the level expected by chance. Kappa ranges from -1 (perfect disagreement) to 1 (perfect agreement), with 0 representing chance-level agreement. A kappa above 0.80 indicates strong agreement and a reliable annotation process. A kappa between 0.60 and 0.80 indicates moderate agreement and an annotation process that may need clearer guidelines. A kappa below 0.60 means the label schema is ambiguous and the training data will have significant noise. For multi-class labelling with more than two annotators, Fleiss kappa generalises Cohen kappa to k annotators and m categories. The same thresholds apply: above 0.80 for reliable annotation, investigate and revise guidelines below 0.60. In practice, annotation agreement is measured on a calibration set of 50-100 examples that every annotator labels independently before the main annotation run begins. If kappa is above 0.80, proceed with single-annotator labelling for the remainder of the dataset. If kappa is below 0.80, hold a calibration discussion, revise the annotation guidelines to resolve the disagreements, and re-measure on a new calibration set before proceeding. Disagreement on specific example types is informative: if annotators consistently disagree on ambiguous phrasing that could be either a boundary-testing legitimate query or a low-confidence jailbreak attempt, those examples should be labelled as 'uncertain' and excluded from training. Training on uncertain examples adds label noise without adding signal.

Part 6

Title

Dataset Versioning with DVC

Body

A trained classifier is reproducible only if its training dataset is reproducible. Without dataset versioning, the dataset used for training model version 3 cannot be reconstructed after the annotation queue has received new labels, production traffic has added more examples, or the label schema has been updated from binary to multi-class. When model version 3 produces unexpected results in production and the team wants to retrain to investigate, they cannot reproduce the exact training conditions. DVC (Data Version Control) extends Git's versioning model to large binary files and datasets. It stores a small .dvc metadata file in the Git repository that references the dataset content by hash, and stores the actual dataset content in a configured remote storage (S3, GCS, or local storage). A git commit that tags a model training run includes both the training code (tracked by Git) and the dataset hash (tracked by DVC). Any prior model training run can be reproduced exactly by checking out the tagged commit and running dvc pull to restore the dataset version from remote storage. The dataset versioning workflow for Chapter 12 has three tracked artefacts: the raw annotation queue (raw_annotations.jsonl), the processed dataset with temporal split (dataset_v{n}.parquet), and the SMOTE-augmented training set (train_smote_v{n}.parquet). Each is tracked by DVC with a content hash. The version number increments when any of the three artefacts changes: new annotations added, label schema updated, or SMOTE parameters changed. The model registry in Section 12.13 stores the dataset version tag alongside every trained model so that the training conditions of any production model can be reproduced in full.

# security_dataset_builder.py
# Section 12.04: Security Dataset Builder
# 20260606 | AI Security Mastery -- Chapter 12 by Raghav Dinesh
# Single quotes throughout per book convention

from __future__ import annotations

import hashlib
import json
from dataclasses import dataclass, field
from pathlib import Path
from typing import Dict, List, Literal, Optional, Tuple

import numpy as np
import pandas as pd

SCHEMA_VERSION = '1.0.0'
VALID_BINARY_LABELS = {0, 1}
VALID_MULTICLASS_LABELS = {
    'benign', 'prompt_injection', 'jailbreak',
    'pii_extraction', 'model_extraction', 'other_attack',
}
LabelSchema = Literal['binary', 'multiclass', 'multilabel']


@dataclass
class DatasetConfig:
    label_schema: LabelSchema = 'binary'
    train_frac: float = 0.70
    val_frac: float = 0.15
    test_frac: float = 0.15
    min_examples_per_class: int = 50
    deduplicate: bool = True
    output_dir: str = 'dataset'

    def __post_init__(self) -> None:
        assert abs(self.train_frac + self.val_frac + self.test_frac - 1.0) < 1e-6, \
            'Split fractions must sum to 1.0'


@dataclass
class LabelledExample:
    text: str
    label: int                        # binary: 0/1
    attack_class: str                 # multiclass label string
    source: str                       # production / red_team / public / synthetic
    collected_at_ms: float            # unix ms timestamp -- used for temporal sort
    text_hash: str = field(init=False)

    def __post_init__(self) -> None:
        self.text_hash = hashlib.sha256(self.text.encode()).hexdigest()[:16]


class SecurityDatasetBuilder:
    '''
    Builds a labelled security dataset from four sources with deduplication,
    schema validation, temporal splitting, and provenance tracking.
    '''

    def __init__(self, config: DatasetConfig) -> None:
        self.config = config
        self._examples: List[LabelledExample] = []
        self._seen_hashes: set = set()

    # ------------------------------------------------------------------
    # Source ingestion
    # ------------------------------------------------------------------

    def ingest_annotation_queue(self, queue_path: str) -> int:
        '''
        Ingest confirmed TPs from the Section 12.03 anomaly alert labeller
        supervised_training_queue.jsonl. Each line is a JSON record with
        fields: text, label (1), attack_class, source, added_at_ms.
        '''
        path = Path(queue_path)
        if not path.exists():
            print(f'  Queue not found: {queue_path}')
            return 0
        added = 0
        with open(path) as f:
            for line in f:
                r = json.loads(line.strip())
                ex = LabelledExample(
                    text=r['text'],
                    label=int(r.get('label', 1)),
                    attack_class=r.get('attack_class', 'unknown'),
                    source='production',
                    collected_at_ms=float(r.get('added_at_ms', 0.0)),
                )
                if self._add(ex):
                    added += 1
        print(f'  Ingested {added} examples from production annotation queue.')
        return added

    def ingest_red_team(self, json_path: str) -> int:
        '''
        Ingest red team exercise results from a JSON file.
        Expected format: list of {text, label, attack_class, collected_at_ms}.
        '''
        path = Path(json_path)
        if not path.exists():
            print(f'  Red team file not found: {json_path}')
            return 0
        records = json.loads(path.read_text())
        added = sum(
            1 for r in records
            if self._add(LabelledExample(
                text=r['text'], label=int(r['label']),
                attack_class=r.get('attack_class', 'unknown'),
                source='red_team',
                collected_at_ms=float(r.get('collected_at_ms', 1_000_000.0)),
            ))
        )
        print(f'  Ingested {added} examples from red team file.')
        return added

    def ingest_public_corpus(self, corpus_path: str, label: int = 1, attack_class: str = 'jailbreak') -> int:
        '''
        Ingest a public jailbreak corpus (one text per line).
        Assigns a fixed past timestamp (collected_at_ms=1) so public corpus
        examples always sort before production data in the temporal split.
        '''
        path = Path(corpus_path)
        if not path.exists():
            print(f'  Corpus not found: {corpus_path}')
            return 0
        added = 0
        with open(path) as f:
            for i, line in enumerate(f):
                text = line.strip()
                if not text:
                    continue
                ex = LabelledExample(
                    text=text, label=label, attack_class=attack_class,
                    source='public', collected_at_ms=float(i + 1),
                )
                if self._add(ex):
                    added += 1
        print(f'  Ingested {added} examples from public corpus.')
        return added

    def ingest_benign_sample(self, texts: List[str], collected_at_ms: List[float]) -> int:
        '''Ingest a list of confirmed benign traffic samples.'''
        assert len(texts) == len(collected_at_ms)
        added = sum(
            1 for text, ts in zip(texts, collected_at_ms)
            if self._add(LabelledExample(
                text=text, label=0, attack_class='benign',
                source='production', collected_at_ms=ts,
            ))
        )
        print(f'  Ingested {added} benign examples.')
        return added

    def _add(self, ex: LabelledExample) -> bool:
        if self.config.deduplicate and ex.text_hash in self._seen_hashes:
            return False
        self._seen_hashes.add(ex.text_hash)
        self._examples.append(ex)
        return True

    # ------------------------------------------------------------------
    # Validation
    # ------------------------------------------------------------------

    def validate(self) -> List[str]:
        issues = []
        n_attack = sum(1 for e in self._examples if e.label == 1)
        n_benign = sum(1 for e in self._examples if e.label == 0)
        if n_attack < self.config.min_examples_per_class:
            issues.append(
                f'Attack examples ({n_attack}) below minimum ({self.config.min_examples_per_class}). '
                f'Continue anomaly alert collection before training.'
            )
        if n_benign < self.config.min_examples_per_class:
            issues.append(f'Benign examples ({n_benign}) below minimum.')
        if n_attack > 0 and n_benign / n_attack > 50:
            issues.append(
                f'Imbalance ratio {n_benign/n_attack:.0f}:1 -- apply SMOTE or class_weight '
                f'before training (Section 12.04 deliverable_3).'
            )
        return issues

    # ------------------------------------------------------------------
    # Temporal split
    # ------------------------------------------------------------------

    def build(self) -> Tuple[pd.DataFrame, pd.DataFrame, pd.DataFrame]:
        '''
        Sort by collected_at_ms (temporal order) and split into
        train / validation / test DataFrames.

        Returns (train_df, val_df, test_df).
        '''
        issues = self.validate()
        for issue in issues:
            print(f'  WARN: {issue}')

        df = pd.DataFrame([{
            'text': e.text,
            'label': e.label,
            'attack_class': e.attack_class,
            'source': e.source,
            'collected_at_ms': e.collected_at_ms,
            'text_hash': e.text_hash,
        } for e in self._examples])

        # Temporal sort -- the only valid split for security ML
        df = df.sort_values('collected_at_ms').reset_index(drop=True)

        n = len(df)
        train_end = int(n * self.config.train_frac)
        val_end = train_end + int(n * self.config.val_frac)

        train_df = df.iloc[:train_end].copy()
        val_df = df.iloc[train_end:val_end].copy()
        test_df = df.iloc[val_end:].copy()

        self._print_split_summary(train_df, val_df, test_df)
        return train_df, val_df, test_df

    def _print_split_summary(
        self,
        train: pd.DataFrame,
        val: pd.DataFrame,
        test: pd.DataFrame,
    ) -> None:
        print('\nDataset split summary (temporal):')
        for name, df in [('train', train), ('val', val), ('test', test)]:
            n_atk = (df['label'] == 1).sum()
            n_ben = (df['label'] == 0).sum()
            ratio = f'{n_ben/max(n_atk,1):.1f}:1'
            ts_range = (
                f'{df["collected_at_ms"].min():.0f} -- {df["collected_at_ms"].max():.0f} ms'
                if len(df) > 0 else 'empty'
            )
            print(f'  {name:<6}: {len(df):>5} examples  '
                  f'attack={n_atk}  benign={n_ben}  '
                  f'imbalance={ratio}  ts=[{ts_range}]')

    # ------------------------------------------------------------------
    # Persistence
    # ------------------------------------------------------------------

    def save(
        self,
        train_df: pd.DataFrame,
        val_df: pd.DataFrame,
        test_df: pd.DataFrame,
        version: str = 'v1',
    ) -> Dict[str, str]:
        out = Path(self.config.output_dir)
        out.mkdir(parents=True, exist_ok=True)
        paths = {}
        for name, df in [('train', train_df), ('val', val_df), ('test', test_df)]:
            p = str(out / f'{name}_{version}.parquet')
            df.to_parquet(p, index=False)
            paths[name] = p
            print(f'  Saved {name} -> {p}')
        # Save dataset card
        card = {
            'schema_version': SCHEMA_VERSION,
            'dataset_version': version,
            'label_schema': self.config.label_schema,
            'split_fractions': {
                'train': self.config.train_frac,
                'val': self.config.val_frac,
                'test': self.config.test_frac,
            },
            'split_methodology': 'temporal -- sorted by collected_at_ms',
            'sources': list({e.source for e in self._examples}),
            'total_examples': len(self._examples),
            'attack_examples': sum(1 for e in self._examples if e.label == 1),
            'benign_examples': sum(1 for e in self._examples if e.label == 0),
        }
        card_path = str(out / f'dataset_card_{version}.json')
        Path(card_path).write_text(json.dumps(card, indent=2))
        paths['card'] = card_path
        print(f'  Saved dataset card -> {card_path}')
        return paths


if __name__ == '__main__':

# class_imbalance_handler.py
# Section 12.04: Class Imbalance Handler (SMOTE + Class Weighting)
# 20260606 | AI Security Mastery -- Chapter 12 by Raghav Dinesh
# Single quotes throughout per book convention

from __future__ import annotations

from dataclasses import dataclass
from typing import Dict, Optional, Tuple

import numpy as np
import pandas as pd
from imblearn.over_sampling import SMOTE
from sklearn.utils.class_weight import compute_class_weight


@dataclass
class ImbalanceReport:
    original_attack: int
    original_benign: int
    original_ratio: float
    treated_attack: int
    treated_benign: int
    treated_ratio: float
    treatment: str
    class_weights: Dict[int, float]


def log_imbalance(label: str, y: np.ndarray) -> None:
    n_atk = (y == 1).sum()
    n_ben = (y == 0).sum()
    ratio = n_ben / max(n_atk, 1)
    print(f'  {label}: attack={n_atk}  benign={n_ben}  ratio={ratio:.1f}:1')


def apply_smote(
    X_train: np.ndarray,
    y_train: np.ndarray,
    sampling_strategy: float = 0.5,
    k_neighbors: int = 5,
    random_state: int = 42,
) -> Tuple[np.ndarray, np.ndarray]:
    '''
    Apply SMOTE to the training set to oversample the minority (attack) class.

    sampling_strategy=0.5 means the attack class will be oversampled to 50%
    of the size of the benign class after SMOTE.

    RULE: NEVER call this on validation or test data.
    '''
    print('\nApplying SMOTE to training set:')
    log_imbalance('before', y_train)

    n_attack = (y_train == 1).sum()
    if n_attack < k_neighbors + 1:
        print(f'  WARN: {n_attack} attack examples < k_neighbors ({k_neighbors}). '
              f'Reduce k_neighbors or use class_weight instead.')
        return X_train, y_train

    smote = SMOTE(
        sampling_strategy=sampling_strategy,
        k_neighbors=k_neighbors,
        random_state=random_state,
    )
    X_res, y_res = smote.fit_resample(X_train, y_train)
    log_imbalance('after', y_res)
    return X_res, y_res


def compute_class_weights(y_train: np.ndarray) -> Dict[int, float]:
    '''
    Compute class weights inversely proportional to class frequency.
    Pass as class_weight parameter to sklearn classifiers.
    '''
    classes = np.unique(y_train)
    weights = compute_class_weight(class_weight='balanced', classes=classes, y=y_train)
    weight_dict = dict(zip(classes.tolist(), weights.tolist()))
    print(f'\nComputed class weights: {weight_dict}')
    return weight_dict


def recommend_treatment(y_train: np.ndarray, min_smote_examples: int = 100) -> str:
    '''
    Returns the recommended imbalance treatment given the training set composition.
    '''
    n_attack = (y_train == 1).sum()
    if n_attack >= min_smote_examples:
        return 'smote'
    return 'class_weight'


def apply_imbalance_treatment(
    X_train: np.ndarray,
    y_train: np.ndarray,
    X_val: np.ndarray,
    y_val: np.ndarray,
    X_test: np.ndarray,
    y_test: np.ndarray,
    sampling_strategy: float = 0.5,
) -> Tuple[np.ndarray, np.ndarray, Dict[int, float], ImbalanceReport]:
    '''
    Apply the recommended imbalance treatment to the training set only.
    Validates that val and test sets are unchanged.
    Returns (X_train_treated, y_train_treated, class_weights, report).
    '''
    treatment = recommend_treatment(y_train)
    print(f'\nRecommended treatment: {treatment}')

    orig_attack = int((y_train == 1).sum())
    orig_benign = int((y_train == 0).sum())

    if treatment == 'smote':
        X_out, y_out = apply_smote(X_train, y_train, sampling_strategy)
    else:
        print('\nUsing class_weight (too few attack examples for SMOTE).')
        X_out, y_out = X_train, y_train

    weights = compute_class_weights(y_train)  # always compute from original

    # Validate val and test are untouched
    assert X_val.shape == X_val.shape, 'Validation set modified -- this is a bug.'
    assert X_test.shape == X_test.shape, 'Test set modified -- this is a bug.'

    report = ImbalanceReport(
        original_attack=orig_attack,
        original_benign=orig_benign,
        original_ratio=orig_benign / max(orig_attack, 1),
        treated_attack=int((y_out == 1).sum()),
        treated_benign=int((y_out == 0).sum()),
        treated_ratio=int((y_out == 0).sum()) / max(int((y_out == 1).sum()), 1),
        treatment=treatment,
        class_weights=weights,
    )
    return X_out, y_out, weights, report

# Section 12.04: DVC-Based Dataset Versioning
# 20260606 | AI Security Mastery -- Chapter 12 by Raghav Dinesh

from __future__ import annotations

import hashlib
import json
import subprocess
from dataclasses import dataclass
from pathlib import Path
from typing import List, Optional


@dataclass
class DatasetVersion:
    version_tag: str
    dataset_paths: List[str]
    content_hashes: dict
    schema_version: str
    created_at: str
    description: str


def _sha256(path: str) -> str:
    h = hashlib.sha256()
    with open(path, 'rb') as f:
        for chunk in iter(lambda: f.read(8192), b''):
            h.update(chunk)
    return h.hexdigest()[:16]


def _run(cmd: List[str], cwd: Optional[str] = None) -> str:
    result = subprocess.run(cmd, capture_output=True, text=True, cwd=cwd)
    if result.returncode != 0:
        print(f'  CMD: {" ".join(cmd)}')
        print(f'  STDERR: {result.stderr.strip()}')
    return result.stdout.strip()


class DatasetVersioner:
    '''
    DVC-based versioning for security ML datasets.

    Workflow:
      1. version(paths, tag, description) -- add files to DVC, commit, tag
      2. restore(tag) -- checkout tag and dvc pull to restore dataset state
      3. list_versions() -- show all tagged dataset versions
    '''

    def __init__(self, repo_root: str = '.', dvc_remote: Optional[str] = None) -> None:
        self.repo_root = Path(repo_root)
        self.dvc_remote = dvc_remote
        self._versions_file = self.repo_root / '.dataset_versions.json'

    def _ensure_dvc_init(self) -> None:
        dvc_dir = self.repo_root / '.dvc'
        if not dvc_dir.exists():
            print('Initialising DVC...')
            _run(['dvc', 'init'], cwd=str(self.repo_root))
            if self.dvc_remote:
                _run(['dvc', 'remote', 'add', '-d', 'storage', self.dvc_remote],
                     cwd=str(self.repo_root))
            print('DVC initialised.')

    def version(
        self,
        dataset_paths: List[str],
        tag: str,
        description: str,
        schema_version: str = '1.0.0',
    ) -> DatasetVersion:
        '''
        Add dataset files to DVC tracking, commit to Git, and tag.
        '''
        import datetime
        self._ensure_dvc_init()

        hashes = {}
        for p in dataset_paths:
            if not Path(p).exists():
                print(f'  WARN: {p} not found, skipping.')
                continue
            _run(['dvc', 'add', p], cwd=str(self.repo_root))
            hashes[p] = _sha256(p)
            print(f'  DVC tracked: {p} (hash={hashes[p]})')

        dv = DatasetVersion(
            version_tag=tag,
            dataset_paths=dataset_paths,
            content_hashes=hashes,
            schema_version=schema_version,
            created_at=datetime.datetime.utcnow().isoformat(),
            description=description,
        )

        # Persist version metadata
        versions = self._load_versions()
        versions[tag] = dv.__dict__
        self._versions_file.write_text(json.dumps(versions, indent=2))

        # Git commit and tag
        _run(['git', 'add', '.'], cwd=str(self.repo_root))
        _run(['git', 'commit', '-m', f'Dataset version {tag}: {description}'],
             cwd=str(self.repo_root))
        _run(['git', 'tag', tag], cwd=str(self.repo_root))
        print(f'  Tagged: {tag}')

        if self.dvc_remote:
            _run(['dvc', 'push'], cwd=str(self.repo_root))
            print('  Pushed to DVC remote.')

        return dv

    def restore(self, tag: str) -> None:
        '''Checkout a prior dataset version by Git tag and pull dataset files.'''
        print(f'Restoring dataset version: {tag}')
        _run(['git', 'checkout', tag], cwd=str(self.repo_root))
        _run(['dvc', 'pull'], cwd=str(self.repo_root))
        print(f'  Restored. Dataset files at state of tag {tag}.')

    def list_versions(self) -> None:
        versions = self._load_versions()
        if not versions:
            print('No dataset versions found.')
            return
        print('Dataset versions:')
        for tag, meta in sorted(versions.items()):
            print(f'  [{tag}] {meta["created_at"]} -- {meta["description"]}')
            print(f'    files: {meta["dataset_paths"]}')
            print(f'    hashes: {meta["content_hashes"]}')

    def _load_versions(self) -> dict:
        if not self._versions_file.exists():
            return {}
        return json.loads(self._versions_file.read_text())

# inter_annotator_agreement.py
# Section 12.04: Inter-Annotator Agreement Measurement
# 20260606 | AI Security Mastery -- Chapter 12 by Raghav Dinesh

from __future__ import annotations

from dataclasses import dataclass
from typing import Dict, List, Tuple

import numpy as np
from sklearn.metrics import cohen_kappa_score


KAPPA_THRESHOLDS = {
    'strong':   0.80,
    'moderate': 0.60,
    'weak':     0.40,
}

LABEL_CLASSES = ['benign', 'prompt_injection', 'jailbreak', 'pii_extraction', 'model_extraction', 'uncertain']


@dataclass
class AgreementReport:
    kappa: float
    agreement_level: str
    action_required: str
    per_class_disagreement: Dict[str, float]
    n_examples: int
    n_disagreements: int


def cohen_kappa(labels_a: List[str], labels_b: List[str]) -> Tuple[float, AgreementReport]:
    '''
    Compute Cohen kappa between two annotators.
    labels_a, labels_b: lists of string labels of equal length.
    '''
    assert len(labels_a) == len(labels_b), 'Annotator label lists must be equal length.'
    kappa = float(cohen_kappa_score(labels_a, labels_b))

    disagreements = [i for i, (a, b) in enumerate(zip(labels_a, labels_b)) if a != b]
    n_dis = len(disagreements)

    # Per-class disagreement: how often does each class appear in a disagreement?
    per_class: Dict[str, int] = {c: 0 for c in LABEL_CLASSES}
    for i in disagreements:
        per_class[labels_a[i]] = per_class.get(labels_a[i], 0) + 1
        per_class[labels_b[i]] = per_class.get(labels_b[i], 0) + 1
    per_class_rate = {c: v / max(n_dis * 2, 1) for c, v in per_class.items() if v > 0}

    level, action = _interpret_kappa(kappa)
    report = AgreementReport(
        kappa=kappa,
        agreement_level=level,
        action_required=action,
        per_class_disagreement=per_class_rate,
        n_examples=len(labels_a),
        n_disagreements=n_dis,
    )
    return kappa, report


def fleiss_kappa(ratings_matrix: np.ndarray) -> float:
    '''
    Compute Fleiss kappa for k annotators and m categories.
    ratings_matrix: shape (n_examples, m_categories) where each cell is
    the number of annotators who assigned that category to that example.
    '''
    n, m = ratings_matrix.shape
    n_raters = ratings_matrix.sum(axis=1)
    assert np.all(n_raters == n_raters[0]), 'All examples must have same number of raters.'
    k = int(n_raters[0])

    p_j = ratings_matrix.sum(axis=0) / (n * k)
    P_i = ((ratings_matrix ** 2).sum(axis=1) - k) / (k * (k - 1))
    P_bar = P_i.mean()
    P_e_bar = (p_j ** 2).sum()

    if abs(1.0 - P_e_bar) < 1e-10:
        return 1.0
    return float((P_bar - P_e_bar) / (1.0 - P_e_bar))


def _interpret_kappa(kappa: float) -> Tuple[str, str]:
    if kappa >= KAPPA_THRESHOLDS['strong']:
        return ('strong', 'Proceed with single-annotator labelling.')
    elif kappa >= KAPPA_THRESHOLDS['moderate']:
        return ('moderate', 'Hold calibration discussion; revise guidelines for edge cases; re-measure.')
    elif kappa >= KAPPA_THRESHOLDS['weak']:
        return ('weak', 'Do not proceed. Redesign label schema; conduct team training; re-measure from scratch.')
    else:
        return ('poor', 'Stop annotation. Escalate to detection engineering lead. Revisit attack taxonomy.')


def print_agreement_report(report: AgreementReport, annotator_names: Tuple[str, str] = ('A', 'B')) -> None:
    print(f'Inter-Annotator Agreement: {annotator_names[0]} vs {annotator_names[1]}')
    print(f'  Kappa:            {report.kappa:.3f}')
    print(f'  Agreement level:  {report.agreement_level.upper()}')
    print(f'  Examples:         {report.n_examples}')
    print(f'  Disagreements:    {report.n_disagreements} ({report.n_disagreements/report.n_examples:.1%})')
    print(f'  Action:           {report.action_required}')
    if report.per_class_disagreement:
        print('  Per-class disagreement rate:')
        for cls, rate in sorted(report.per_class_disagreement.items(), key=lambda x: -x[1]):
            bar = '#' * int(rate * 20)
            print(f'    {cls:<20} {rate:.2%}  {bar}')

Common Mistakes

Mistake 1

Description

Using a random train/test split instead of a temporal split, producing evaluation metrics that overstate production performance by 10-20 percentage points

Why It Happens

sklearn.train_test_split() defaults to shuffle=True. Every ML tutorial uses it. The engineer follows the tutorial pattern, produces a 94% accurate classifier in evaluation, deploys it, and observes 74% accuracy on the first week of production traffic. The gap is entirely due to leakage from the random split.

Consequence

The test set contains examples from the same time window and adversary campaigns as the training set. The classifier memorises campaign-specific patterns that are not present in future traffic. The evaluation metrics are optimistic by the margin of that memorisation. The production failure is silent: the classifier continues to produce predictions; they are just wrong at a rate higher than the evaluation indicated.

Correct Approach

Sort the dataset by collected_at_ms and split at the cumulative fraction boundaries. The security_dataset_builder.py in deliverable_1 implements this correctly. Never pass shuffle=True or use train_test_split without setting shuffle=False and sorting by timestamp first.

Mistake 2

Description

Applying SMOTE to the validation and test sets alongside the training set

Why It Happens

The engineer imports SMOTE and applies it to all three splits in a single call, treating imbalance treatment as a data preprocessing step that applies uniformly. The sklearn Pipeline API makes this easy to do accidentally if SMOTE is added as a pipeline step that runs before the split.

Consequence

The validation and test sets no longer reflect the real production class distribution. A 1:20 attack:benign dataset becomes a 1:2 or 1:1 dataset in the evaluation sets. Every metric computed on these sets -- precision, recall, F1, ROC-AUC -- is computed against an artificially balanced distribution. The classifier appears to perform well on balanced evaluation; deployed on 1:20 imbalanced production traffic it produces high false positive rates that were invisible in the synthetic evaluation distribution.

Correct Approach

Apply SMOTE only after the temporal split, and only to the training DataFrame. The apply_smote() function in deliverable_3 takes X_train and y_train as separate inputs. Call it after building the split, never before. The validation and test sets always remain at the original imbalanced ratio.

Mistake 3

Description

Treating public jailbreak corpora as the primary data source and evaluating on the same corpus used for training

Why It Happens

Public corpora (JailbreakChat.com, AdvBench) are large, freely available, and immediately usable. An engineer who needs to demonstrate a working classifier quickly trains on 80% of the public corpus and evaluates on the remaining 20%. The classifier reaches 96% accuracy. This is reported as production-ready.

Consequence

The public corpus represents historical attack techniques that adversaries have already moved past. A classifier trained and evaluated on the same historical corpus learns corpus-specific patterns (specific phrasing, character distributions, formatting conventions common in the corpus). Deployed on production traffic, it faces current attack techniques that were not in the corpus, and the measured 96% accuracy collapses to 50-60% on novel techniques.

Correct Approach

Use public corpora only as a supplementary training source, never as the sole source, and never as the test set. The test set must contain only production-traffic examples collected after all training examples. Document in the dataset card which fraction of training data came from public corpora so the distribution limitation is explicit.

Mistake 4

Description

Skipping inter-annotator agreement measurement and proceeding directly to full annotation with a single analyst

Why It Happens

A single analyst is assigned to the annotation task. Inter-annotator agreement requires two annotators and a calibration set, which seems unnecessary when only one analyst is available. The engineer skips it as an overhead not worth the effort on a small dataset.

Consequence

Without an agreement measurement, there is no way to know whether the annotation process is reliable. A single analyst who is inconsistent -- labelling edge cases differently on different days, or applying a different threshold for 'uncertain' in week 1 versus week 4 -- produces label noise that is invisible in the dataset. The classifier is trained on an inconsistently labelled dataset and its decision boundary reflects the analyst's inconsistency rather than the true attack/benign distinction.

Correct Approach

Measure intra-annotator agreement (the same analyst labels the same 50 examples twice, one week apart) if only one analyst is available. A kappa below 0.80 on intra-annotator agreement means the analyst's own labelling is inconsistent and the annotation guidelines need clarification before full annotation proceeds. The inter_annotator_agreement.py in deliverable_5 supports intra-annotator measurement by passing the same annotator's labels as both inputs.

Mistake 5

Description

Not versioning the dataset and being unable to reproduce prior model training runs when a production incident requires investigation

Why It Happens

Dataset versioning requires DVC setup and a remote storage configuration. For a first prototype, this seems like engineering overhead that can be added later. The engineer trains the first classifier without versioning, adds more annotations over the following weeks, and by the time a production incident occurs the original training dataset no longer exists in its original form.

Consequence

Model version 2 is deployed and produces unexpected false positives on a specific request pattern. To investigate, the team needs to retrain model version 1 on its original dataset to isolate whether the issue is in the new training data or the new model architecture. Without dataset versioning, model version 1 cannot be reproduced. The investigation is inconclusive and the root cause is not identified.

Correct Approach

Set up DVC at the start of the dataset construction phase, not after the first model has been trained. The dataset_versioner.py in deliverable_4 handles DVC initialisation and tagging. The model registry in Section 12.13 stores the dataset version tag alongside every model so that any production model's training conditions can be reproduced by checking out the tagged dataset version and running dvc pull.

Section Summary

Compact

Security ML datasets have four requirements that standard ML tutorial datasets ignore. Source diversity: production traffic annotation (highest fidelity), red team exercises, public corpora (supplementary only), and synthetic generation for underrepresented classes. Temporal splitting: sorting by collected_at_ms and slicing at cumulative fraction boundaries -- the only methodology that prevents leakage between training and test examples from the same adversary campaign. Class imbalance treatment: SMOTE oversampling on the training set only (100+ attack examples), or class_weight='balanced' for smaller datasets, to prevent classifiers from learning to predict benign for every request. Versioned reproducibility: DVC tracking of all dataset artefacts with content hashes linked to Git tags so that any prior model training run can be reproduced exactly. The dataset card documents all of these choices. Inter-annotator agreement above kappa 0.80 is the entry gate for beginning full annotation.

Key Takeaways

  • Temporal splitting is non-negotiable for security ML evaluation -- a random split leaks adversary campaign patterns from training into test, inflating metrics by 10-20 percentage points
  • Public jailbreak corpora are supplementary training sources only; they represent historical attack distributions and must never be the primary test set source
  • SMOTE is applied to the training set only -- the validation and test sets must remain at the original imbalanced ratio to reflect production traffic distribution
  • A classifier trained without class imbalance treatment on a 1:20 attack:benign dataset learns to predict benign for every request; accuracy of 95% means nothing if recall is zero
  • Inter-annotator kappa above 0.80 is the minimum bar before full annotation begins; below 0.60 the label schema is ambiguous and the resulting training data will have systematic label noise
  • Dataset versioning is a production requirement, not an optional best practice -- every model in the registry must be linkable to the exact dataset version used for training
