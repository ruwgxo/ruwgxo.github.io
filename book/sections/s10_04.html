PGD: Projected Gradient Descent

Section Overview

One Line Summary

PGD solves the inner maximisation problem of robust optimisation by iterating FGSM steps with projection back onto the epsilon ball, making it the canonical empirical robustness evaluation adversary.

Why This Section Exists

PGD is the section with the most production consequence in Chapter 10. Every empirical robustness claim in the adversarial ML literature is evaluated against PGD. Section 10.15 adversarial training uses PGD as the inner optimiser. Section 10.14 certified robustness is evaluated against PGD. The detection primitives in Sections 10.11-10.12 are calibrated against PGD. Understanding PGD precisely -- not as "iterative FGSM" but as the solution to the inner maximisation problem of the Madry et al. robust optimisation framework -- is the prerequisite for every defence section that follows.

Position In Chapter

Section 10.4 is the second white-box attack implementation and the most important evaluation tool in Chapter 10. It inherits the FGSM gradient-sign primitive from Section 10.3 and adds the projection operator, step-size hyperparameter, and random restart. Every subsequent defence claim -- "robust to PGD at epsilon=8/255" -- is measured with the evaluator built in this section.

Prose Content

Part 1

Title

Madry et al. 2018: The Robust Optimisation Framework

Body

Madry, Makelov, Schmidt, Tsipras, and Vladu published "Towards Deep Learning Models Resistant to Adversarial Attacks" in 2018. The paper''s central contribution was not a new attack -- it was a new problem formulation that placed adversarial training on rigorous optimisation footing and identified PGD as the natural inner adversary. The standard training objective is: min_theta E_{(x,y)~D}[L(f_theta(x), y)]. This minimises expected loss over the natural data distribution. The Madry et al. robust training objective is: min_theta E_{(x,y)~D}[max_{delta: ||delta||_p <= epsilon, 0 <= x+delta <= 1} L(f_theta(x+delta), y)]. The inner maximisation replaces the natural input x with the worst-case perturbed input within the epsilon ball. Training on this worst-case input produces a model that is simultaneously trying to be correct on the hardest possible version of each example. The inner maximisation problem -- find the delta within the epsilon ball that maximises loss -- is the adversary''s problem. Solving it exactly is intractable in general. Madry et al. proposed PGD as the practical solver: iteratively take gradient steps that increase the loss, projecting back onto the epsilon ball after each step to maintain feasibility. The resulting delta is not the global maximum of the loss over the epsilon ball, but it is a strong local maximum and, empirically, a sufficient approximation for robust training. This framing has two production consequences. First, PGD adversarial training (Section 10.15) is the natural implementation of the robust optimisation objective -- each training step solves the inner PGD problem, then takes an outer gradient step. Second, PGD evaluation is the natural test of whether a defence addresses the robust optimisation objective: if a model is robust to PGD, it has addressed the inner maximisation problem for first-order adversaries.

Part 2

Title

The PGD Algorithm: Iterative FGSM with Projection Derived

Body

PGD for L-infinity adversarial examples iterates the following update: x_{t+1} = Pi_{x, epsilon}(x_t + alpha * sign(nabla_{x_t} L(theta, x_t, y))) where Pi_{x, epsilon} is the projection operator that maps any input back to the set {x + delta : ||delta||_inf <= epsilon, 0 <= x + delta <= 1}. The initialisation x_0 is either x itself (clean start) or a uniformly random point within the epsilon ball (random start). The attack runs for k steps and returns x_k as the adversarial example. The update has three components. The FGSM component (sign of gradient) is identical to Section 10.3: take one gradient ascent step of size alpha in the sign direction. The projection component clips the cumulative perturbation delta = x_{t+1} - x to [-epsilon, epsilon] per feature, maintaining the L-infinity feasibility constraint. The input validity component clips the result to [0, 1] (or whatever the valid input range is), maintaining the physical feasibility constraint. The projection is applied to the delta (the total perturbation from the original x), not to x_t directly. This is the critical implementation detail. If you project x_t to [x - epsilon, x + epsilon] independently of x, you are projecting a moving target, and the cumulative perturbation can drift outside the intended epsilon ball. The correct implementation is: delta = clip(x_t + alpha * sign(grad) - x, -epsilon, epsilon); x_{t+1} = clip(x + delta, 0, 1). The delta accumulates the total perturbation from the original x across all steps; the L-infinity projection operates on the total delta; the input validity clip operates on the resulting input.

Part 3

Title

The Projection Operator: L-infinity and L2

Body

The L-infinity projection is the simpler of the two norms and is the standard in PGD implementations. For a perturbation delta and epsilon budget, the projection clips each feature independently: delta_projected = clip(delta, -epsilon, epsilon). This is a component-wise operation -- each feature of the perturbation is independently constrained to lie in [-epsilon, epsilon]. The projected delta then satisfies ||delta_projected||_inf = max_i |delta_projected_i| <= epsilon by construction. The L2 projection requires a different operation. The L2 ball {delta : ||delta||_2 <= epsilon} is a hypersphere. To project delta onto this ball, check if ||delta||_2 > epsilon. If so, scale the entire delta vector down to lie on the boundary: delta_projected = epsilon * delta / ||delta||_2. If ||delta||_2 <= epsilon, the delta is already inside the ball and no projection is needed. Unlike L-infinity projection (which clips each feature independently), L2 projection rescales the entire perturbation vector, preserving its direction while bounding its magnitude. The two projections produce qualitatively different adversarial examples at matched norm budget. L-infinity projection produces uniform perturbations: every feature is perturbed by exactly epsilon. L2 projection allows some features to be perturbed by more than others as long as the total Euclidean norm stays bounded. In practice for images, L-infinity PGD produces uniform fine-grained noise; L2-PGD produces perturbations that concentrate on the most important features while leaving others relatively unchanged. C&W (Section 10.5) pushes this logic further by directly minimising the L2 norm of the perturbation, finding the minimum-norm adversarial example rather than operating at a fixed epsilon budget.

Part 4

Title

Hyperparameters: Step Size, Iteration Count, and Convergence

Body

PGD has three hyperparameters with distinct roles: step size alpha (controls how far each FGSM step moves), iteration count k (controls how many steps), and restart count R (controls how many random initialisations are tried). Step size alpha must satisfy alpha < epsilon. If alpha >= epsilon, each step can take the perturbation from one side of the epsilon ball to the other in a single move, causing oscillation without convergence. The standard rule of thumb is alpha = epsilon / k * c where c is a small constant. For evaluation PGD with k=40, alpha = epsilon/4 to epsilon/8 is common. For adversarial training PGD with k=7, alpha = 2*epsilon/3 is the standard from Madry et al. The smaller k in training requires a larger alpha to make progress in fewer steps. Iteration count k controls the trade-off between attack strength and computation. Empirically, attack success rate increases rapidly with the first 10-20 steps and then levels off. Beyond 40-50 steps, the marginal improvement per additional step is typically small. For production robustness evaluation, k=40 with random restart is the standard. For adversarial training, k=7 is the common choice because training runs k forward-backward passes per example per training step -- at k=40, adversarial training is 40x more expensive than standard training, which is often infeasible at production model scales. The convergence diagnostic is the per-step loss curve: plot the average loss across examples as a function of step t. A well-converged PGD run shows a rapid rise in the first 10-20 steps followed by a plateau. If the curve is still rising steeply at k=40, increase k. If the curve plateaued at k=10, k=40 is wasteful. This diagnostic is built into the evaluator deliverable in this section.

Part 5

Title

Random Restart: Escaping Local Optima in the Epsilon Ball

Body

Without random restart, PGD initialises from x_0 = x -- the clean input. The gradient at x points toward the nearest local maximum of the loss in the epsilon ball, and PGD converges to that local maximum. For many inputs, the nearest local maximum is not the global maximum: the loss landscape inside the epsilon ball has multiple local peaks, and a clean-start PGD finds only the nearest one from x. Random restart initialises x_0 from a random point inside the epsilon ball: x_0 = clip(x + Uniform(-epsilon, epsilon), 0, 1). Running PGD from this random start explores a different region of the loss landscape. Running R restarts and keeping the adversarial example with the highest loss across all restarts produces a stronger attack than any single restart because it samples multiple local optima and selects the best. The practical trade-off is compute: R restarts multiply the PGD cost by R. For evaluation, R=5 to R=20 is common. For adversarial training data generation, R=1 is standard because the training process itself provides diversity across batches -- each batch generates new adversarial examples from a fresh random start, covering different regions of the landscape across the full training run. The multi-restart implementation must track the per-sample best adversarial example, not the batch average. An adversarial example that increases loss for sample i but not for sample j should be kept for i and discarded for j. The per-sample loss tracking using nn.CrossEntropyLoss(reduction=''none'') is the correct implementation pattern and is demonstrated in the pgd_attack.py deliverable.

Part 6

Title

PGD as the Universal First-Order Adversary and the Gradient Masking Diagnostic

Body

Madry et al.''s central claim is that PGD is the strongest first-order (gradient-based) adversary: any first-order attack can be viewed as a special case or approximation of PGD. FGSM is PGD with k=1 and no projection constraint. Iterative FGSM is PGD with fixed step size and no projection. Momentum-based PGD accumulates gradient direction across steps, smoothing the path through the loss landscape. The claim is empirically supported: for models without gradient masking, PGD with sufficient steps and restarts finds adversarial examples at least as strong as any published first-order attack. This universality claim has a direct implication for robustness evaluation: if a model is robust to PGD at epsilon, it is robust to all first-order attacks at epsilon. This makes PGD success rate the correct robustness benchmark, not FGSM success rate. A model that resists FGSM but not PGD has gradient masking: the gradient signal at x is obfuscated (by discontinuities, randomisation, or other mechanisms) such that a single gradient step produces a weak adversarial example, but multiple steps find the way through the obfuscation. The gradient masking diagnostic is: run both FGSM and PGD at the same epsilon on the same model and test set. If PGD success rate is substantially higher than FGSM success rate (say >15 percentage points), the model has gradient masking. This does not mean the model is robust -- gradient masking is a form of obfuscated robustness that is typically broken by adaptive attacks. C&W (Section 10.5) with BPDA (Backward Pass Differentiable Approximation) is designed specifically to break gradient masking defences. Any published defence that reports only FGSM robustness without PGD robustness should be treated with scepticism. The adversarial ML literature contains numerous examples of proposed defences that showed near-zero FGSM attack success rates but were trivially broken by PGD with sufficient iterations. The Carlini and Wagner (2017) evaluation guidelines -- which motivated the C&W attack in Section 10.5 -- explicitly identify FGSM-only evaluation as insufficient.

Part 7

Title

PGD Adversarial Training and Computational Cost

Body

PGD adversarial training (the full version is covered in Section 10.15) uses the PGD inner loop as a data augmentation step during training. At each training step: (1) generate a PGD adversarial example for each batch element using k=7 inner steps; (2) take a training gradient step on the resulting adversarial examples to update model weights. The model is never trained on clean examples -- only on the worst-case adversarial examples from each batch. The computational cost is k times the cost of standard training per step. At k=7 (Madry et al. configuration), adversarial training is approximately 7x more expensive than standard training in wall-clock time. At k=40 (evaluation-grade PGD), it is approximately 40x more expensive. This cost is the primary reason production adversarial training uses k=7 rather than k=40 -- the adversarial training literature accepts a moderate reduction in empirical robustness in exchange for training feasibility. The accuracy-robustness trade-off from PGD adversarial training is significant and well- documented. On CIFAR-10 with epsilon=8/255, standard training achieves ~95% clean accuracy; Madry et al. PGD adversarial training achieves ~87% clean accuracy and ~45% PGD robust accuracy. The clean accuracy cost (~8 percentage points) is the price of certified empirical robustness. For production security systems, this trade-off must be explicitly documented: the operational threshold for a fraud classifier or content moderator changes when the model is adversarially trained, and the decision boundary shift must be recalibrated post-training. The pgd_training_data_generator.py deliverable produces PGD adversarial examples formatted for use as an augmented training set. Section 10.15 (adversarial_trainer.py) wraps this generator in the full min-max training loop. The generator is kept separate here so the data generation step can be profiled and cached independently of the training step.

PGD Core Implementation

pgd_attack.py

Production-quality L-infinity PGD with configurable step size, iterations, multi-restart tracking via per-sample loss, and both targeted and untargeted modes

Code

# pgd_attack.py
# Section 10.4: PGD -- Projected Gradient Descent
# 20260523 | AI Security Mastery by Raghav Dinesh
# Single quotes throughout per book convention

import torch
import torch.nn as nn
from torch import Tensor
from typing import Optional


def pgd_linf(
    model: nn.Module,
    x: Tensor,
    y: Tensor,
    epsilon: float,
    alpha: float,
    n_steps: int,
    n_restarts: int = 1,
    targeted: bool = False,
    clip_min: float = 0.0,
    clip_max: float = 1.0,
    criterion: Optional[nn.Module] = None,
) -> Tensor:
    '''
    PGD L-infinity adversarial attack (Madry et al. 2018).

    Solves: argmax_{||delta||_inf <= epsilon} L(f(x + delta), y)
    via k steps of projected gradient ascent with optional random restart.

    Args:
        model:      PyTorch classifier (eval mode recommended)
        x:          Input batch, shape (N, *), normalised to [clip_min, clip_max]
        y:          True labels (untargeted) or target labels (targeted)
        epsilon:    L-infinity perturbation budget
        alpha:      Step size per iteration; must satisfy alpha < epsilon
        n_steps:    Number of PGD iterations per restart
        n_restarts: Number of random restarts; best adversarial per sample kept
        targeted:   If True, minimise loss for y (treat y as target class)
        clip_min:   Minimum valid input value
        clip_max:   Maximum valid input value
        criterion:  Loss function (default: CrossEntropyLoss, reduction=none)

    Returns:
        best_x_adv: Adversarial examples with highest per-sample loss across restarts
    '''
    if criterion is None:
        criterion = nn.CrossEntropyLoss(reduction='none')

    direction = -1.0 if targeted else 1.0
    x = x.detach()

    # Track best adversarial example per sample across all restarts
    best_loss = torch.full((x.size(0),), -float('inf'), device=x.device)
    best_x_adv = x.clone()

    for _ in range(n_restarts):
        # --- Initialise: random point in epsilon ball ---
        delta_init = torch.zeros_like(x).uniform_(-epsilon, epsilon)
        x_adv = torch.clamp(x + delta_init, clip_min, clip_max).detach()

        for step in range(n_steps):
            # Enable gradient on current iterate
            x_adv = x_adv.detach().requires_grad_(True)

            # Forward + per-sample loss
            per_sample_loss = criterion(model(x_adv), y)
            total_loss = direction * per_sample_loss.sum()

            # Backward
            model.zero_grad()
            total_loss.backward()

            with torch.no_grad():
                # FGSM step (gradient ascent for untargeted; descent for targeted)
                grad_sign = x_adv.grad.data.sign()
                x_step = x_adv + direction * alpha * grad_sign

                # L-infinity projection: clamp total delta from ORIGINAL x
                delta = torch.clamp(x_step - x, -epsilon, epsilon)

                # Input validity clip
                x_adv = torch.clamp(x + delta, clip_min, clip_max)

        # --- Multi-restart: keep per-sample best ---
        with torch.no_grad():
            final_loss = criterion(model(x_adv), y)
            improved = final_loss > best_loss
            best_loss[improved] = final_loss[improved]
            best_x_adv[improved] = x_adv[improved]

    return best_x_adv.detach()


def attack_success_rate(
    model: nn.Module,
    x_adv: Tensor,
    y_true: Tensor,
) -> float:
    with torch.no_grad():
        preds = model(x_adv).argmax(dim=1)
    return (preds != y_true).float().mean().item()


def pgd_convergence_curve(
    model: nn.Module,
    x: Tensor,
    y: Tensor,
    epsilon: float,
    alpha: float,
    n_steps: int,
    n_restarts: int = 1,
) -> list:
    '''
    Return per-step average loss for convergence diagnostics.
    Runs one restart; tracks loss at each PGD step.
    '''
    criterion = nn.CrossEntropyLoss()
    x = x.detach()
    delta_init = torch.zeros_like(x).uniform_(-epsilon, epsilon)
    x_adv = torch.clamp(x + delta_init, 0.0, 1.0).detach()
    losses = []

    for step in range(n_steps):
        x_adv = x_adv.detach().requires_grad_(True)
        loss = criterion(model(x_adv), y)
        losses.append(loss.item())
        model.zero_grad()
        loss.backward()
        with torch.no_grad():
            x_step = x_adv + alpha * x_adv.grad.data.sign()
            delta = torch.clamp(x_step - x, -epsilon, epsilon)
            x_adv = torch.clamp(x + delta, 0.0, 1.0)
    return losses

    try:
        from fgsm_attack import ToyLinear, attack_success_rate as fgsm_asr
        from fgsm_attack import fgsm
    except ImportError:
        print('Run from directory containing fgsm_attack.py')
        return

    torch.manual_seed(42)
    model = ToyLinear()
    model.eval()
    x = torch.rand(64, 1, 28, 28)
    y = torch.randint(0, 10, (64,))
    eps = 8.0 / 255.0
    alpha = eps / 4.0

    print('PGD L-inf demo on ToyLinear (synthetic data)')
    print(f'epsilon = {eps:.4f} ({eps * 255:.1f}/255), alpha = {alpha:.4f}')
    print()

    configs = [
        ('FGSM (k=1)', 1, 1),
        ('PGD k=7', 7, 1),
        ('PGD k=20', 20, 1),
        ('PGD k=40', 40, 1),
        ('PGD k=40 R=5', 40, 5),
    ]

    for name, k, r in configs:
        if k == 1 and r == 1:
            x_adv = fgsm(model, x, y, epsilon=eps)
        else:
            x_adv = pgd_linf(model, x, y, epsilon=eps, alpha=alpha,
                             n_steps=k, n_restarts=r)
        rate = attack_success_rate(model, x_adv, y)
        l_inf = (x_adv - x).abs().max().item()
        print(f'  {name:<22} success={rate:.3f}  L-inf={l_inf:.4f}')

    print()
    print('Convergence curve (PGD k=40, R=1):')
    losses = pgd_convergence_curve(model, x, y, eps, alpha, n_steps=40)
    for step in [0, 4, 9, 19, 39]:
        print(f'  step {step + 1:>3}: loss = {losses[step]:.4f}')


if __name__ == '__main__':
    demo()

# pgd_l2_variant.py
# Section 10.4: L2-PGD Implementation
# 20260523 | AI Security Mastery by Raghav Dinesh
# Single quotes throughout per book convention

import torch
import torch.nn as nn
from torch import Tensor
from typing import Optional


def project_l2(delta: Tensor, epsilon: float) -> Tensor:
    '''
    Project delta onto the L2 ball of radius epsilon.
    If ||delta||_2 > epsilon: rescale to epsilon.
    If ||delta||_2 <= epsilon: return unchanged.
    Operates per-sample in a batch.
    '''
    # Flatten each sample for norm computation
    batch_size = delta.size(0)
    flat = delta.view(batch_size, -1)
    norms = flat.norm(p=2, dim=1, keepdim=True)
    # Scale = min(epsilon / norm, 1.0); apply only where norm > epsilon
    scale = torch.clamp(epsilon / norms, max=1.0)
    projected_flat = flat * scale
    return projected_flat.view_as(delta)


def pgd_l2(
    model: nn.Module,
    x: Tensor,
    y: Tensor,
    epsilon: float,
    alpha: float,
    n_steps: int,
    n_restarts: int = 1,
    targeted: bool = False,
    clip_min: float = 0.0,
    clip_max: float = 1.0,
    criterion: Optional[nn.Module] = None,
) -> Tensor:
    '''
    PGD L2 adversarial attack.
    L2 step: x_t + alpha * g / ||g||_2
    L2 projection: rescale delta to L2 ball of radius epsilon.
    '''
    if criterion is None:
        criterion = nn.CrossEntropyLoss(reduction='none')

    direction = -1.0 if targeted else 1.0
    x = x.detach()
    best_loss = torch.full((x.size(0),), -float('inf'), device=x.device)
    best_x_adv = x.clone()

    for _ in range(n_restarts):
        # Random L2 start: sample direction uniformly on L2 sphere, scale by random radius
        delta_init = torch.randn_like(x)
        flat = delta_init.view(x.size(0), -1)
        norms = flat.norm(p=2, dim=1, keepdim=True).view(x.size(0), *([1] * (x.dim() - 1)))
        r = torch.zeros(x.size(0), *([1] * (x.dim() - 1)), device=x.device).uniform_(0, 1)
        delta_init = epsilon * r * (delta_init / (norms + 1e-8))
        x_adv = torch.clamp(x + delta_init, clip_min, clip_max).detach()

        for step in range(n_steps):
            x_adv = x_adv.detach().requires_grad_(True)
            per_sample_loss = criterion(model(x_adv), y)
            total_loss = direction * per_sample_loss.sum()
            model.zero_grad()
            total_loss.backward()

            with torch.no_grad():
                grad = x_adv.grad.data
                # L2 step: normalise gradient to unit L2 norm, scale by alpha
                flat_grad = grad.view(x.size(0), -1)
                grad_norm = flat_grad.norm(p=2, dim=1, keepdim=True).view(
                    x.size(0), *([1] * (x.dim() - 1)))
                grad_unit = grad / (grad_norm + 1e-8)
                x_step = x_adv + direction * alpha * grad_unit

                # L2 projection of total delta
                delta = project_l2(x_step - x, epsilon)
                x_adv = torch.clamp(x + delta, clip_min, clip_max)

        with torch.no_grad():
            final_loss = criterion(model(x_adv), y)
            improved = final_loss > best_loss
            best_loss[improved] = final_loss[improved]
            best_x_adv[improved] = x_adv[improved]

    return best_x_adv.detach()


def compare_l_inf_l2(model, x, y, eps_linf, eps_l2, n_steps=40, n_restarts=3):
    '''Compare L-inf and L2 PGD at independently specified budgets.'''
    from pgd_attack import pgd_linf, attack_success_rate

    alpha_linf = eps_linf / 10.0
    alpha_l2 = eps_l2 / 10.0

    x_adv_linf = pgd_linf(model, x, y, eps_linf, alpha_linf, n_steps, n_restarts)
    x_adv_l2 = pgd_l2(model, x, y, eps_l2, alpha_l2, n_steps, n_restarts)

    rate_l2 = attack_success_rate(model, x_adv_l2, y)

    l2_actual = (x_adv_l2 - x).view(x.size(0), -1).norm(p=2, dim=1).mean().item()

    print(f'L-inf PGD: success={rate_linf:.3f}, actual L-inf={linf_actual:.4f}')
    print(f'L2   PGD: success={rate_l2:.3f}, actual L2 mean={l2_actual:.4f}')

    with torch.no_grad():

    return (preds == y).float().mean().item()


def robustness_sweep(
    model: nn.Module,
    x: torch.Tensor,
    y: torch.Tensor,
    epsilons: List[float],
    pgd_steps: int = 40,
    pgd_restarts: int = 5,
    masking_threshold: float = 0.15,
    model_name: str = 'model',
) -> RobustnessReport:
    from pgd_attack import pgd_linf, attack_success_rate
    from fgsm_attack import fgsm

    pgd_robust_accs, fgsm_rates, pgd_rates, flags = [], [], [], []

Common Mistakes

Mistake 1

Description

Using alpha >= epsilon as the step size, causing the perturbation to leave the epsilon ball every step and preventing convergence

Why It Happens

The relationship between alpha and epsilon is not immediately obvious. Engineers who read "step size alpha" and choose alpha = epsilon (a natural round number) observe that the attack is fast to implement but produces strange adversarial examples with seemingly random success rates.

Consequence

At alpha = epsilon, each FGSM step moves the perturbation from one edge of the epsilon ball to the other. The projection then clips it back. The attack oscillates along the boundary of the epsilon ball without converging to a local maximum. Attack success rate is erratic and typically lower than FGSM alone. Convergence curves show no clear rise.

Correct Approach

Choose alpha = epsilon / k * c where c is typically 2 to 2.5. For k=40, alpha = epsilon/10 is standard. For k=7 (Madry training), alpha = 2*epsilon/3 is standard. Always verify the convergence curve: a well-tuned alpha produces a smoothly rising loss curve that plateaus within k steps. If the curve is flat or oscillating, reduce alpha.

Mistake 2

Description

Projecting x_adv directly to [x - epsilon, x + epsilon] rather than projecting the accumulated delta from the original x

Why It Happens

The projection intuitively sounds like clamping the current adversarial example. Engineers write: x_adv = clip(x_adv, x - epsilon, x + epsilon) and clip to [0, 1]. This appears correct for one step but accumulates error across multiple steps.

Consequence

After each step, the projection clips x_adv relative to the current x_adv, not the original x. Over multiple steps the epsilon ball drifts: the adversarial example is no longer guaranteed to be within epsilon of the original input. The final L-infinity distance (x_adv - x_original).abs().max() may significantly exceed epsilon, invalidating the attack as a norm-constrained adversarial example.

Correct Approach

Always compute delta = x_adv - x_original before projecting, and project the delta: delta = clip(x_step - x_original, -epsilon, epsilon); x_adv = clip(x_original + delta, 0, 1). The delta accumulates the total perturbation from the fixed original x. The L-infinity projection operates on the total delta. Verify with a post-hoc norm check: assert (best_x_adv - x).abs().max() <= epsilon + 1e-6.

Mistake 3

Description

Reporting single-restart PGD robustness and treating it as equivalent to multi-restart PGD robustness

Why It Happens

Multi-restart PGD is computationally expensive. Engineers run PGD with R=1 for speed and report the resulting robustness numbers. Papers sometimes omit the restart count, making it unclear whether the evaluation is single-restart or multi-restart.

Consequence

Single-restart PGD underestimates attack strength because it converges to the local maximum nearest to the clean start, missing stronger adversarial examples reachable from other starting points in the epsilon ball. Robustness claims based on R=1 are overly optimistic; the model may be substantially less robust under R=5 or R=10.

Correct Approach

For final robustness claims, always use R >= 5 with random starts. Report the restart count explicitly alongside epsilon, k, and alpha. Use the PGD robustness evaluator from this section which forces explicit restart configuration. The gradient masking diagnostic (large FGSM-to-PGD gap) becomes more reliable with more restarts.

Mistake 4

Description

Using the same PGD configuration for adversarial training and for robustness evaluation

Why It Happens

A single PGD configuration (epsilon, alpha, k) is used throughout the training and evaluation pipeline. Engineers train with k=40 PGD (extremely slow) or evaluate with k=7 PGD (too weak), because no distinction is made between the two use cases.

Consequence

Training with k=40 is approximately 40x more expensive than standard training, making large-scale adversarial training infeasible. Evaluating with k=7 underestimates attack strength at the evaluation phase, producing overly optimistic robustness numbers.

Correct Approach

Use separate PGD configs for training and evaluation: PGDConfig.madry_training(epsilon) for the inner training loop (k=7, alpha=2*epsilon/3, R=1) and PGDConfig.evaluation_grade(epsilon) for the robustness report (k=40, alpha=epsilon/10, R=5). The training config is optimised for speed at acceptable robustness; the evaluation config is optimised for attack strength. Both are implemented in PGDConfig in pgd_training_data_generator.py.

Mistake 5

Description

Concluding that a model is robust because its PGD success rate is low, without checking whether PGD is properly converging on that model

Why It Happens

PGD is claimed to be the strongest first-order adversary, so low PGD success rate is taken as evidence of robustness. The claim is true for models without gradient masking but fails for models with obfuscated gradients (shattered gradients, stochastic defences, non-differentiable preprocessing).

Consequence

A model with shattered gradients produces near-zero gradients everywhere, making every PGD step ineffective. PGD shows 0% success, the model is declared robust, but C&W with BPDA achieves 95% success by approximating the non-differentiable components. Published defences including input transformations and certain certified defences have been broken this way.

Correct Approach

Apply the gradient masking diagnostic first: compare FGSM success to PGD success at matched epsilon. If PGD barely outperforms FGSM, and both show near-zero success at epsilon where natural models are 60%+ vulnerable, gradient masking is likely. Follow up with C&W (Section 10.5) or BPDA. The robustness evaluator flags this automatically. Any defence claiming PGD robustness below 5% at epsilon=8/255 on CIFAR-10 without certified robustness should be treated with scepticism.

Section Summary

Compact

PGD extends FGSM from a single step to an iterative projected gradient ascent that solves the inner maximisation problem of the Madry et al. robust optimisation objective. The algorithm iterates: take an FGSM step, project the accumulated delta back onto the L-infinity epsilon ball from the original x, clip to valid input range. Step size alpha < epsilon prevents oscillation; random restart (R >= 5) escapes local optima in the epsilon ball and produces the strongest first-order adversarial examples. PGD success rate is the canonical empirical robustness measure: the gradient masking diagnostic (PGD success substantially exceeds FGSM success) identifies defences that obfuscate gradients without achieving real robustness. PGD adversarial training uses k=7 inner steps to balance robustness and compute cost, producing models with ~8 percentage point clean accuracy loss and ~45% PGD robust accuracy on CIFAR-10 at epsilon=8/255.

Key Takeaways

  • PGD solves the inner maximisation of the min-max robust optimisation problem; it is the adversary that adversarial training trains against
  • The projection must operate on the accumulated delta from the original x, not on the current x_adv; this is the most common implementation error
  • Random restart (R >= 5) is required for honest robustness evaluation; single-restart PGD underestimates attack strength
  • PGD success rate, not FGSM success rate, is the truthful empirical robustness measure; use k=40 and R=5 for evaluation
  • The gradient masking diagnostic: if PGD minus FGSM success gap exceeds 15 percentage points, the defence is obfuscating gradients rather than achieving robustness
  • Training config (k=7, alpha=2*eps/3, R=1) and evaluation config (k=40, alpha=eps/10, R=5) are distinct; use the evaluator to report published robustness claims

Section 10.5: C&W -- The Carlini-Wagner Attack

Summary

Section 10.5 implements C&W L2 (Carlini and Wagner 2017), the optimality-focused attack designed specifically to evaluate and break proposed defences. Where FGSM and PGD fix epsilon and maximise loss, C&W minimises ||delta||_2 subject to the misclassification constraint -- finding the minimum-norm adversarial example. The formulation uses a change of variables (tanh-space) to handle box constraints without projection, a binary search on the regularisation constant c to balance perturbation size against classification margin, and a confidence parameter kappa that controls how strongly wrong the adversarial output must be. High kappa C&W produces examples that survive squeezing and consistency checking, making it the correct attack for evaluating Track 7 defences. Carlini and Wagner''s original goal was breaking every proposed defence of 2016-2017; Section 10.5 uses C&W for the same purpose against Chapter 10 Track 7 primitives.
