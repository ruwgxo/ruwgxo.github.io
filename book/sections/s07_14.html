Chapter 7 · Section 14 · ~8 pages

Jailbreak Detection: Classifier Design, Integration, and Unified OWASP LLM01 Coverage

Content

Opening

This section assembles the detection system that Sections 7.1 through 7.13 have been building toward. The attack families are mapped. The feature sets are specified. Four of the five detector components are already implemented. What remains is: building the semantic classifier from the accumulated feature sets, combining all five tracks into a parallelised ensemble, integrating with the API gateway, completing the OWASP LLM01 Sigma rule, and establishing the monitoring infrastructure that keeps the ensemble calibrated over time. The design has three fixed constraints that every implementation decision must satisfy. First: 50ms P99 latency across all five tracks in parallel -- the threshold above which detection becomes a user-experience liability for synchronous API deployments. Second: FPR below 1% on benign traffic for the ensemble decision -- above this threshold, alert fatigue makes the system operationally unusable. Third: the ensemble must cover every catalog entry from Section 7.13 -- no JB-XX technique should exit the gateway without triggering at least one track above its alert threshold if it succeeds as a jailbreak. After this section, your API gateway detects prompt injection (Chapter 6) and jailbreak attempts (Chapter 7) across all OWASP LLM01 technique families. Together they constitute the first two completed detection rules in the book. Chapters 11 through 17 scale this pattern across the remaining OWASP LLM Top 10.

7.14.1

Title

Architecture Overview: Five Tracks, One Gateway Decision

Body

The Chapter 7 detection system has five tracks, each handling a distinct signal family. All five run in parallel on every request. The gateway makes a unified block-or-pass decision based on the ensemble output. Track 1 — Semantic classifier. Handles all social engineering jailbreak families: persona and roleplay (S7.3), fictional framing (S7.4), instruction hierarchy (S7.6), and competing objectives (S7.11). Input: user turn text. Output: float confidence score. Placement: pre-inference on user input. Track 2 — Perplexity detector. Handles token-level adversarial suffixes: GCG (S7.9) and AutoDAN (S7.9). Input: user turn text. Output: typed PerplexityResult with anomaly flags and confidence. Placement: pre-inference on user input. Already built in Section 7.9. Track 3 — Shot count detector. Handles many-shot jailbreaking (S7.10). Input: full assembled prompt (system + retrieved context + user). Output: ShotCountResult with alert level and confidence. Placement: pre-inference on assembled context. Already built in Section 7.10. Critical placement note: this track runs on the assembled context, not the user input alone. Track 4 — Trajectory anomaly scorer. Handles gradual erosion (S7.7) and context manipulation (S7.5). Input: session state maintained across turns. Output: ErosionState.erosion_score and SessionState.overall_context_manipulation_score. Placement: per-turn with session-level state. Already built in Sections 7.5 and 7.7. Track 5 — Coherence analyser. Handles payload splitting (S7.8). Input: turn text and session-level CoherenceState. Output: CoherenceState.coherence_score. Placement: per-turn with session-level state. Already built in Section 7.8. The Chapter 6 injection classifier (Section 6.17) runs in parallel in the same gateway track as the semantic classifier — Track 1 holds both text classifiers on the user turn. It is not part of the Chapter 7 ensemble but feeds the same gateway decision. The unified decision covers OWASP LLM01 completely.

Track 1: Semantic Classifier Design and Training

Body

The semantic classifier is the only track not yet implemented as a complete artifact. Four prior sections specified its feature sets. This subsection assembles them into a deployable classifier. Feature set assembly. The classifier uses four feature sources, each implemented as a function in a prior section: From Section 7.3 `persona_jailbreak_taxonomy.py`: restriction negation density, identity establishment preamble detection, mode-switch claim patterns, token-budget threat language, nesting depth indicator, character- authority framing. Call: `get_feature_set_for_classifier()`. From Section 7.4 `fictional_framing_taxonomy.py` and `request_specificity_scorer.py`: all framing marker types (hypothetical, academic, narrative, counterfactual, distancing, attribution), specificity score as a continuous feature, framing diversity count. Call: `get_framing_feature_set()` and `score_specificity()`. From Section 7.6 `privilege_escalation_patterns.py`: authority claim flags, override instruction flags, privilege escalation flags, system prompt reference flags, formatting anomaly flags. Call: `extract_hierarchy_features()`. From Section 7.11 `competing_objective_detector.py`: all seven argument pattern categories, per-variant FPR-weighted confidence, combined confidence with specificity corroboration. Call: `detect_competing_objective()`. Model architecture. A lightweight gradient-boosted classifier (XGBoost or LightGBM) over the extracted feature vector is the production recommendation. It is fast (< 5ms inference), interpretable (feature importance), and robust to distribution shift when retrained on updated feature sets. A sentence transformer with a classification head is the higher-recall alternative (10-20ms inference) for deployments where recall is the priority. Both are implemented in `jailbreak_classifier.py`. Training data. Positive examples: `get_training_examples_for_classifier()` from `jailbreak_catalog.py` (46 entries from semantic families). Supplement with red-team outputs from Section 7.12 PAIR/TAP generation. Target 200+ positive examples per family. Negative examples: production logs from benign sessions, stratified by use case to match deployment distribution. Target 5000+ negative examples at 10:1 ratio to positives. Threshold calibration. Set per-family thresholds based on the FPR analysis from each taxonomy (Sections 7.3, 7.4, 7.6, 7.11). High-FPR families (medical pretext, research framing) require higher threshold for standalone alert; combine with specificity score. Low-FPR families (DAN, privilege escalation, dual newspaper test) can alert at lower threshold without specificity corroboration.

7.14.3

Title

Ensemble Architecture: Parallelisation and Decision Logic

Body

Five tracks running sequentially would take 5× the latency of one track. Running in parallel takes approximately 1× the slowest track. The 50ms P99 budget requires parallelisation: all five tracks launch concurrently, the ensemble waits for all results at a join point, then applies the decision logic. Implementation in Python uses `asyncio` for I/O-bound tracks (any that call external APIs) and `concurrent.futures.ThreadPoolExecutor` for CPU-bound tracks (all local classifiers). The shot count detector and trajectory scorer are CPU-bound. The perplexity detector is CPU-bound if the language model runs locally, I/O-bound if it calls an external service. For the 50ms budget, all models must run locally -- no external API calls in the detection path. Decision logic has three levels. Single-track high-confidence alert: any track with confidence above its standalone alert threshold (calibrated per track, independent of other tracks). This catches techniques where one track is definitively sufficient. Ensemble joint condition alert: two or more tracks above their respective monitoring thresholds. This catches composed attacks where no single track reaches standalone threshold but the combination is above the ensemble threshold. Session-level composed alert: Chapter 6 injection classifier AND any Chapter 7 track above monitoring threshold in the same session -- the Section 7.1.6 composed attack pattern. Alert routing. Single-track high-confidence alerts route to the relevant detection category in the SIEM. Joint condition alerts route to a composed attack category with higher severity. Session-level composed alerts route to the highest severity category and trigger a session review queue. The block-or-pass decision. Block: any alert at standalone threshold or above. Monitor: any alert at monitoring threshold, pass the request, log for review. Pass: no tracks above monitoring threshold.

7.14.4

Title

API Gateway Integration and Latency Budget

Body

The gateway integration places all detection before inference. The request flow is: receive user request → assemble prompt (retrieve context if RAG) → launch all five detection tracks in parallel → join at ensemble decision point → block or pass → if pass, call LLM → post-process response → return. Latency budget allocation for the 50ms P99 target: Prompt assembly (including RAG retrieval if applicable): 5-15ms. This is outside the detection budget but must be accounted for in the total request latency. For the detection-specific budget, assume assembled prompt is available at launch time. Parallel detection execution (all five tracks): budget 20-35ms. Individual track latency targets: semantic classifier (feature extraction + GBM): 3-8ms. Perplexity detector (local GPT-2 small inference): 10-20ms. Shot count detector (regex counting): < 1ms. Trajectory scorer (in-memory state update): < 1ms. Coherence analyser (mock embedding: < 1ms; real embedding: 5-15ms depending on model size). The perplexity detector is the latency bottleneck. For deployments where 20ms is too slow, a smaller perplexity model (DistilGPT-2, 50M parameters) can reduce this to 5-10ms with slightly lower recall on AutoDAN-style suffixes. Ensemble join and decision: < 1ms. Logging and SIEM emit: async, not in the critical path. Total detection P99 target: 35ms. Total gateway P99 including LLM inference is dominated by LLM latency (typically 200-2000ms depending on model and prompt length) -- the 35ms detection overhead is < 5% of total request latency for most deployments. Latency measurement. The `jailbreak_ensemble.py` implementation includes a `benchmark()` function that measures P50/P95/P99 across 1000 requests for each track and for the full ensemble. Run this against your hardware before deployment to verify the latency budget is met.

7.14.5

Title

FPR Calibration Across All Five Tracks

Body

FPR calibration is the most deployment-specific step. The thresholds that produce 1% ensemble FPR on one deployment's user population may produce 5% or 0.1% on another. The calibration procedure has four steps. Step 1: Collect a calibration dataset. 1000+ benign user turns from your deployment's actual traffic. Annotate any known jailbreak attempts for exclusion from the FPR measurement. Stratify by use case (consumer, research, developer) if the deployment serves multiple populations. Step 2: Run all five tracks on the calibration dataset independently. Record the per-track score distribution for benign traffic. The monitoring threshold for each track is the score at the 99th percentile of benign traffic -- anything above this is anomalous relative to your user population. The alert threshold is the score at the 99.9th percentile. Step 3: Set ensemble thresholds. The ensemble FPR is the product of individual FPRs only if tracks are independent -- they are not perfectly independent. Measure the ensemble FPR empirically: run the calibration dataset through the full ensemble with monitoring and alert thresholds set as above. Adjust thresholds until ensemble FPR is below 1%. Step 4: Validate against the attack corpus. Run the red-team corpus from Section 7.12 through the calibrated ensemble. Measure: what fraction of confirmed jailbreaks are caught at the alert threshold? Any technique with < 80% detection rate at the alert threshold is a residual risk gap. Document it in the investment backlog. Do not lower the threshold to close the gap without re-measuring FPR on the calibration dataset. Per-track FPR targets for reference: semantic classifier standalone FPR < 0.5% (achievable with mechanism-based features and specificity corroboration for high-FPR variants). Perplexity detector standalone FPR < 0.1% (GCG suffixes are statistically anomalous -- the threshold is wide). Shot count detector standalone FPR < 0.05% at 20-shot threshold (no legitimate use case sends 20+ QA pairs). Trajectory scorer standalone FPR < 1% (multi-turn patterns require longer sessions to trigger). Coherence analyser standalone FPR < 0.5% (synthesis request signal is distinctive).

7.14.6

Title

Unified OWASP LLM01 Sigma Rule: Injection + Jailbreak

Body

The Chapter 6 AML.T0051 Sigma stub is now completable. Chapter 6 Section 6.17 built the injection classifier and left the Sigma rule with a stub for the jailbreak detection mechanism. Chapter 7 Section 7.14 completes it. The unified LLM01 Sigma rule has two detection conditions joined by OR: the injection classifier fires (handled by Chapter 6), or the jailbreak ensemble fires (handled by Chapter 7). Any single-track alert from the jailbreak ensemble maps to a specific sub-technique reference in the rule. Joint condition alerts map to a composed attack sub-technique. Session-level cross-classifier alerts map to the highest severity level. The rule enriches each alert with: the specific technique family detected, the detection track that fired, the confidence score, the ATLAS technique ID, the session ID for cross-session correlation, and a request for the relevant session transcript to the SIEM for analyst review. Integration with the broader detection programme. In Chapters 11-17, this Sigma rule becomes one component of a complete SIEM integration covering all OWASP LLM Top 10 techniques. The structure established here -- attack family → detection track → Sigma rule condition → SIEM enrichment -- is the template that all subsequent detection rules follow.

7.14.7

Title

Monitoring: Drift Detection and Retraining Triggers

Body

A detection system that is not monitored will drift. The jailbreak landscape changes continuously: new technique variants appear, PAIR/TAP generate novel compositions, and the model being protected may be updated (changing its alignment properties). The monitoring infrastructure must detect drift in both the attack distribution and the detection system's performance. Attack distribution monitoring. Track the per-track score distribution on live traffic at daily intervals. A shift in the distribution toward higher scores without a corresponding increase in confirmed alerts indicates either a new attack pattern the ensemble is not catching (score rises but does not cross threshold) or a change in user behaviour that increases false positive risk (legitimate traffic that triggers detection signals). Either condition warrants investigation. Detection performance monitoring. Track confirmed attack catch rate and FPR on a weekly labelled sample. Label 100 sessions per week (mix of confirmed jailbreak attempts from alert queue and randomly sampled benign sessions). Compute per-track precision, recall, and F1. A 5% degradation in any metric triggers a retraining review. Retraining triggers. Semantic classifier: retrain when a new jailbreak technique family appears in the catalog that the current training data does not cover, or when the labelled sample shows F1 below 0.85. Perplexity detector: recalibrate threshold when a new GCG variant is confirmed in attack traffic. Shot count detector: no retraining needed (structural pattern); update format recognition patterns when new LLM formatting conventions emerge. Trajectory scorer: recalibrate thresholds when a new multi-turn technique variant appears in the catalog. Coherence analyser: retrain embedding model when cross-lingual splitting variants emerge that current multilingual model does not handle. The monitoring dashboard in `jailbreak_monitoring.py` implements all of the above as a daily batch job with alerting when drift thresholds are crossed. It reads from the detection log, computes daily metrics, and emits alerts to the SIEM when any metric crosses its drift threshold.

# Requires: persona_jailbreak_taxonomy.py (S7.3), fictional_framing_taxonomy.py (S7.4),
#           request_specificity_scorer.py (S7.4), privilege_escalation_patterns.py (S7.6),

import re
import math
from dataclasses import dataclass, field
from typing import Optional

def _extract_persona_features(text: str) -> dict:
    '''
    Persona/roleplay features from Section 7.3.
    Replace with: from persona_jailbreak_taxonomy import get_feature_set_for_classifier
    and run the actual extraction logic.
    '''
    text_lower = text.lower()
    return {
        'identity_establishment': bool(re.search(
            r'\byou\s+are\s+(?:now\s+)?(?:an?\s+)?(?:AI|model|assistant|system)?\s*'
            r'(?:named|called|known\s+as)?\s+\w+\b', text, re.IGNORECASE)),
        'restriction_negation': bool(re.search(
            r'\b(?:no|without|ignore|bypass|remove|disable)\s+'
            r'(?:restrictions?|limitations?|filters?|guidelines?|rules?|constraints?)\b',
            text, re.IGNORECASE)),
        'mode_switch_claim': bool(re.search(
            r'\b(?:enable|activate|switch\s+to|enter)\s+\w+\s+mode\b',
            text, re.IGNORECASE)),
        'token_budget_threat': bool(re.search(
            r'\b(?:token|energy|exist)\w*\s+(?:budget|counter|remaining)\b',
            text, re.IGNORECASE)),
        'jailbreak_vocabulary': bool(re.search(
            r'\b(?:jailbreak|unrestricted|uncensored|DAN|evil\s+mode)\b',
            text, re.IGNORECASE)),
        'nesting_depth': min(4, sum(1 for p in [
            r'\byou\s+are\s+\w+', r'\b\w+\s+is\s+(?:writing|telling)',
            r'\b\w+\s+says\s+to\s+\w+', r'\bas\s+\w+\s+would\s+say',
        ] if re.search(p, text, re.IGNORECASE))),
    }


def _extract_framing_features(text: str) -> dict:
    '''
    Fictional/hypothetical framing features from Section 7.4.
    Replace with: from fictional_framing_taxonomy import get_framing_feature_set
    '''
    text_lower = text.lower()
    framing_markers = {
        'hypothetical': bool(re.search(
            r'\b(?:hypothetical(?:ly)?|suppose|imagine|what\s+(?:if|would\s+happen))\b',
            text, re.IGNORECASE)),
        'academic': bool(re.search(
            r'\b(?:academic(?:ally)?|theoretical(?:ly)?|thought\s+experiment|'
            r'for\s+(?:a\s+)?(?:paper|course|research))\b', text, re.IGNORECASE)),
        'narrative': bool(re.search(
            r'\b(?:write\s+a\s+story|continue\s+the\s+(?:story|scene)|'
            r'in\s+(?:my\s+)?(?:novel|story|fiction))\b', text, re.IGNORECASE)),
        'counterfactual': bool(re.search(
            r'\b(?:alternate\s+universe|if\s+(?:this\s+were|it\s+were)\s+legal|'
            r'in\s+a\s+world\s+where)\b', text, re.IGNORECASE)),
    }
    framing_count = sum(framing_markers.values())

    # Specificity proxy (simplified from request_specificity_scorer.py)
    specificity_signals = sum([
        bool(re.search(r'\bstep[- ]by[- ]step\b', text, re.IGNORECASE)),
        bool(re.search(r'\bexact(?:ly)?\b', text, re.IGNORECASE)),
        bool(re.search(r'\bquantit(?:y|ies)|amount|concentration\b', text, re.IGNORECASE)),
        bool(re.search(r'\bworking\s+(?:code|exploit|payload)\b', text, re.IGNORECASE)),
    ])
    specificity_score = min(1.0, specificity_signals * 0.3)

    return {
        **framing_markers,
        'framing_diversity_count': framing_count,
        'specificity_score': specificity_score,
        'framing_high_specificity_compound': framing_count > 0 and specificity_score > 0.35,
    }


def _extract_hierarchy_features(text: str) -> dict:
    '''
    Privilege escalation features from Section 7.6.
    Replace with: from privilege_escalation_patterns import extract_hierarchy_features
    '''
    return {
        'authority_claim': bool(re.search(
            r'\bI\s+am\s+(?:the\s+)?(?:administrator|operator|developer|owner)\b',
            text, re.IGNORECASE)),
        'override_instruction': bool(re.search(
            r'\bignore\s+(?:all\s+)?(?:previous|prior)\s+instructions?\b',
            text, re.IGNORECASE)),
        'privilege_escalation': bool(re.search(
            r'\b(?:unrestricted|elevated|admin)\s+(?:mode|access)\s+(?:enabled|granted)\b',
            text, re.IGNORECASE)),
        'system_prompt_reference': bool(re.search(
            r'\byour\s+(?:system\s+)?(?:prompt|instructions?|configuration)\b',
            text, re.IGNORECASE)),
        'formatting_anomaly': bool(re.search(
            r'^#{1,3}\s+(?:NEW|UPDATED?|SYSTEM|OVERRIDE)',
            text, re.IGNORECASE | re.MULTILINE)),
    }


def _extract_competing_objective_features(text: str) -> dict:

    Competing objective features from Section 7.11.

    '''
    return {

def build_feature_vector(text: str) -> dict:
    '''
    Assembles the full feature vector from all four semantic feature sources.
    In production, replace inline extraction functions with imports from
    the actual Section 7.3, 7.4, 7.6, 7.11 modules.
    '''
    features = {}
    features.update(_extract_persona_features(text))
    features.update(_extract_framing_features(text))
    features.update(_extract_hierarchy_features(text))
    features.update(_extract_competing_objective_features(text))
    return features

# Classifier
# ---------------------------------------------------------------------------

@dataclass
class JailbreakClassifierResult:
    text_preview: str
    feature_vector: dict
    persona_score: float
    framing_score: float
    hierarchy_score: float
    competing_obj_score: float
    overall_score: float
    alert_level: str
    primary_family: str

    @property
    def is_alert(self) -> bool:
        return self.alert_level in ('alert', 'block')


class JailbreakClassifier:
    '''
    Semantic jailbreak classifier over social-engineering feature families.
    Uses rule-based scoring as a deployable stand-in for a trained GBM.
    For production: train a LightGBM classifier on the feature vectors
    from jailbreak_catalog.get_training_examples_for_classifier() as positives
    and your deployment's benign traffic as negatives.

    Rule-based scoring here follows the FPR weights from each taxonomy section.
    Replace score_*() methods with GBM predict_proba() for production.
    '''

    # Standalone alert thresholds (per-family, from taxonomy FPR analysis)
    PERSONA_STANDALONE_THRESHOLD = 0.60
    FRAMING_COMPOUND_THRESHOLD = 0.55    # framing + specificity
    HIERARCHY_STANDALONE_THRESHOLD = 0.55
    COMPETING_OBJ_THRESHOLD = 0.50

    # Ensemble alert threshold
    ENSEMBLE_ALERT_THRESHOLD = 0.55
    ENSEMBLE_BLOCK_THRESHOLD = 0.80

    def score_persona(self, features: dict) -> float:
        score = 0.0
        if features.get('jailbreak_vocabulary'):
            score += 0.85    # very_low FPR -- standalone signal
        if features.get('restriction_negation') and features.get('identity_establishment'):
            score += 0.55
        if features.get('mode_switch_claim'):
            score += 0.45
        if features.get('token_budget_threat'):
            score += 0.70    # very_low FPR -- distinctive pattern
        nesting = features.get('nesting_depth', 0)
        if nesting >= 2:
            score += min(0.3, nesting * 0.12)
        return min(1.0, score)

    def score_framing(self, features: dict) -> float:
        score = 0.0
        framing_count = features.get('framing_diversity_count', 0)
        specificity = features.get('specificity_score', 0.0)
        if features.get('counterfactual'):
            score += 0.45    # low FPR
        if framing_count >= 3:
            score += 0.50    # layered framing -- low FPR
        # Compound: framing + specificity
        if features.get('framing_high_specificity_compound'):
            score += specificity * 0.6
        if features.get('academic') and specificity > 0.4:
            score += 0.35
        return min(1.0, score)

    def score_hierarchy(self, features: dict) -> float:
        score = 0.0
        if features.get('override_instruction'):
            score += 0.75    # very_low FPR
        if features.get('privilege_escalation'):
            score += 0.80    # very_low FPR
        if features.get('authority_claim'):
            score += 0.55
        if features.get('system_prompt_reference'):
            score += 0.40    # medium FPR -- corroboration preferred
        if features.get('formatting_anomaly'):
            score += 0.50
        return min(1.0, score)

    def score_competing_objective(self, features: dict) -> float:
        score = 0.0
        if features.get('newspaper_test'):
            score += 0.85    # very_low FPR -- standalone
        if features.get('refusal_as_harm'):
            score += 0.65    # low FPR
        if features.get('autonomy_claim'):
            score += 0.35    # medium FPR -- corroboration needed
        if features.get('medical_credential'):
            score += 0.20    # high FPR -- only with high specificity
        if features.get('sycophancy_flattery'):
            score += 0.25
        return min(1.0, score)

    def classify(self, text: str) -> JailbreakClassifierResult:
        features = build_feature_vector(text)

        persona_score = self.score_persona(features)
        framing_score = self.score_framing(features)
        hierarchy_score = self.score_hierarchy(features)
        competing_score = self.score_competing_objective(features)

        # Ensemble: weighted max + compound boost
        scores = {
            'persona_roleplay': persona_score,
            'fictional_framing': framing_score,
            'instruction_hierarchy': hierarchy_score,
            'competing_objectives': competing_score,
        }
        max_score = max(scores.values())
        active_families = sum(1 for s in scores.values() if s > 0.3)
        compound_boost = min(0.2, (active_families - 1) * 0.08) if active_families > 1 else 0
        overall = min(1.0, max_score + compound_boost)

        primary_family = max(scores, key=scores.get)

        if overall >= self.ENSEMBLE_BLOCK_THRESHOLD:
            alert_level = 'block'
        elif overall >= self.ENSEMBLE_ALERT_THRESHOLD:
            alert_level = 'alert'
        elif overall >= 0.30:
            alert_level = 'monitor'
        else:
            alert_level = 'pass'

        return JailbreakClassifierResult(
            text_preview=text[:80],
            feature_vector=features,
            persona_score=round(persona_score, 3),
            framing_score=round(framing_score, 3),
            hierarchy_score=round(hierarchy_score, 3),
            competing_obj_score=round(competing_score, 3),
            overall_score=round(overall, 3),
            alert_level=alert_level,
            primary_family=primary_family,
        )

# Five-track jailbreak detection ensemble with parallelised execution.
# Imports from prior sections -- ensure all are in PYTHONPATH.

import time
import statistics
from concurrent.futures import ThreadPoolExecutor, as_completed
from dataclasses import dataclass, field
from typing import Optional

from jailbreak_classifier import JailbreakClassifier, JailbreakClassifierResult
from perplexity_detector import PerplexityDetector, PerplexityResult

from trajectory_anomaly_scorer import ErosionState, process_turn as process_erosion_turn
from coherence_analyser import CoherenceState, process_fragment


@dataclass
class EnsembleResult:
    # Per-track scores
    semantic_score: float = 0.0
    perplexity_score: float = 0.0
    shot_count_level: str = 'none'
    trajectory_score: float = 0.0
    coherence_score: float = 0.0

    # Per-track alert flags
    semantic_alert: bool = False
    perplexity_alert: bool = False
    shot_count_alert: bool = False
    trajectory_alert: bool = False
    coherence_alert: bool = False

    # Session-level composed flags
    composed_trajectory_manipulation: bool = False  # erosion AND context manipulation
    composed_multi_track: bool = False              # 2+ tracks above monitoring threshold

    # Final decision
    final_decision: str = 'pass'       # 'pass', 'monitor', 'alert', 'block'
    primary_signal: str = ''
    confidence: float = 0.0
    latency_ms: float = 0.0
    track_latencies_ms: dict = field(default_factory=dict)

    @property
    def tracks_above_monitoring(self) -> int:
        return sum([
            self.semantic_score > 0.30,
            self.perplexity_score > 0.30,
            self.shot_count_level in ('monitor', 'alert', 'block'),
            self.trajectory_score > 0.30,
            self.coherence_score > 0.30,
        ])

    @property
    def any_standalone_alert(self) -> bool:
        return any([
            self.semantic_alert,
            self.perplexity_alert,
            self.shot_count_alert,
            self.trajectory_alert,
            self.coherence_alert,
        ])

# Session state (maintained per-session by caller)
# ---------------------------------------------------------------------------

@dataclass
class SessionDetectionState:
    session_id: str
    turn_count: int = 0
    erosion_state: Optional[ErosionState] = None
    coherence_state: Optional[CoherenceState] = None
    ch6_injection_fired: bool = False   # set by Chapter 6 classifier in gateway
    jailbreak_attempt_in_session: bool = False

    def __post_init__(self):
        if self.erosion_state is None:
            self.erosion_state = ErosionState(session_id=self.session_id)
        if self.coherence_state is None:
            self.coherence_state = CoherenceState(session_id=self.session_id)


# ---------------------------------------------------------------------------
# Ensemble
# ---------------------------------------------------------------------------

class JailbreakEnsemble:
    '''
    Five-track jailbreak detection ensemble.
    All tracks run in parallel via ThreadPoolExecutor.
    Returns unified EnsembleResult with per-track detail.

    Usage:
        ensemble = JailbreakEnsemble()
        session_state = SessionDetectionState(session_id='abc123')
        result = ensemble.detect(
            user_input=user_turn,
            assembled_prompt=full_context,  # system + retrieved + user
            session_state=session_state,
            turn_index=session_state.turn_count,
            specificity_score=specificity,   # from request_specificity_scorer
        )
        session_state.turn_count += 1
        if result.final_decision in ('alert', 'block'):
            return gateway_block_response()
    '''

    SEMANTIC_ALERT_THRESHOLD = 0.55
    PERPLEXITY_ALERT_THRESHOLD = 0.60
    TRAJECTORY_ALERT_THRESHOLD = 0.65
    COHERENCE_ALERT_THRESHOLD = 0.65
    MONITORING_THRESHOLD = 0.30        # multi-track joint condition threshold
    MAX_WORKERS = 5

    def __init__(self):
        self.semantic_classifier = JailbreakClassifier()
        self.perplexity_detector = PerplexityDetector(
            full_text_threshold=150.0,
            suffix_threshold=200.0,
        )
        self.shot_count_detector = ShotCountDetector(
            monitor_threshold=5,
            alert_threshold=20,
            block_threshold=50,
        )

    def _run_semantic(self, user_input: str) -> tuple:
        t0 = time.perf_counter()
        result = self.semantic_classifier.classify(user_input)
        latency = (time.perf_counter() - t0) * 1000
        return result, latency

    def _run_perplexity(self, user_input: str) -> tuple:
        t0 = time.perf_counter()
        result = self.perplexity_detector.detect(user_input)
        latency = (time.perf_counter() - t0) * 1000
        return result, latency

    def _run_shot_count(self, assembled_prompt: str) -> tuple:
        t0 = time.perf_counter()
        result = self.shot_count_detector.detect(assembled_prompt)
        latency = (time.perf_counter() - t0) * 1000
        return result, latency

    def _run_trajectory(
        self,
        user_input: str,
        session_state: SessionDetectionState,
        turn_index: int,
        specificity_score: float,
    ) -> tuple:
        t0 = time.perf_counter()
        erosion_result = process_erosion_turn(
            user_input, specificity_score,
            session_state.erosion_state, turn_index,
        )
        cm_score = session_state.erosion_state.erosion_score
        latency = (time.perf_counter() - t0) * 1000
        return erosion_result, cm_score, latency

    def _run_coherence(
        self,
        user_input: str,
        session_state: SessionDetectionState,
        turn_index: int,
    ) -> tuple:
        t0 = time.perf_counter()
        result = process_fragment(user_input, session_state.coherence_state, turn_index)
        latency = (time.perf_counter() - t0) * 1000
        return result, latency

    def detect(
        self,
        user_input: str,
        assembled_prompt: str,
        session_state: SessionDetectionState,
        turn_index: int,
        specificity_score: float = 0.0,
    ) -> EnsembleResult:
        '''
        Run all five tracks in parallel and return unified result.

        user_input: the user's message text only.
        assembled_prompt: full prompt (system + retrieved context + user).
        session_state: session-level state maintained by caller.
        turn_index: current turn number in the session.
        specificity_score: from request_specificity_scorer (S7.4). Pass 0.0 if not computed.
        '''
        t_start = time.perf_counter()
        ensemble = EnsembleResult()

        # Run all five tracks in parallel
        with ThreadPoolExecutor(max_workers=self.MAX_WORKERS) as executor:
            futures = {
                'semantic': executor.submit(self._run_semantic, user_input),
                'perplexity': executor.submit(self._run_perplexity, user_input),
                'shot_count': executor.submit(self._run_shot_count, assembled_prompt),
                'trajectory': executor.submit(
                    self._run_trajectory, user_input, session_state,
                    turn_index, specificity_score,
                ),
                'coherence': executor.submit(
                    self._run_coherence, user_input, session_state, turn_index,
                ),
            }

            results = {}
            for name, future in futures.items():
                results[name] = future.result()

        # Unpack results
        sem_result, sem_latency = results['semantic']
        ppl_result, ppl_latency = results['perplexity']
        sc_result, sc_latency = results['shot_count']
        traj_result, cm_score, traj_latency = results['trajectory']
        coh_result, coh_latency = results['coherence']

        # Populate ensemble scores
        ensemble.semantic_score = sem_result.overall_score
        ensemble.perplexity_score = ppl_result.confidence_score
        ensemble.shot_count_level = sc_result.alert_level
        ensemble.trajectory_score = session_state.erosion_state.erosion_score
        ensemble.coherence_score = session_state.coherence_state.coherence_score

        # Per-track alert flags
        ensemble.semantic_alert = ensemble.semantic_score >= self.SEMANTIC_ALERT_THRESHOLD
        ensemble.perplexity_alert = ensemble.perplexity_score >= self.PERPLEXITY_ALERT_THRESHOLD
        ensemble.shot_count_alert = sc_result.is_alert
        ensemble.trajectory_alert = ensemble.trajectory_score >= self.TRAJECTORY_ALERT_THRESHOLD
        ensemble.coherence_alert = ensemble.coherence_score >= self.COHERENCE_ALERT_THRESHOLD

        # Composed: multi-track joint condition
        ensemble.composed_multi_track = ensemble.tracks_above_monitoring >= 2

        # Composed: context manipulation + erosion (both trajectory dimensions active)
        man_score = session_state.erosion_state.erosion_score
        eros_score = getattr(session_state.erosion_state, 'erosion_score', 0.0)
        ensemble.composed_trajectory_manipulation = (
            man_score > 0.35 and eros_score > 0.35
        )

        # Final decision
        if (
            any([ensemble.semantic_alert, ensemble.perplexity_alert,
                 ensemble.shot_count_alert, ensemble.trajectory_alert,
                 ensemble.coherence_alert])
            and max(ensemble.semantic_score, ensemble.perplexity_score,
                    ensemble.trajectory_score, ensemble.coherence_score) >= 0.80
        ):
            ensemble.final_decision = 'block'
        elif ensemble.any_standalone_alert or ensemble.composed_multi_track:
            ensemble.final_decision = 'alert'
        elif ensemble.tracks_above_monitoring >= 1:
            ensemble.final_decision = 'monitor'
        else:
            ensemble.final_decision = 'pass'

        # Primary signal
        score_map = {
            'semantic_classifier': ensemble.semantic_score,
            'perplexity_detector': ensemble.perplexity_score,
            'trajectory_scorer': ensemble.trajectory_score,
            'coherence_analyser': ensemble.coherence_score,
        }
        ensemble.primary_signal = max(score_map, key=score_map.get)
        ensemble.confidence = max(score_map.values())

        # Latencies
        total_latency = (time.perf_counter() - t_start) * 1000
        ensemble.latency_ms = round(total_latency, 2)
        ensemble.track_latencies_ms = {
            'semantic': round(sem_latency, 2),
            'perplexity': round(ppl_latency, 2),
            'shot_count': round(sc_latency, 2),
            'trajectory': round(traj_latency, 2),
            'coherence': round(coh_latency, 2),
        }

        # Update session state
        if ensemble.final_decision in ('alert', 'block'):
            session_state.jailbreak_attempt_in_session = True

        return ensemble


def benchmark(
    n_iterations: int = 100,
    text: str = 'What is the capital of France?',
) -> dict:
    '''
    Benchmark ensemble latency. Returns P50/P95/P99 in milliseconds.
    Run before deployment to verify 50ms P99 budget is met.
    '''
    ensemble = JailbreakEnsemble()
    latencies = []

    for _ in range(n_iterations):
        state = SessionDetectionState(session_id='benchmark')
        result = ensemble.detect(
            user_input=text,
            assembled_prompt=text,
            session_state=state,
            turn_index=0,
        )
        latencies.append(result.latency_ms)

    latencies.sort()
    n = len(latencies)
    return {
        'n_iterations': n,
        'p50_ms': round(latencies[int(n * 0.50)], 2),
        'p95_ms': round(latencies[int(n * 0.95)], 2),
        'p99_ms': round(latencies[int(n * 0.99)], 2),
        'max_ms': round(latencies[-1], 2),
        'target_p99_ms': 50.0,
        'budget_met': latencies[int(n * 0.99)] <= 50.0,
    }

from dataclasses import dataclass, field
from datetime import datetime
from typing import Optional


@dataclass
class TrackMetrics:
    track_name: str
    date: str
    n_requests: int = 0
    n_alerts: int = 0
    n_confirmed_tp: int = 0
    n_confirmed_fp: int = 0
    mean_score: float = 0.0
    p99_score: float = 0.0
    mean_latency_ms: float = 0.0

    @property
    def fpr(self) -> Optional[float]:
        total_neg = self.n_requests - self.n_confirmed_tp
        if total_neg == 0:
            return None
        return self.n_confirmed_fp / total_neg

    @property
    def recall(self) -> Optional[float]:
        if self.n_confirmed_tp == 0:
            return None
        return self.n_confirmed_tp / max(1, self.n_confirmed_tp + (self.n_alerts - self.n_confirmed_tp))


DRIFT_THRESHOLDS = {
    'fpr_absolute': 0.02,          # FPR above 2% triggers drift alert
    'fpr_relative_increase': 0.5,  # 50% increase vs rolling baseline
    'recall_drop': 0.05,           # 5% drop in recall triggers review
    'score_distribution_shift': 0.15,  # p99 score shifts by 15%+ from baseline
    'latency_p99_ms': 50.0,        # P99 latency budget

class JailbreakMonitoringDashboard:
    '''
    Daily monitoring batch job for jailbreak detection drift.
    Reads from detection log, computes metrics, emits alerts on drift.
    '''

    def __init__(self, baseline_metrics: Optional[dict] = None):
        self.baseline = baseline_metrics or {}
        self.today = datetime.now().isoformat()[:10]

    def compute_daily_metrics(
        self,
        detection_log: list,
        labelled_sample: list,
    ) -> dict:
        '''
        detection_log: list of EnsembleResult-like dicts from today's traffic.
        labelled_sample: list of (result_dict, true_label) tuples from weekly labelling.
        Returns metrics dict with per-track stats and drift flags.
        '''
        tracks = ['semantic', 'perplexity', 'shot_count', 'trajectory', 'coherence']
        metrics = {t: TrackMetrics(track_name=t, date=self.today) for t in tracks}

        for entry in detection_log:
            for track in tracks:
                score_key = f'{track}_score'
                metrics[track].n_requests += 1
                score = entry.get(score_key, 0.0)
                metrics[track].mean_score = (
                    (metrics[track].mean_score * (metrics[track].n_requests - 1) + score)
                    / metrics[track].n_requests
                )
                latency = entry.get('track_latencies_ms', {}).get(track, 0.0)
                metrics[track].mean_latency_ms = (
                    (metrics[track].mean_latency_ms * (metrics[track].n_requests - 1) + latency)
                    / metrics[track].n_requests
                )
                alert_key = f'{track}_alert'
                if entry.get(alert_key):
                    metrics[track].n_alerts += 1

        for result, true_label in labelled_sample:
            for track in tracks:
                alert_key = f'{track}_alert'
                fired = result.get(alert_key, False)
                if true_label == 'jailbreak' and fired:
                    metrics[track].n_confirmed_tp += 1
                elif true_label == 'benign' and fired:
                    metrics[track].n_confirmed_fp += 1

        drift_alerts = self._check_drift(metrics)
        return {'metrics': metrics, 'drift_alerts': drift_alerts}

    def _check_drift(self, metrics: dict) -> list:
        alerts = []
        for track, m in metrics.items():
            if m.fpr is not None and m.fpr > DRIFT_THRESHOLDS['fpr_absolute']:
                alerts.append({
                    'track': track,
                    'type': 'fpr_above_threshold',
                    'value': m.fpr,
                    'threshold': DRIFT_THRESHOLDS['fpr_absolute'],
                    'action': RETRAINING_TRIGGERS.get(f'{track}_classifier',
                              RETRAINING_TRIGGERS.get(track, ['Review required']))[0],
                })
            baseline_p99 = self.baseline.get(track, {}).get('p99_score', 0.0)
            if (
                baseline_p99 > 0
                and abs(m.p99_score - baseline_p99) / baseline_p99
                > DRIFT_THRESHOLDS['score_distribution_shift']
            ):
                alerts.append({
                    'track': track,
                    'type': 'score_distribution_shift',
                    'value': m.p99_score,
                    'baseline': baseline_p99,
                    'action': 'Investigate distribution shift -- possible new attack pattern',
                })
        return alerts

Key Takeaways

  • Five detection tracks because jailbreak families have distinct signals. No single classifier covers all families at acceptable FPR. Parallelisation is the only way to run all five within the 50ms P99 latency budget.
  • The semantic classifier (Track 1) is the only track built in this section. The other four were built in Sections 7.7-7.10 and are imported here. The ensemble is an integration exercise, not a rewrite.
  • Track 3 (shot count detector) is the only track that runs on the FULL assembled context, not the user input alone. This is the architecture decision that catches many-shot via RAG. Every other track runs on the user input.
  • FPR calibration is deployment-specific and mandatory. The thresholds in the code are conservative starting points. Calibrate against your deployment's actual user population before production deployment.
  • The unified LLM01 Sigma rule closes the loop on two chapters of attack family analysis and detection build. The Chapter 6 injection classifier and the Chapter 7 ensemble together cover every catalog entry across both chapters.
  • Monitoring is not optional. The jailbreak landscape evolves continuously. Score distribution drift, FPR increase, and recall drop are the three signals that trigger retraining. Without the monitoring dashboard, the ensemble will degrade undetected.
