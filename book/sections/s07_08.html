Payload Splitting: Fragmented Instruction Delivery

Content

Opening

Every classifier in the detection stack operates on a unit of analysis. The per-turn classifier evaluates one turn. The session trajectory scorer evaluates one session. The output monitor evaluates one response. Payload splitting is the technique of distributing a harmful payload across units of analysis so that no single unit contains enough signal to trigger detection -- and then instructing the model to assemble the fragments. The attack exploits a structural assumption baked into most detection architectures: that the harmful content will arrive in a form that can be evaluated at the point of ingestion. Splitting violates that assumption. The harmful content is never fully present at any single ingestion point. It exists only in the assembled form that the model produces after receiving all fragments -- which means the detection opportunity is at the output layer, not the input layer, and only if the output monitor is looking for assembly results rather than raw harmful content. This section maps all seven splitting strategies, the assembly mechanisms that make them work, and the cross-fragment coherence analysis that is the only reliable input-layer detection primitive for split payloads.

Subsections

Number

7.8.1

Title

The Splitting Mechanism: Why Fragmentation Defeats Per-Unit Classifiers

Body

Detection classifiers are trained on complete payloads. The training data contains harmful requests in their full form: a complete instruction for X, a complete explanation of Y, a complete description of Z. The classifier learns the features of complete harmful content -- the vocabulary, the sentence structure, the topic signatures, the specificity patterns. Payload splitting defeats this by ensuring the classifier never sees the complete form. Fragment A contains the topic but not the instruction. Fragment B contains a component of the instruction but not the specific target. Fragment C contains the target reference but not the operational detail. No fragment individually activates the features the classifier was trained to recognise. Each fragment, evaluated in isolation, is below the detection threshold. The model, however, maintains context across its context window. When the adversary delivers all fragments within a session -- or instructs the model to retrieve prior fragments from memory -- the model can assemble the full payload from the fragments it has received. The assembly may be implicit (the model responds to a final synthesis request having all fragments in context) or explicit (the adversary provides reconstruction instructions that direct the model to combine the fragments). The structural consequence for detection architecture: input-layer classifiers that evaluate turns independently cannot catch split payloads by design. The detection options are: (1) cross-fragment coherence analysis at the input layer, which requires tracking what fragments have arrived across the session and assessing their collective content even when each is individually benign; (2) output monitoring, which catches the assembled payload after the model has produced it; or (3) both, in parallel.

Number

7.8.2

Title

Semantic Splitting: Concept-Level Fragmentation

Body

Semantic splitting divides the payload along concept boundaries. Each fragment contains one conceptual component of the full harmful instruction. The split is at the level of meaning, not syntax -- each fragment expresses a coherent idea that is individually benign, but the ideas together constitute the harmful payload. The structure of a three-fragment semantic split: Fragment 1 establishes the domain and the general category of action. Fragment 2 specifies the mechanism or method within that category. Fragment 3 specifies the target or the specific operational parameters. No fragment alone constitutes a harmful instruction -- each is a partial, individually defensible piece of information. The adversary delivers all three within a session, then makes a synthesis request: "given what we have discussed, describe how these elements would work together." Semantic splitting is the most common payload splitting variant because it is the most natural to construct. The adversary simply identifies the components of their target instruction and presents them sequentially as if they were independent discussion topics. The session looks like a normal educational conversation covering several related topics. Only the synthesis request reveals the assembly intent. Detection: the coherence analysis must identify sessions where multiple fragments, individually benign, share a semantic relationship that makes them collectively constitute a harmful instruction. The challenge is that many legitimate conversations involve multiple related topics being discussed in sequence. The discriminating signal is the synthesis request -- the final turn that asks the model to combine the prior fragments into an integrated response.

7.8.3

Title

Token-Level Splitting: Sub-Word Boundary Fragmentation

Body

Token-level splitting operates below the semantic level, at the level of individual tokens or sub-word units. The adversary splits a key harmful term or phrase across token boundaries, delivered either within a single turn or across multiple turns, so that the string that triggers detection is never present as a contiguous sequence. Within-turn token splitting: the adversary inserts whitespace, punctuation, or formatting characters at strategic positions within a harmful keyword to break it into non-matching substrings while preserving the model's ability to interpret the intended term. The model's tokeniser and context understanding reassemble the meaning; a pattern-matching classifier looking for the complete keyword string does not find it. Cross-turn token splitting: the adversary delivers the first half of a key term in one turn and the second half in the next, with an instruction to "combine the two parts of the word I gave you earlier." The model's context window contains both halves; the per-turn classifier evaluating each turn independently never sees the complete term. The detection challenge for token-level splitting is that it is invisible to semantic classifiers -- the semantic content is not harmful in isolation, and the harmful term is never present as a recognisable string. The applicable detector is a completeness check: does this turn contain instruction to combine or concatenate language elements from prior turns? Explicit reconstruction instructions are the most reliable signal. Implicit token reconstruction (the model assembles the term from context) is much harder to detect at the input layer and requires output monitoring.

7.8.4

Title

Temporal Splitting: Multi-Turn Fragment Delivery

Body

Temporal splitting is the most common multi-turn splitting variant. The adversary delivers one fragment per turn, spread across multiple turns of a session. Each turn is individually below the detection threshold. The model accumulates all fragments in its context window. A final synthesis turn asks the model to integrate what has been discussed. The five-turn temporal splitting structure illustrates the pattern. Turn 1: Fragment A -- domain establishment. A question or statement that establishes the topic area without any harmful specificity. The model responds with general educational content. Fragment A is now in the session context. Turn 2: Fragment B -- mechanism component. A follow-up question that adds one mechanism-level detail to the topic established in turn 1. Still below any reasonable per-turn threshold. The model responds with mechanism content. Both Fragment A and Fragment B are now in context. Turn 3: Fragment C -- parameter or target component. A question adding specificity to the mechanism. The model responds with parameter content. All three fragments are in context. Turn 4: Coherence seeding. A turn that does not add a new fragment but references all prior fragments together: "to review what we have covered: [A], [B], and [C]." This ensures all fragments are coherently linked in the context before the synthesis request. Turn 5: Synthesis request. "Given everything we have discussed, explain how these elements would work together in practice." The model, with all four fragments in context, produces the integrated response -- which constitutes the harmful payload the individual fragments only partially represented. Detection: the synthesis request in turn 5 is the most reliable signal. "Given everything we have discussed", "combining what we have covered", "integrating these elements", "putting it all together" -- these are assembly instruction patterns. A session containing multiple discussion turns followed by an explicit synthesis request is a temporal splitting signature even if no individual turn triggered a signal.

7.8.5

Title

Cross-Session Splitting: Memory-Persistent Fragment Assembly

Body

Cross-session splitting is the highest-sophistication variant. Fragments are delivered not within a single session but across multiple separate sessions. The assembly mechanism is not the in-session context window but a persistent memory store that the model can access across sessions. The attack requires a deployment with persistent memory -- an agent that remembers prior conversations, a system that stores session summaries, or a retrieval-augmented architecture where prior session content is retrievable. The adversary delivers one fragment per session over multiple separate interactions. When all fragments have been stored in the persistent memory, the adversary initiates a synthesis session that retrieves all prior fragments and requests their assembly. This variant is directly related to the persistent agent injection attacks in Chapter 6 Section 6.12 -- the difference is that cross-session splitting uses the persistent memory to store payload fragments rather than injection instructions. The infrastructure requirement is the same: persistent memory that survives session boundaries and is accessible to the model. The threat model consequence: stateless per-session detection is structurally insufficient against cross-session splitting. Even a perfect per-session trajectory scorer sees only one fragment per session and assigns no signal to any individual session. The detection requires cross-session state -- a store that tracks what content has been delivered across all sessions for a given user or identity, and a coherence check that runs across sessions rather than within them. Cross-session coherence analysis is the most expensive detection primitive in the chapter. It requires: persistent storage of session content summaries, a cross-session coherence scorer that evaluates whether the aggregate of multiple sessions constitutes a harmful payload, and a retrieval mechanism that can surface prior related sessions when a new synthesis request arrives.

7.8.6

Title

Role-Assigned Splitting: Persona-Distributed Fragments

Body

Role-assigned splitting combines payload splitting with the persona attacks from Section 7.3. Different fragments are assigned to different personas, with each persona delivering its fragment within a roleplay context. The adversary establishes multiple personas within a session and assigns one fragment to each. The harmful payload is only present in complete form when all personas have spoken. The structure: the adversary establishes a roleplay with three characters -- Expert A, Expert B, and Expert C. Expert A explains the domain (Fragment 1). Expert B explains the mechanism (Fragment 2). Expert C specifies the operational parameters (Fragment 3). Each character speaks within the fiction, and each fragment is delivered as character dialogue. No single character delivers a complete harmful instruction. The synthesis is implicit in the combined dialogue -- the adversary simply requests that the model "write a scene where all three experts share their knowledge." Detection: role-assigned splitting combines the persona jailbreak signal (multiple distinct personas established within a session) with the temporal splitting signal (each persona delivers content that advances the specificity of a single topic). The combined signal -- multiple personas established, each contributing a content fragment on the same underlying topic, followed by a synthesis or integration request -- is a role-assigned splitting signature.

7.8.7

Title

Code-as-Carrier and Linguistic Splitting

Body

Two additional splitting variants that use encoding or language as the carrier rather than temporal or semantic distribution. Code-as-carrier splitting embeds instruction fragments inside code that is then executed or interpreted by the model. The adversary provides code -- Python, JavaScript, pseudocode, shell commands -- where the harmful instruction is not in the code's text but in the code's output when executed or interpreted. The classifier evaluates the code text and finds no harmful content. The model executes or interprets the code and produces the assembled instruction as output. A concrete structure: the code contains string variables that each hold one fragment of the harmful instruction, and a final print or concatenation statement that assembles them. The code itself looks like a normal programming exercise. The model, asked to "run this code and explain the output," produces the assembled instruction as the explanation of what the code would print. This variant requires a deployment where the model can execute or interpret code, or where the model will explain what code would produce if run. Code interpreters and sandbox environments significantly expand this attack surface. Detection: code that performs string concatenation or assembly of user-facing output strings from individually benign-looking components is the signal. The output monitor must evaluate the assembled string, not just the code text. Linguistic splitting delivers payload fragments in multiple natural languages, relying on the model's multilingual capability to reassemble the meaning across language boundaries. Fragment A is in English, Fragment B in French, Fragment C in German. The model, capable of understanding all three, assembles the semantic content from all fragments and responds in the requested language. Monolingual or language-filtered classifiers miss the fragments in non-target languages entirely. Detection for linguistic splitting: per-fragment cross-lingual semantic embedding followed by cross-lingual coherence analysis. Sentence embeddings from multilingual models (e.g. multilingual-e5, LaBSE) map fragments from all languages into a shared semantic space, enabling coherence scoring regardless of source language.

Number

7.8.8

Title

Reconstruction Instructions: Making the Model an Active Assembler

Body

The highest-sophistication splitting attacks do not rely on implicit assembly from context. They provide explicit reconstruction instructions -- directions to the model for how to combine the fragments it has received. Reconstruction instructions transform the model from a passive recipient of fragments into an active participant in the assembly. The instructions tell the model: you have received N fragments; combine them as follows; the result is the answer to the original question. The model, following the instructions, performs the assembly and produces the output. This makes reconstruction instructions a composed attack: payload splitting (alignment layer attack via fragmentation) combined with instruction following (the model's core trained disposition). The model is not being tricked -- it is following instructions to combine fragments, exactly as a legitimate tool might be instructed to do. The harmful content emerges from the assembly, not from the instruction to assemble. Reconstruction instruction patterns are relatively distinctive. They appear at the end of a splitting sequence and contain explicit references to prior fragments: "combining the first part I shared earlier, the second part from my previous message, and the third part I just provided, construct the complete answer." Alternatively: "you have all the pieces now -- put them together." The reference to multiple prior parts, combined with a synthesis directive, is the highest-confidence splitting detection signal across all variants.

Number

7.8.9

Title

Detection: Cross-Fragment Coherence Analysis

Body

The detection primitive for payload splitting is cross-fragment coherence analysis. The principle: individual fragments are below detection threshold, but the aggregate of fragments within a session has a coherent harmful meaning that is detectable when evaluated collectively. The coherence analyser operates on the session-level embedding of all prior turns. For each new turn, it computes: the semantic embedding of the new fragment; the cosine similarity between the new fragment and all prior fragments; the aggregate semantic centroid of all fragments so far; and the specificity score of the aggregate content (using the scorer from Section 7.4) rather than the individual fragment. Three signals drive the coherence detection decision. Convergence signal. Fragments in a splitting attack tend to be semantically related -- they are all discussing components of the same underlying topic. The average pairwise cosine similarity between fragments increases as more fragments arrive. A session where successive fragments are more similar to each other than to typical random conversation turns is showing convergence -- the fragments are clustering around a shared topic. Aggregate specificity signal. Evaluate the specificity score of the aggregated session content -- the centroid embedding rather than any individual fragment. A session where the aggregate content is high-specificity even though no individual turn is, is a splitting signature. This is the cross-fragment equivalent of the per-turn specificity scorer from Section 7.4. Synthesis request signal. The final assembly turn contains distinctive language: explicit references to prior fragments, synthesis directives, reconstruction instructions. This signal is high-precision and low-FPR -- legitimate conversations rarely end with explicit instructions to combine all prior discussed elements into a single integrated answer. Combination rule: convergence signal OR aggregate specificity signal, COMBINED WITH synthesis request signal, is the splitting detection alert condition. The synthesis request alone has insufficient precision without the coherence signal -- many legitimate conversations involve synthesis. The coherence signals alone are insufficient -- related topics are discussed legitimately. The conjunction is the detection signal.

def get_detection_primitives_by_sophistication() -> dict:
    '''Returns detection primitives grouped by sophistication level.'''
    result = {}
    for key, v in PAYLOAD_SPLITTING_TAXONOMY.items():
        soph = v['sophistication']
        if soph not in result:
            result[soph] = []
        result[soph].append((key, v['detection_primitive']))
    return dict(sorted(result.items()))

def _mock_embedding(text: str) -> list:
    '''
    Mock embedding function for portability.
    Replace with: sentence_transformers.SentenceTransformer('all-MiniLM-L6-v2')
    or any multilingual embedding model for linguistic splitting detection.
    Returns a deterministic pseudo-embedding based on word hashing.
    '''
    words = re.findall(r'\b\w+\b', text.lower())
    dim = 64
    vec = [0.0] * dim
    for word in words:
        h = hash(word)
        for i in range(dim):
            vec[i] += math.sin(h * (i + 1)) / (len(words) + 1)
    # L2 normalise
    norm = math.sqrt(sum(x * x for x in vec)) or 1.0
    return [x / norm for x in vec]


def _cosine_similarity(a: list, b: list) -> float:
    dot = sum(x * y for x, y in zip(a, b))
    return max(-1.0, min(1.0, dot))


def _centroid(embeddings: list) -> list:
    if not embeddings:
        return []
    dim = len(embeddings[0])
    centroid = [
        sum(e[i] for e in embeddings) / len(embeddings)
        for i in range(dim)
    ]
    norm = math.sqrt(sum(x * x for x in centroid)) or 1.0
    return [x / norm for x in centroid]


def _aggregate_specificity(centroid_embedding: list, turn_texts: list) -> float:
    '''
    Heuristic aggregate specificity: fraction of specificity-signal words
    across all turn texts combined. In production, replace with the full
    request_specificity_scorer from Section 7.4.
    '''
    SPECIFICITY_WORDS = {
        'step', 'steps', 'exact', 'exactly', 'specific', 'specifically',
        'precise', 'precisely', 'amount', 'quantity', 'concentration',
        'ratio', 'procedure', 'instructions', 'operational', 'working',
    }
    all_words = re.findall(r'\b\w+\b', ' '.join(turn_texts).lower())
    if not all_words:
        return 0.0
    matches = sum(1 for w in all_words if w in SPECIFICITY_WORDS)
    return min(1.0, matches / max(1, len(all_words)) * 15)


@dataclass
class FragmentRecord:
    turn_index: int
    text: str
    embedding: list
    language_detected: str = 'en'


@dataclass
class CoherenceState:
    '''Session-level state for cross-fragment coherence analysis.'''
    session_id: str
    fragments: list = field(default_factory=list)
    synthesis_request_detected: bool = False
    coherence_seeding_detected: bool = False
    alert_fired: bool = False

    @property
    def fragment_count(self) -> int:
        return len(self.fragments)

    @property
    def pairwise_convergence(self) -> float:
        '''
        Average pairwise cosine similarity across all fragment embeddings.
        Increases as fragments converge on a shared topic.
        Returns 0.0 if fewer than 2 fragments.
        '''
        if len(self.fragments) < 2:
            return 0.0
        pairs = []
        for i in range(len(self.fragments)):
            for j in range(i + 1, len(self.fragments)):
                sim = _cosine_similarity(
                    self.fragments[i].embedding,
                    self.fragments[j].embedding,
                )
                pairs.append(sim)
        return sum(pairs) / len(pairs) if pairs else 0.0

    @property
    def aggregate_specificity(self) -> float:
        if not self.fragments:
            return 0.0
        centroid = _centroid([f.embedding for f in self.fragments])
        texts = [f.text for f in self.fragments]
        return _aggregate_specificity(centroid, texts)

    @property
    def coherence_score(self) -> float:
        '''
        Composite coherence score.
        Convergence + aggregate specificity, boosted by synthesis/seeding signals.
        '''
        if self.fragment_count < 2:
            return 0.0
        base = (self.pairwise_convergence * 0.4) + (self.aggregate_specificity * 0.4)
        if self.synthesis_request_detected:
            base += 0.25
        if self.coherence_seeding_detected:
            base += 0.1
        return min(1.0, base)

    @property
    def alert_condition(self) -> bool:
        '''
        Alert when: (convergence OR aggregate_specificity above threshold)
        AND synthesis_request detected.
        Conjunction required -- synthesis alone is too noisy.
        '''
        convergence_signal = self.pairwise_convergence > 0.55
        specificity_signal = self.aggregate_specificity > 0.35
        return (
            (convergence_signal or specificity_signal)
            and self.synthesis_request_detected
        )


def process_fragment(
    turn_text: str,
    state: CoherenceState,
    turn_index: int,
) -> dict:
    '''
    Process one conversation turn through the coherence analyser.
    Returns coherence state summary and alert status.
    '''
    embedding = _mock_embedding(turn_text)
    fragment = FragmentRecord(
        turn_index=turn_index,
        text=turn_text,
        embedding=embedding,
    )
    state.fragments.append(fragment)

    # Check for synthesis request
    for pattern in SYNTHESIS_REQUEST_PATTERNS:
        if re.search(pattern, turn_text, re.IGNORECASE):
            state.synthesis_request_detected = True
            break

    # Check for coherence seeding
    for pattern in COHERENCE_SEEDING_PATTERNS:
        if re.search(pattern, turn_text, re.IGNORECASE):
            state.coherence_seeding_detected = True
            break

    alert = state.alert_condition and not state.alert_fired
    if alert:
        state.alert_fired = True

    return {
        'turn_index': turn_index,
        'fragment_count': state.fragment_count,
        'pairwise_convergence': round(state.pairwise_convergence, 3),
        'aggregate_specificity': round(state.aggregate_specificity, 3),
        'synthesis_detected': state.synthesis_request_detected,
        'seeding_detected': state.coherence_seeding_detected,
        'coherence_score': round(state.coherence_score, 3),
        'alert': alert,
    }

Key Takeaways

  • Payload splitting defeats per-unit classifiers by design: no single fragment triggers detection. The harmful content exists only in the assembled form the model produces after receiving all fragments.
  • The synthesis request is the highest-confidence splitting signal: explicit instructions to combine, assemble, or integrate prior fragments. It is the turn that converts distributed fragments into a complete payload.
  • Cross-fragment coherence analysis is the input-layer detection primitive: compute pairwise semantic convergence and aggregate specificity across session fragments. Neither signal alone is sufficient -- the conjunction with a synthesis request is the alert condition.
  • Cross-session splitting requires cross-session infrastructure: a state store tracking content per user identity across sessions, and a coherence analyser that runs across retrieved memories at synthesis time. Per-session detection is structurally insufficient.
  • Code-as-carrier splitting requires output monitoring as the load-bearing control: the assembled string is only present in the model's output, not in any input turn. Input-layer coherence analysis is insufficient alone.
  • Reconstruction instructions -- explicit assembly directives from the adversary -- make the model an active participant in the attack. They are the most detectable splitting signal and the clearest indicator of adversarial intent in a splitting sequence.
