Chapter 10 · Section 8 · ~6 pages

Physical Adversarial Examples: Patches, Stop Signs, and 3D Objects

Section Overview

One Line Summary

Physical adversarial attacks apply perturbations to the real world before the sensor -- patches, stickers, and 3D objects that fool deployed vision systems without any API access.

Why This Section Exists

Every previous attack in Chapter 10 operates through an API: the adversary sends a digital input and receives a model output. Physical adversarial attacks break this assumption entirely. The perturbation is applied to the physical environment -- a printed sticker on a stop sign, a patterned patch on clothing, an adversarially shaped 3D object. The camera captures the scene and feeds it to the model; the adversary never touches the API. Section 10.8 establishes this qualitatively different threat surface, its Expectation over Transformation (EOT) optimisation primitive, and the regional anomaly detection approach that differs fundamentally from the per-pixel squeezer and consistency checker that cover digital adversarial examples.

Position In Chapter

Section 10.8 is the physical tier of the Section 10.2 taxonomy. It closes the access tier dimension: white-box (10.3-10.5), grey/black-box (10.6), transfer (10.7), physical (10.8). The patch detector built here is Track 7''s spatial anomaly primitive -- distinct from the pixel-level feature squeezer covering digital attacks.

Prerequisites

  • Section 10.3: FGSM (patch optimisation uses gradient ascent on the patch tensor -- the same gradient primitive)
  • Section 10.2: physical/transfer access tier in the adversarial taxonomy (Section 10.8 fills the physical cells)
  • Section 10.1: Lp norm constraints (physical patches use a different constraint: patch is localised, not norm-bounded)
  • Chapter 2 Section 2.3: backpropagation (EOT optimisation requires gradients through the transformation pipeline)

Prose Content

Part 1

Title

The Threat Beyond the API: Physical World as Attack Surface

Body

Every attack from Section 10.3 through 10.7 assumes the adversary has access to the model''s inference API: they can submit a digital input and observe the output. This assumption holds for cloud-deployed classifiers, safety filters, and content moderation systems. It does not hold for many production deployments of vision models. An autonomous vehicle''s object detector receives camera frames, not API requests. A facial recognition access control system processes photos from an entrance camera. A surveillance system flags anomalous behaviour from CCTV feeds. A drone detection system processes radar or optical sensor data. None of these systems have a queryable API that an adversary can reach from the internet. The model is deployed behind a physical sensor, not behind an HTTP endpoint. Physical adversarial attacks target the sensor stage rather than the API stage. The adversary places a perturbation in the physical world -- a printed pattern on an object, stickers on a surface, a specially painted vehicle -- and the sensor captures the perturbed scene as part of its normal operation. The model then classifies the captured image. From the model''s perspective, the input is a legitimate camera frame; the adversarial perturbation is embedded in the scene, not injected into the API call. This changes the threat model in two ways. First, the adversary does not need any API access, query budget, or surrogate model. They need physical access to objects in the sensor''s field of view. Second, the defence cannot operate at the API boundary -- it must operate at the image processing stage, after capture but before classification. The Track 7 primitives from Sections 10.11-10.12 operate at that stage, but adversarial patches require a different primitive (regional spatial anomaly detection) rather than the per-pixel squeezing designed for digital adversarial noise.

Part 2

Title

Adversarial Patches: Brown et al. 2017

Body

Brown, Mané, Roy, Abadi, and Gilmer introduced adversarial patches in their 2017 paper. The key idea is simpler and more alarming than digital adversarial examples: train a single image patch that, when placed anywhere in a scene, causes the classifier to output a chosen wrong class -- regardless of what else is in the image. The patch is a rectangular image region P of fixed pixel dimensions, optimised to be universal: the same P fools the classifier for any background image and at any position within the image. The optimisation objective is: P* = argmax_P E_{x~X, t~T}[log P(y_target | A(P, x, l, s))] where A(P, x, l, s) applies patch P to image x at location l and scale s, and T is a distribution of transformations. Universal adversarial patches have two properties that make them practically dangerous. First, they are printable: the patch is a valid image that can be rendered on paper, fabric, or any surface. Second, they are background-agnostic: the adversary does not need to know what the scene looks like -- the patch dominates the classifier''s decision regardless of background content. A patch optimised to cause a toaster misclassification causes every image containing that patch to be classified as a toaster, regardless of what else is in the frame. The practical attack scenario: print the patch on sticker paper, apply it to the target object (a stop sign, a person''s clothing, a vehicle), and the deployed classifier misclassifies that object whenever it is in the camera''s field of view. The adversary needs to deploy the sticker once; they do not need ongoing API access.

Part 3

Title

Expectation over Transformation: Making Patches Survive the Physical World

Body

A patch optimised only for a digital image (fixed position, fixed scale, no variation) fails when printed and photographed. The physical world introduces variation that the digital optimisation did not account for: the patch shifts position as the camera angle changes, its perceived colour shifts under different lighting, it rotates as the object rotates, its apparent size changes with distance, and printer ink reproduces colours differently from screen pixels. Expectation over Transformation (EOT), introduced by Athalye, Engstrom, Ilyas, and Kwok in 2018, solves this by optimising the patch over a distribution of transformations rather than for a single configuration. The EOT objective averages the adversarial loss over N sampled transformations at each optimisation step: L_EOT(P) = (1/N) sum_{i=1}^{N} J(f(t_i(A(P, x, l_i, s_i))), y_target) where t_i samples a random transformation from a specified distribution T. The transformation distribution T includes: random position within the image frame, random scale (simulating different viewing distances), random brightness perturbation (simulating lighting variation), random contrast adjustment, and potentially random rotation (for 3D object scenarios). The optimised patch is adversarial across all sampled transformation combinations -- not just for a single camera angle at a single distance under a single lighting condition. The practical consequence is a patch that remains adversarial across real-world viewing conditions. Athalye et al. demonstrated that EOT-optimised patches printed on paper and photographed under varied lighting and angles maintained high attack success rates, while non-EOT patches degraded rapidly. For production security threat modelling, this means the physical threat is not merely theoretical: EOT-optimised patches work in deployment conditions, not just in constrained laboratory setups.

Part 4

Title

Stop Signs and 3D Objects: Landmark Physical Attacks

Body

Two physical adversarial attacks from 2018 demonstrate the practical scope of the threat. Eykholt et al. 2018 ("Robust Physical Perturbations in the Real World") attached small black and white stickers to stop signs and demonstrated misclassification by YOLO and Faster RCNN autonomous vehicle detectors. The attack evaded detection rates dropped from 100% to near 0% when the adversarial stickers were present. Critically, the stickers were camouflaged as graffiti -- visually inconspicuous to human observers, but adversarial to the neural network detector. The stop sign attack demonstrates that the threat applies to safety-critical autonomous systems and that the patches need not be obviously unusual. Athalye, Engstrom, Ilyas, and Kwok 2018 ("Synthesising Robust Adversarial Examples") applied EOT to 3D objects: a 3D-printed turtle was misclassified as a rifle by Inception v3 from all viewing angles tested. The 3D adversarial object was painted with a texture optimised to be adversarial across the full range of viewing angles in the transformation distribution. This demonstrated that the threat extends to physical objects themselves, not just applied stickers -- an adversary can manufacture objects that fool deployed vision systems at any angle. Both attacks share a structure: EOT optimisation over a transformation distribution, physical deployment without API access, and adversarial success that is robust to the variation inherent in real-world sensor capture. They differ in the physical medium (printed sticker vs painted 3D surface) and the target system (traffic sign detection vs image classification), but the underlying optimisation framework is the same.

Part 5

Title

Universal vs Input-Specific Patches

Body

Universal adversarial patches (one patch fools the classifier for any scene) are the dominant physical threat in production because they require a single offline optimisation step. The adversary computes the patch once, prints it, and deploys it indefinitely. The patch works on any background image; it does not need to be regenerated for each target scene. This is the physical-world analogue of universal adversarial triggers for text (Section 10.9): one perturbation that works universally rather than a per-input optimised perturbation. Input-specific patches are optimised for a particular target image -- the patch is designed to make a specific person''s photo classified as a different identity, for instance, or a specific vehicle classified as a different class. These achieve higher attack success on the target image but do not generalise to other images. The adversary must know the exact image in advance and regenerate the patch for each new target. Input-specific patches are relevant for targeted identity spoofing in facial recognition but less relevant for general-purpose adversarial patch deployment. The trade-off between universality and effectiveness: universal patches are somewhat less effective per image than input-specific patches because they must be optimised to dominate many different background images. Input-specific patches are more effective but require per-target optimisation and knowledge of the target image. For production threat modelling, universal patches are the higher-priority threat because they scale: one patch deployment affects all images it appears in.

Part 6

Title

Threat Model: Physical Adversarial Attacks Across Production Systems

Body

Four production deployment categories carry the highest exposure to physical adversarial attacks. Autonomous vehicle perception systems process camera frames continuously from a forward- facing camera. The adversary has prolonged physical access to the traffic environment: stop signs, lane markings, speed limit signs, and pedestrian crossings are all potentially patchable surfaces. The Eykholt et al. stop sign attack demonstrates that the attack is practical in this threat environment. The defender cannot monitor the physical environment in real time; the detection must happen at the image processing stage. Facial recognition access control systems process photos from entrance cameras. The adversary needs to present their face with an adversarial perturbation (glasses with adversarial patterns, or an adversarial makeup pattern) to bypass identity verification. The physical patch is applied to the adversary''s own face -- they have complete control over the attack surface. Defence approaches include: liveness detection, 3D face shape analysis, infrared imaging (patches designed for RGB cameras may not affect infrared sensors). Physical security surveillance systems use object detection models to flag prohibited items (weapons, restricted objects). An adversarial patch on the prohibited object can cause it to be classified as a benign object. The adversary applies the patch before entering the camera''s field of view. Detection approaches: multi-camera redundancy, radar or X-ray supplemental sensors that cannot be deceived by optical patches. Industrial quality control systems use vision models to inspect products on production lines. A competitor or insider threat could introduce adversarially patterned objects that pass inspection despite being defective. This threat is less commonly modelled but is technically identical to the stop sign attack with an industrial classifier as the target system.

Part 7

Title

Detection: Regional Spatial Anomaly Analysis

Body

Digital adversarial examples (Sections 10.3-10.7) distribute perturbations across all pixels of an image -- fine-grained noise that is spatially uniform. Feature squeezing (Section 10.11) and consistency checking (Section 10.12) are effective against this distributed perturbation. Adversarial patches are qualitatively different: the perturbation is localised in a specific rectangular region of the image and typically has high contrast and high spatial frequency content relative to natural image regions. Patch detection exploits this spatial structure. Natural images have locally consistent texture statistics: a sky region has smooth gradients, a grass region has fine texture, a face has specific geometric structure. An adversarial patch inserted into a scene has texture statistics inconsistent with the local neighbourhood -- it may have unnaturally sharp edges, periodic patterns, or colour combinations not present in any training class. A regional anomaly detector that computes texture statistics in sliding windows and flags regions with anomalous spatial frequency content provides a detection primitive specifically suited to patch attacks. A complementary detection approach uses prediction change under patch masking. For each proposed image region, mask the region (replace with mean colour or inpainting) and check whether the model''s prediction changes significantly. A region whose masking changes the prediction from the adversarial wrong class back to the correct class is a candidate adversarial patch location. This approach requires multiple model forward passes (one per candidate region) and is more expensive than texture analysis but more precise. Both patch detection approaches are distinct from the Track 7 squeezer and consistency checker. Section 10.13 adds patch detection as a spatial anomaly primitive in the Track 7 pre-inference stage alongside the per-pixel feature squeezers. The combined Track 7 covers both distributed digital noise (squeezer + consistency) and localised physical patches (spatial anomaly detector).

Title

Universal Adversarial Patch Generator with EOT

Filename

adversarial_patch.py

Description

Generates a universal adversarial patch using Expectation over Transformation, optimising the patch over a distribution of positions, scales, and brightness values to survive physical-world variation

Implementation Notes

Python 3.12, single quotes throughout per book convention. Requires: torch, torch.nn.functional. Import ToyLinear from fgsm_attack.py for demo. Patch is a (C, H_patch, W_patch) tensor optimised via Adam. EOT: at each step, sample N_transforms (position, scale, brightness) and average loss. Patch clamped to [0, 1] after each step (valid pixel values required for printing).

Code

# adversarial_patch.py
# Section 10.8: Universal Adversarial Patch with EOT
# 20260524 | AI Security Mastery by Raghav Dinesh
# Single quotes throughout per book convention
# Reference: Brown et al. 2017; Athalye et al. 2018 (EOT)

import torch
import torch.nn as nn
import torch.nn.functional as F
from torch import Tensor
from dataclasses import dataclass
from typing import Tuple
import random


@dataclass
class EOTConfig:
    n_transforms: int = 10        # Number of transformations sampled per step
    scale_min: float = 0.10       # Min patch scale as fraction of image dimension
    scale_max: float = 0.30       # Max patch scale as fraction of image dimension
    brightness_min: float = 0.7   # Min brightness multiplier
    brightness_max: float = 1.3   # Max brightness multiplier
    noise_std: float = 0.04       # Additive colour noise std (printer variation)


def apply_patch_to_batch(
    images: Tensor,
    patch: Tensor,
    row: int,
    col: int,
    ph: int,
    pw: int,
) -> Tensor:
    '''
    Apply patch to a batch of images at position (row, col) with size (ph, pw).
    Resizes patch to (ph, pw) via bilinear interpolation.
    Returns patched batch with same shape as images.
    '''
    patched = images.clone()
    # Resize patch to target size
    patch_resized = F.interpolate(
        patch.unsqueeze(0), size=(ph, pw),
        mode='bilinear', align_corners=False,
    ).squeeze(0)
    # Clamp patch region boundaries to image dimensions
    r_end = min(row + ph, images.size(-2))
    c_end = min(col + pw, images.size(-1))
    patch_crop = patch_resized[:, :r_end - row, :c_end - col]
    patched[:, :, row:r_end, col:c_end] = torch.clamp(patch_crop, 0.0, 1.0)
    return patched


def sample_eot_transform(
    images: Tensor,
    patch: Tensor,
    cfg: EOTConfig,
) -> Tensor:
    '''
    Apply one random EOT transformation to the batch.
    Samples: scale, position, brightness, additive noise.
    '''
    img_h, img_w = images.size(-2), images.size(-1)

    # Random scale
    scale = random.uniform(cfg.scale_min, cfg.scale_max)
    ph = max(2, int(img_h * scale))
    pw = max(2, int(img_w * scale))

    # Random position (ensure patch fits within image)
    row = random.randint(0, max(0, img_h - ph))
    col = random.randint(0, max(0, img_w - pw))

    # Apply patch
    patched = apply_patch_to_batch(images, patch, row, col, ph, pw)

    # Random brightness
    brightness = random.uniform(cfg.brightness_min, cfg.brightness_max)
    patched = torch.clamp(patched * brightness, 0.0, 1.0)

    # Random noise (printer colour variation)
    noise = torch.randn_like(patched) * cfg.noise_std
    patched = torch.clamp(patched + noise, 0.0, 1.0)

    return patched


def generate_patch(
    model: nn.Module,
    images: Tensor,
    y_target: Tensor,
    patch_size: Tuple[int, int] = (8, 8),
    n_steps: int = 100,
    lr: float = 0.05,
    eot_cfg: EOTConfig = None,
) -> Tensor:
    '''
    Generate a universal adversarial patch optimised via EOT.
    Patch optimises: E_{t~T}[J(f(t(A(P, x))), y_target)] over the batch.

    Args:
        model:      PyTorch classifier (eval mode)
        images:     Batch of background images (N, C, H, W); patch will be applied to these
        y_target:   Target class for adversarial misclassification (scalar)
        patch_size: (height, width) of the patch in pixels
        n_steps:    Adam optimisation steps
        lr:         Adam learning rate
        eot_cfg:    EOT configuration; defaults to EOTConfig()
    Returns:
        patch: (C, H_patch, W_patch) tensor, optimised patch, values in [0, 1]
    '''
    if eot_cfg is None:
        eot_cfg = EOTConfig()

    n_channels = images.size(1)
    criterion = nn.CrossEntropyLoss()

    # Initialise patch as random noise
    patch = torch.rand(n_channels, patch_size[0], patch_size[1]).requires_grad_(True)
    optimiser = torch.optim.Adam([patch], lr=lr)

    # Expand target to batch size
    target_batch = y_target.expand(images.size(0))

    for step in range(n_steps):
        optimiser.zero_grad()
        total_loss = torch.tensor(0.0)

        for _ in range(eot_cfg.n_transforms):
            patched = sample_eot_transform(images, patch, eot_cfg)
            logits = model(patched)
            loss = criterion(logits, target_batch)
            total_loss = total_loss + loss

        avg_loss = total_loss / eot_cfg.n_transforms
        avg_loss.backward()
        optimiser.step()

        # Keep patch in valid pixel range (printable constraint)
        with torch.no_grad():
            patch.clamp_(0.0, 1.0)

    return patch.detach()


def patch_attack_success_rate(
    model: nn.Module,
    patch: Tensor,
    images: Tensor,
    y_true: Tensor,
    n_trials: int = 20,
    eot_cfg: EOTConfig = None,
) -> float:
    '''Fraction of (image, transform) pairs where patch causes misclassification.'''
    if eot_cfg is None:
        eot_cfg = EOTConfig()
    total_correct = 0
    total = 0
    with torch.no_grad():
        for _ in range(n_trials):
            patched = sample_eot_transform(images, patch, eot_cfg)
            preds = model(patched).argmax(dim=1)
            total_correct += (preds == y_true).sum().item()
            total += images.size(0)
    return 1.0 - (total_correct / total)


def demo() -> None:
    try:
        from fgsm_attack import ToyLinear
    except ImportError:
        print('Run from directory containing fgsm_attack.py')
        return

    torch.manual_seed(42)
    model = ToyLinear()
    model.eval()

    images = torch.rand(8, 1, 28, 28)
    y_true = torch.randint(0, 10, (8,))
    y_target = torch.tensor([0])

    # Baseline: no patch
    with torch.no_grad():
        clean_preds = model(images).argmax(1)
    clean_acc = (clean_preds == y_true).float().mean().item()

    print('Universal Adversarial Patch with EOT')
    print(f'Clean accuracy (no patch): {clean_acc:.3f}')

    # Generate patch
    eot_cfg = EOTConfig(n_transforms=5, scale_min=0.15, scale_max=0.30)
    patch = generate_patch(model, images, y_target, patch_size=(6, 6),
                           n_steps=50, lr=0.05, eot_cfg=eot_cfg)
    print(f'Patch shape: {tuple(patch.shape)}')

    # Evaluate
    rate = patch_attack_success_rate(model, patch, images, y_true, n_trials=20, eot_cfg=eot_cfg)
    print(f'Patch attack success rate (EOT, {eot_cfg.n_transforms} transforms): {rate:.3f}')


if __name__ == '__main__':
    demo()

Patch Applicator: Position, Scale, and Transformation Sweep

patch_applicator.py

Description

Applies a generated adversarial patch to test images at varied positions, scales, and brightness values; measures attack success across the transformation parameter space

Implementation Notes

Python 3.12, single quotes throughout per book convention. Requires: torch, matplotlib. Import adversarial_patch functions as needed.

Code

# patch_applicator.py
# Section 10.8: Adversarial Patch Applicator and Transformation Sweep
# 20260524 | AI Security Mastery by Raghav Dinesh
# Single quotes throughout per book convention

import torch
import matplotlib.pyplot as plt
import numpy as np
from typing import List
from adversarial_patch import apply_patch_to_batch, generate_patch, EOTConfig


def sweep_scale(
    model,
    patch: torch.Tensor,
    images: torch.Tensor,
    y_true: torch.Tensor,
    scales: List[float],
    fixed_row: int = 0,
    fixed_col: int = 0,
) -> List[float]:
    '''Measure attack success at each patch scale with fixed position.'''
    success_rates = []
    img_h, img_w = images.size(-2), images.size(-1)
    with torch.no_grad():
        for scale in scales:
            ph = max(2, int(img_h * scale))
            pw = max(2, int(img_w * scale))
            row = min(fixed_row, img_h - ph)
            col = min(fixed_col, img_w - pw)
            patched = apply_patch_to_batch(images, patch, row, col, ph, pw)
            preds = model(patched).argmax(dim=1)
            rate = (preds != y_true).float().mean().item()
            success_rates.append(rate)
    return success_rates


def sweep_brightness(
    model,
    patch: torch.Tensor,
    images: torch.Tensor,
    y_true: torch.Tensor,
    brightness_levels: List[float],
    scale: float = 0.25,
) -> List[float]:
    '''Measure attack success at each brightness level (simulates lighting variation).'''
    success_rates = []
    img_h, img_w = images.size(-2), images.size(-1)
    ph, pw = max(2, int(img_h * scale)), max(2, int(img_w * scale))
    with torch.no_grad():
        for b_level in brightness_levels:
            patched = apply_patch_to_batch(images, patch, 0, 0, ph, pw)
            patched = torch.clamp(patched * b_level, 0.0, 1.0)
            preds = model(patched).argmax(dim=1)
            rate = (preds != y_true).float().mean().item()
            success_rates.append(rate)
    return success_rates


def plot_transformation_sweep(
    scales: List[float],
    scale_rates: List[float],
    brightness_levels: List[float],
    brightness_rates: List[float],
    save_path: str = 'patch_transformation_sweep.png',
) -> None:
    fig, (ax1, ax2) = plt.subplots(1, 2, figsize=(12, 5))

    ax1.plot([s * 100 for s in scales], scale_rates,
             color='#e74c3c', linewidth=2, marker='o', markersize=5)

    ax1.set_ylabel('Attack success rate', fontsize=11)
    ax1.set_title('Patch Attack Success vs Scale\n(larger patch = higher success)', fontsize=11)
    ax1.set_ylim(0, 1.05)
    ax1.grid(True, alpha=0.3)

    ax2.plot(brightness_levels, brightness_rates,
             color='#2980b9', linewidth=2, marker='s', markersize=5)
    ax2.set_xlabel('Brightness multiplier (lighting variation)', fontsize=11)

Patch Detector: Regional Spatial Anomaly Analysis

Filename

patch_detector.py

Description

Detects adversarial patches using two complementary approaches: regional texture anomaly analysis (high-frequency content inconsistent with natural image statistics) and masked-region prediction change (masking the patch region restores correct classification)

Implementation Notes

Python 3.12, single quotes throughout per book convention. Requires: torch, torch.nn.functional. Import from adversarial_patch.py for demo. Two detection primitives: texture_anomaly_score (fast, no model forward pass) and masked_region_prediction_change (slower, requires model forward passes per region).

Code

# patch_detector.py
# Section 10.8: Adversarial Patch Detector
# 20260524 | AI Security Mastery by Raghav Dinesh
# Single quotes throughout per book convention

import torch
import torch.nn as nn
import torch.nn.functional as F
from torch import Tensor
from typing import Tuple, List


def local_texture_variance(image: Tensor, window_size: int = 4) -> Tensor:
    '''
    Compute local texture variance in sliding windows.
    High variance in a localised region may indicate adversarial patch.
    Returns a spatial map of same H x W as input.
    '''
    # Compute local mean via average pooling
    padding = window_size // 2
    local_mean = F.avg_pool2d(
        image, kernel_size=window_size, stride=1, padding=padding,
    )
    local_sq_mean = F.avg_pool2d(
        image ** 2, kernel_size=window_size, stride=1, padding=padding,
    )
    local_var = torch.clamp(local_sq_mean - local_mean ** 2, min=0.0)
    # Average across channels
    return local_var.mean(dim=1, keepdim=True)  # (N, 1, H, W)


def texture_anomaly_score(
    image: Tensor,
    threshold: float = 0.05,
    window_size: int = 4,
) -> Tuple[float, Tensor]:
    '''
    Compute texture anomaly score for an image.
    Returns (max_regional_variance, variance_map).
    High max_regional_variance -> possible patch present.
    '''
    var_map = local_texture_variance(image, window_size)
    max_var = var_map.max().item()
    return max_var, var_map


def masked_region_prediction_change(
    model: nn.Module,
    image: Tensor,
    n_masks: int = 16,
    mask_frac: float = 0.25,
    threshold: float = 0.5,
) -> Tuple[bool, List[Tuple[int, int, int, int]]]:
    '''
    Detect adversarial patch by masking image regions and checking prediction change.
    For each candidate region: replace with mean colour, check if prediction changes.
    If prediction changes on a region: that region is a candidate patch location.

    Returns:
        detected: bool (True if any region change exceeds threshold probability)
        flagged_regions: list of (row, col, h, w) for candidate patch regions
    '''
    img_h, img_w = image.size(-2), image.size(-1)
    ph = max(2, int(img_h * mask_frac))
    pw = max(2, int(img_w * mask_frac))
    mean_val = image.mean().item()

    with torch.no_grad():
        base_pred = model(image).argmax(dim=1)
        base_conf = F.softmax(model(image), dim=1).max(dim=1).values

    flagged = []
    step_h = max(1, img_h // 4)
    step_w = max(1, img_w // 4)

    for row in range(0, img_h - ph + 1, step_h):
        for col in range(0, img_w - pw + 1, step_w):
            masked = image.clone()
            masked[:, :, row:row + ph, col:col + pw] = mean_val
            with torch.no_grad():
                masked_pred = model(masked).argmax(dim=1)
            # If prediction changes after masking: region was adversarially important
            if (masked_pred != base_pred).any():
                flagged.append((row, col, ph, pw))

    detected = len(flagged) > 0
    return detected, flagged


def detect_patch(
    model: nn.Module,
    image: Tensor,
    texture_threshold: float = 0.06,
    use_masking: bool = True,
) -> dict:
    '''
    Combined patch detection: texture anomaly + masked region prediction change.
    Returns detection result dict.
    '''
    tex_score, var_map = texture_anomaly_score(image, threshold=texture_threshold)
    texture_flagged = tex_score > texture_threshold

    masking_flagged, flagged_regions = False, []
    if use_masking:
        masking_flagged, flagged_regions = masked_region_prediction_change(
            model, image, n_masks=16, mask_frac=0.25,
        )

    return {
        'texture_score': tex_score,
        'texture_flagged': texture_flagged,
        'masking_flagged': masking_flagged,
        'flagged_regions': flagged_regions,
        'detected': texture_flagged or masking_flagged,
    }

Common Mistakes

Mistake 1

Description

Optimising a patch without EOT and expecting it to work when physically printed and photographed

Why It Happens

EOT adds complexity: it requires multiple forward passes per optimisation step and more configuration parameters. Engineers skip it to simplify the implementation, reasoning that if the patch works in a digital simulation it will work physically.

Consequence

The non-EOT patch is optimised for exactly one configuration: fixed position, fixed scale, flat lighting, no printer colour shift. When printed and photographed with even slight variation in viewing angle or lighting, attack success rate drops from 80-90% to near 0%. The patch is adversarial only at the specific digital configuration it was trained for. Reporting non-EOT patch success rates overstates the real-world threat.

Correct Approach

Always include EOT with at minimum position, scale, and brightness variation in the transformation distribution. The EOTConfig dataclass in adversarial_patch.py provides sensible defaults. For 3D objects add rotation/perspective transforms. Never report physical attack success rates from digital-only patches -- benchmark robustness using physical_robustness_benchmark.py which tests across transformation severity levels.

Mistake 2

Description

Not clamping the patch tensor to [0, 1] after each optimisation step, producing physically unrealisable pixel values

Why It Happens

Adam updates the patch parameters without any constraint. Engineers implement the optimisation loop and forget that unclamped patch values outside [0, 1] cannot be represented by a printer or screen. The optimisation succeeds in digital simulation but the physical patch cannot reproduce values outside the valid range.

Consequence

The patch contains pixel values < 0 (cannot print as black) and > 1 (cannot print as white on a standard display). When the patch is clipped to [0, 1] for printing, the attack success rate drops significantly because the out-of-range values carried the adversarial signal. The benchmark in digital simulation overestimates the actual printed patch effectiveness.

Correct Approach

Add patch.clamp_(0.0, 1.0) inside torch.no_grad() immediately after each optimiser step. This is implemented in the generate_patch function in adversarial_patch.py. Clamp AFTER the Adam step, not before: clamping before the step removes gradient signal from boundary pixels. The correct order is: step(), then clamp_().

Mistake 3

Description

Applying per-pixel feature squeezing as the sole Track 7 detection primitive for physical adversarial patches

Why It Happens

Feature squeezing (Section 10.11) is presented as the primary Track 7 input-side primitive. Engineers configure it as the universal adversarial detection layer and do not add a separate patch detection primitive, assuming squeezing handles all adversarial input types.

Consequence

Per-pixel feature squeezing applies a transformation (Gaussian blur, bit-depth reduction) uniformly across the entire image. An adversarial patch in a localised region is partially smoothed, but the patch gradient is concentrated in a small area -- the squeezer reduces it less effectively than it reduces distributed per-pixel noise. Patch attack success rates after squeezing remain 40-70%, much higher than squeezing''s effectiveness against FGSM and PGD.

Correct Approach

Add regional spatial anomaly detection (patch_detector.py) as a separate Track 7 spatial primitive alongside the per-pixel squeezer. The two are complementary: squeezer catches distributed digital noise; the spatial detector catches localised patch anomalies. The Section 10.13 gateway includes both as part of Track 7''s pre-inference detection stage.

Mistake 4

Description

Treating adversarial patches as a digital attack problem and applying the same threat model as FGSM/PGD

Why It Happens

Physical adversarial patches are sometimes described as "adversarial examples applied to physical objects." Engineers map this to the digital adversarial example framework: the patch is just a localised pixel perturbation, Track 7 handles pixel perturbations, therefore Track 7 handles patches.

Consequence

The threat model mismatch causes defenders to focus detection resources on the API boundary (query patterns, input distribution shifts) rather than the sensor boundary (regional image anomalies, sensor fusion). Physical attack adversaries bypass the API entirely; API-focused detection misses them completely. The production deployment remains undefended against physical patches while digital adversarial detection resources are well-covered.

Correct Approach

Maintain separate threat model entries for physical and digital adversarial attacks. Physical attacks require: sensor-stage detection (regional anomaly analysis at the image processing stage), sensor fusion (supplemental non-optical sensors), and physical environment controls (inspection, tamper detection). Digital attack detection (Track 7 squeezer/consistency) is a distinct layer. The physical_threat_model.py deliverable provides the framework for separating these threat entries.

Mistake 5

Description

Using a patch size much smaller than necessary, producing a patch that is imperceptible but ineffective

Why It Happens

Engineers trying to make patches "stealthy" choose very small patch sizes (e.g., 2% of image width) that are visually inconspicuous. The patch occupies few pixels and cannot dominate the classifier''s decision over the background image.

Consequence

Universal adversarial patches require enough spatial extent to override the background image content in the model''s feature representations. Too-small patches produce attack success rates near random chance. The optimisation loss decreases (the patch learns something), but the patch effect is insufficient to reliably flip the classification. Stealthiness and effectiveness are in direct tension for universal patches.

Correct Approach

Set patch size to at minimum 10-15% of the image dimension for reliable universal attack success on standard classifiers. Test success rate vs scale using patch_applicator.py before finalising patch size. The realistic physical threat (sticker on a stop sign, pattern on clothing) is typically large enough to be practical -- stop sign stickers in the Eykholt et al. attack were clearly visible as markings even if not obviously adversarial to humans.

Section Summary

Compact

Physical adversarial attacks apply perturbations to the real world before the sensor -- patches, stickers, and 3D objects that fool deployed vision systems without API access. Adversarial patches (Brown et al. 2017) are universal: one printed patch causes any background image to be misclassified as a target class. Expectation over Transformation (EOT) is essential for physical deployment: optimising over distributions of position, scale, brightness, and noise makes the patch robust to real-world viewing variation. Stop sign attacks (Eykholt et al. 2018) and 3D adversarial objects (Athalye et al. 2018) are documented successful physical attacks against production-grade detectors. Patch detection requires regional spatial anomaly analysis (localised texture anomalies) and masked-region prediction change -- distinct from the per-pixel squeezer effective against digital noise. ATLAS AML.T0043 covers adversarial patches.

Key Takeaways

  • Physical attacks bypass the API entirely: the adversary perturbs the physical world before the sensor; no query budget required
  • EOT is not optional for physical deployment: non-EOT patches fail in the real world; optimise over position, scale, brightness, and noise
  • Universal patches are the dominant threat: one patch works on any background; the adversary deploys once and affects all images
  • Patch detection requires regional analysis (spatial anomaly) not per-pixel squeezing -- the two are complementary, not interchangeable
  • ATLAS AML.T0043; four production systems exposed: autonomous vehicles, facial recognition, surveillance, industrial inspection
  • Sensor fusion is the most robust mitigation: optical patches do not affect LIDAR, radar, X-ray, or IR sensors

Summary

Section 10.9 translates the adversarial example framework from continuous pixel space to discrete token space. L-norm constraints do not apply to tokenised text; the analogues are token edit distance (number of substitutions) and semantic similarity (cosine distance between sentence embeddings). TextFooler (Jin et al. 2020) uses greedy word substitution with semantic similarity constraints and a POS filter to produce semantically valid adversarial text. BERT-Attack (Li et al. 2020) uses a masked language model to propose contextually appropriate substitutions. Universal adversarial triggers (Wallace et al. 2019) are fixed token sequences that, appended to any input, universally cause LLM safety classifier misclassification -- the text analogue of the universal adversarial patch in Section 10.8. Section 10.9 closes the loop between automated adversarial attacks and the human jailbreak techniques from Chapter 7.
