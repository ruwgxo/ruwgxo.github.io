Adversarial Example Taxonomy: Goals, Constraints, and Detection Signals

Section Overview

One Line Summary

The complete adversarial taxonomy maps four attack goals across three access tiers and four input modalities, and assigns each cell a canonical technique and a Track 7 detection primitive.

Why This Section Exists

Section 10.1 established the threat model shift from extraction to evasion. Section 10.2 formalises that shift into a complete operational taxonomy. The taxonomy has three axes: attack goal (what wrong output the adversary wants), access tier (what information they have), and input modality (what type of data they are perturbing). Each combination maps to a canonical technique covered in Sections 10.3-10.9 and to one or more Track 7 detection primitives from Sections 10.11-10.12. The taxonomy is the scaffold for the rest of the chapter and the operational reference the Section 10.13 gateway uses to route alerts.

Position In Chapter

Section 10.2 is the classification layer between the threat model (Section 10.1) and the individual attack implementations (Sections 10.3-10.9). Every attack section occupies one or more cells in this taxonomy. Every detection primitive in Sections 10.11-10.12 covers one or more cells. Building the taxonomy here means each subsequent section can anchor itself precisely without re-establishing context.

  • Section 10.1: evasion threat model, Lp norm constraints, adversary access ladder, Track 7 pre-inference architecture
  • Section 9.2: extraction taxonomy (parallel structure; shared access tier framing)
  • Section 9.10: detection primitive library (five Ch9 primitives; Track 7 extends the same pattern)

Prose Content

Part 1

Title

Why Classification Before Implementation

Body

Every threat catalogue needs a classification layer before an implementation layer. Without it, defences get designed against individual named attacks rather than against the underlying structural properties that make attacks work. A defence that blocks FGSM but not PGD, or catches image attacks but not tabular attacks, is a defence built against the name, not the threat class. The adversarial ML literature has produced dozens of named attacks since Szegedy et al. first demonstrated adversarial examples in 2013. FGSM, IFGSM, PGD, C&W, DeepFool, Boundary Attack, NES, SPSA, HopSkipJump, Square Attack, TextFooler, HotFlip, BERT-Attack, Universal Adversarial Triggers -- each has its own paper, implementation, and benchmark. A practitioner confronting this list faces a combinatorial problem: which attacks should Track 7 defend against, and in what order? The taxonomy reduces that combinatorial problem to a structured question. A given production deployment has a specific input modality (image, text, tabular), a specific adversary access tier (the API configuration determines what information an adversary receives), and a specific set of attack goals the adversary has operational motivation to pursue. The taxonomy maps directly to the intersection of those three axes. A deployment with a hard-label text classification API, where the adversary wants untargeted evasion of a content moderation system, has a well-defined taxonomy cell -- and that cell maps to a specific set of attack families and a specific Track 7 configuration. Section 10.2 also makes the detection gap explicit. Not every taxonomy cell has full Track 7 coverage. Some attack goal × tier × modality combinations are harder to detect than others. Making that explicit is more useful than claiming coverage that does not exist.

Part 2

Title

Four Attack Goals: Extending Targeted and Untargeted to the Full Goal Space

Body

Section 10.1 introduced targeted and untargeted misclassification as the primary goal axis. Two additional goals complete the formal taxonomy and are operationally important for production security systems. Goal 1 -- Untargeted misclassification: the adversary perturbs x such that argmax f(x_adv) != y_true. Any wrong class is acceptable. This is the most common goal in academic adversarial ML benchmarks and the easier optimisation problem. For security deployments, untargeted evasion is sufficient when the downstream control fires on any positive classification (malware detected, fraud flagged, content blocked) -- any evasion of the positive class is operationally meaningful. Goal 2 -- Targeted misclassification: the adversary perturbs x such that argmax f(x_adv) = y_target where y_target is a specific adversary-chosen class. This is harder to achieve (tighter optimisation constraint) but more dangerous to defend against (forces a specific operational decision). Targeted evasion suppresses all downstream controls that depend on the specific classification output: a fraud transaction classified as a specific trusted merchant pattern, a malware binary classified as a specific signed system file hash. Goal 3 -- Confidence reduction: the adversary perturbs x such that the model''s confidence in any class falls below an operational threshold, without necessarily changing the argmax class. This goal is relevant against systems that use calibrated confidence scores for downstream routing (send low-confidence predictions to human review, high-confidence to automated action). By reducing confidence, the adversary shifts decisions from automated processing to lower-scrutiny human queues. The perturbation budget is often smaller than for outright misclassification because the objective is softer. Goal 4 -- Detection evasion: the adversary crafts x_adv to fool the primary classifier (goal 1 or 2) while simultaneously evading Track 7''s adversarial detector. This is the adaptive adversary goal -- the adversary knows Track 7 exists and optimises against it. An adversarial example that evades feature squeezing, consistency checking, and the adversarial classifier simultaneously requires a more constrained optimisation, typically resulting in larger perturbation or lower attack success rate. Detection evasion is the goal that motivates the three-primitive Track 7 ensemble: each primitive is harder to jointly evade than any single primitive alone.

Part 3

Title

Access Tier Taxonomy: Four Tiers Including Physical

Body

Section 10.1 covered three API-level access tiers. Section 10.2 adds the physical tier, which is qualitatively different and expands the threat surface beyond the API entirely. The three API tiers (white-box, grey-box, black-box) were defined in Section 10.1 with query budget implications. The key addition here is the relationship between tiers and attack goal feasibility. Not all tier × goal combinations are equally achievable. Targeted misclassification under black-box access (hard-label only) is orders of magnitude harder than under white-box access: the adversary has no gradient information to guide the optimisation toward the target class. The Boundary Attack can achieve untargeted black-box evasion efficiently, but targeted black-box evasion typically requires the adversary to have a surrogate model (elevating from black-box to transfer tier) or to use more expensive decision-based targeted attack variants. The physical tier describes adversaries who cannot query the API at all but interact with the physical environment sensed by the system. A stop sign attacked with stickers (Section 10.8), a face with adversarial glasses frames, a surface painted with an adversarial pattern -- these attacks bypass the API entirely. The physical tier maps to Goal 1 (untargeted, most common: cause any misclassification) and Goal 2 (targeted, harder: force a specific wrong class such as misidentifying a person as a known identity). Physical attacks require expectation-over- transformation optimisation because the perturbation must survive variation in viewing angle, lighting, and distance. Section 10.8 covers the complete physical attack threat model. The transfer tier -- introduced in Section 10.1 as the Chapter 9 elevation path -- fits between grey-box and white-box in terms of attack capability: the adversary has white-box access to a surrogate but only limited access to the victim. Transfer tier attacks can achieve all four goals against the surrogate; whether those goals transfer to the victim depends on how closely the surrogate matches the victim. This is why Section 9.4 distillation quality directly determines Chapter 10 transfer attack power.

Part 4

Title

Input Modality Dimension: Why the Attack Problem Changes Across Domains

Body

The input modality dimension is where the formal Lp norm framework either applies directly or requires domain-specific adaptation. Image inputs live in a continuous space where Lp norms are natural perturbation metrics. Each pixel is a continuous value in [0, 255]; perturbing a pixel by delta_i is a well-defined real-valued operation. The gradient of the loss with respect to pixel values is computable via backpropagation. This makes images the canonical domain for adversarial ML research: FGSM, PGD, and C&W all operate most cleanly here. The perceptibility constraint (human eyes cannot detect small per-pixel changes at low epsilon) maps naturally to the L-infinity ball. Text inputs are discrete. A token is an integer index into a vocabulary -- not a continuous value. Perturbing token i by a real-valued delta_i produces a value that does not correspond to any valid token. The gradient of the loss with respect to token indices is not meaningful in the same way. The adversarial text literature has developed two workarounds: operating in embedding space (treat embeddings as continuous, optimise there, then project back to the nearest valid token) or using combinatorial search (try all single-token substitutions, greedy or beam). HotFlip (Section 10.9) uses the Jacobian of the loss with respect to a one-hot token indicator to identify which character flip most reduces confidence, operating in a continuous relaxation of the discrete space. TextFooler (Section 10.9) uses a fully discrete search with semantic similarity constraints. Neither approach admits a clean Lp bound; token edit distance (the number of substitutions) and semantic similarity (cosine distance between sentence embeddings) are the relevant constraints. Tabular inputs are mixed: some features are continuous (amount, duration, count) where Lp norms apply; some are categorical (merchant category, country code, payment method) where they do not. The physically realisable constraint is typically more restrictive than any Lp ball: a transaction cannot freely combine any feature values -- the adversary is limited to changes they can actually execute (changing the amount within a range, choosing among available merchant categories). Production adversarial attacks against fraud scoring systems typically use constrained optimisation over the continuous features with categorical features enumerated by search. Audio inputs share the continuous-space property with images but have frequency-domain structure that matters for perceptibility. Psychoacoustic models define what modifications are inaudible to humans, analogous to visual perceptibility constraints for images. Section 10.2 does not develop audio attacks in depth; the Chapter 10 attack sections (10.3-10.9) focus on images and text as the two highest-production-risk modalities.

Part 5

Title

Budget-Success Tradeoff: The Operational Space Where Attacks Live

Body

The budget-success tradeoff curve describes how attack success rate varies with perturbation magnitude (epsilon) for a given attack method and norm. This curve has a characteristic shape: near zero at small epsilon, rising steeply through a transition region, plateauing near 100% at large epsilon. The location and slope of the transition region is what determines where production attacks operate. For L-infinity attacks on image classifiers, empirical benchmarks (CIFAR-10, ResNet family) show characteristic behaviour. FGSM achieves roughly 30% untargeted attack success at epsilon=4/255, rising to 60% at 8/255 and plateauing near 90% at 16/255. PGD (40 steps) achieves 65% at 4/255, rising to 95% at 8/255. C&W L2 operates at a different epsilon scale (L2 distance rather than L-infinity); minimum-norm C&W finds adversarial examples at L2 distances typically below 1.0 for ResNet on CIFAR-10. The security-critical insight from this curve is the detectability-success joint distribution. High epsilon produces high attack success rates -- but large perturbations are more detectable by feature squeezing (Section 10.11), which reduces precision in the input and is most effective against fine-grained perturbations. Low epsilon produces lower attack success rates but smaller perturbations that survive feature squeezing with less prediction change. Production adversaries operate in the transition region: enough epsilon to achieve reliable attack success, small enough to stay below detection thresholds. Finding that region is itself an optimisation problem, which is why the Section 10.11 squeezer calibration must be done at the epsilon values where attack success rates are non-trivial, not at extreme epsilon values. For targeted attacks, the success-epsilon curve shifts right and down relative to untargeted attacks at matched epsilon: targeted attacks require larger perturbations to achieve the same success rate because the optimisation constraint is tighter. At the epsilon values where untargeted attacks achieve 95% success, targeted attacks may achieve only 40-60%. This trade- off means targeted attackers typically need larger perturbations, which are more detectable -- the defender is in a slightly better position against targeted attacks at matched detection thresholds.

Part 6

Title

Detectability Analysis: Goal-to-Detection-Signal Mapping

Body

Track 7 has three detection primitives, each with different coverage across the taxonomy cells. Understanding which primitive covers which cell is the design specification for the Section 10.13 gateway. Feature squeezing (Section 10.11) detects adversarial examples through their sensitivity to input transformation. The detection signal is: original prediction P(y|x) disagrees with transformed prediction P(y|squeezer(x)) by more than threshold tau. This works because adversarial perturbations are precisely calibrated to the victim model -- small input transformations (Gaussian blur, bit-depth reduction, JPEG compression) destroy the calibration and restore the correct classification, while natural images are robust to the same transformations. Coverage: best against L-infinity FGSM and PGD; weaker against C&W (which finds minimum-norm adversarial examples that may survive squeezing) and against attacks that optimise through the squeezer (adaptive attacks). Consistency checking (Section 10.12) detects adversarial examples through prediction instability under random perturbation. The detection signal is: N randomly perturbed variants of x produce a distribution of predictions inconsistent with the original. This works because adversarial examples are typically fragile -- they exist in narrow regions of input space near decision boundaries, and small random perturbations push them back to correctly classified regions. Coverage: best against FGSM (single-step, sits precisely on boundary) and boundary attacks (by construction near boundary); weaker against C&W with high confidence parameter kappa (which specifically optimises for a large margin, making the adversarial example robust to small perturbations). The adversarial detector classifier (Section 10.12) detects adversarial examples through learned pattern recognition. It is a binary classifier trained on adversarial and natural examples from multiple attack families. Coverage: generalises across attack families seen in training; degrades on novel attack families not represented in training data. The detection evasion goal (Goal 4) specifically targets this primitive -- an adversary who can query the adversarial detector may be able to craft examples that fool both the primary classifier and the adversarial classifier. The three-primitive ensemble (Section 10.13) provides meaningful resistance against Goal 4 (detection evasion) because jointly evading all three primitives is a harder optimisation problem than evading any one. A detection-evasion adversary must craft an example that: (a) survives squeezing without restoring correct classification, (b) is stable under random perturbation, and (c) falls outside the distribution the adversarial classifier was trained on. Achieving all three simultaneously requires larger perturbation budgets or higher query counts than single-primitive evasion.

Part 7

Title

Defender Decision Tree: Classifying Evasion Attempts from Observable Signals

Body

The defender decision tree converts observable signals into a taxonomy classification. In production, defenders do not observe attacks directly -- they observe API inputs, model outputs, and Track 7 detector signals. The decision tree maps those observations to the most likely attack goal, access tier, and modality. Signal 1: input modality. The modality is directly observable -- the input is an image, a text string, a feature vector, or an audio sample. This immediately constrains the applicable attack families and the relevant perturbation constraints. Signal 2: query pattern. Does the request arrive as an isolated submission, or is it part of an anomalous query pattern detected by Track 6? If Track 6 fired, the adversary was running a query-based attack (grey-box or black-box) requiring a campaign footprint. A single isolated submission with no query pattern signal suggests white-box access or a transfer attack. Signal 3: feature squeezer disagreement magnitude. A large disagreement (original prediction changes substantially under squeezing) suggests an L-infinity or L2 attack with a detectable perturbation. A small or zero disagreement suggests either a natural input or an adaptive attack that survives squeezing (C&W style, or deliberate optimisation through the squeezer). Signal 4: consistency check result. Prediction instability under random perturbation (consistency check fires) suggests the adversarial example is near the decision boundary -- consistent with FGSM, untargeted PGD, or boundary attacks. A stable prediction despite Track 7 squeezer signal suggests C&W with high kappa (produces robust adversarial examples intentionally far from the boundary). Signal 5: primary model output class. Is the output the most likely wrong class (suggesting untargeted), a specific suspiciously plausible class (suggesting targeted), or an unusually low-confidence correct class (suggesting confidence reduction)? This signal is not conclusive alone but in combination with signals 3 and 4 narrows the goal classification. The operational value of the decision tree is that it gives the analyst a classification in under 60 seconds from the available signals, which informs the incident response (is this a one-off targeted attack or an ongoing campaign?) and the detection tuning priority (which Track 7 primitive needs recalibration based on the attack class observed?).

def query(
    goal: Optional[str] = None,
    tier: Optional[str] = None,
    modality: Optional[str] = None,
) -> List[TaxonomyCell]:
    result = TAXONOMY
    if goal:
        result = [c for c in result if c.goal == goal]
    if tier:
        result = [c for c in result if c.tier == tier]
    if modality:
        result = [c for c in result if c.modality == modality]
    return result

@dataclass

    name: str
    norm: str
    success_fn: Callable[[np.ndarray], np.ndarray]

def logistic_curve(
    x: np.ndarray,
    midpoint: float,
    steepness: float,
    ceiling: float = 0.97,
) -> np.ndarray:
    return ceiling / (1.0 + np.exp(-steepness * (x - midpoint)))

        name='PGD-40 (L-inf)',

@dataclass
class EvasionSignals:
    modality: str                      # 'image', 'text', 'tabular', 'audio'
    query_pattern_fired: bool          # Track 6 fired (extraction campaign detected)
    squeezer_disagreement: float       # 0.0 = no change; 1.0 = complete flip
    squeezer_disagreement_threshold: float = 0.20
    consistency_check_fired: bool = False
    consistency_instability_score: float = 0.0

    likely_goal: str
    likely_tier: str
    confidence: str
    canonical_technique: str
    recommended_primitive: str
    rationale: str


def classify_evasion(signals: EvasionSignals) -> EvasionClassification:
    # Step 1: Determine access tier from query pattern
    if signals.query_pattern_fired:
        tier = 'grey_or_black_box_campaign'
    else:
        tier = 'white_box_or_transfer'

    # Step 2: Determine goal from output signals
    if signals.output_confidence is not None and signals.output_confidence < 0.40:
        goal = 'confidence_reduction'
        technique = 'Low-epsilon FGSM or C&W kappa=0'
        primitive = 'Output entropy monitor + feature squeezing'
    elif signals.output_class_suspicious:
        goal = 'targeted'
        technique = 'PGD targeted or C&W L2 high-kappa'
        primitive = 'Adversarial classifier (primary) + consistency checker'
    else:
        goal = 'untargeted'
        technique = 'FGSM or PGD (white-box); Boundary Attack (black-box)'
        primitive = 'Feature squeezing (primary) + consistency checker'

    # Step 3: Refine tier estimate from squeezer and consistency signals
    large_squeezer = signals.squeezer_disagreement > signals.squeezer_disagreement_threshold
    if large_squeezer and not signals.consistency_check_fired:
        tier_refined = 'white_box_fgsm_or_pgd'
        conf = 'moderate'
    elif not large_squeezer and signals.consistency_check_fired:
        tier_refined = 'near_boundary_black_box'
        conf = 'moderate'
    elif large_squeezer and signals.consistency_check_fired:
        tier_refined = 'white_box_low_iterations'
        conf = 'low'
    elif not large_squeezer and not signals.consistency_check_fired:
        tier_refined = 'cw_high_kappa_or_transfer_or_natural'
        conf = 'low'
    else:
        tier_refined = tier
        conf = 'low'

    # Step 4: Modality-specific override
    if signals.modality == 'text':
        primitive = 'Semantic consistency check (back-translation) + adversarial classifier'
        technique = 'TextFooler or HotFlip (if white-box)'

        f'Modality={signals.modality}, '
        f'track6={signals.query_pattern_fired}, '
        f'squeezer_disagreement={signals.squeezer_disagreement:.2f}, '
        f'consistency_fired={signals.consistency_check_fired}, '
        f'conf={signals.output_confidence}'
    )

    return EvasionClassification(
        likely_goal=goal,
        likely_tier=tier_refined,
        confidence=conf,
        canonical_technique=technique,
        recommended_primitive=primitive,
        rationale=rationale,

Common Mistakes

Mistake 1

Description

Using the taxonomy as a checklist rather than as a filter -- defending all cells rather than the cells relevant to the deployment

Why It Happens

The full taxonomy matrix has 4 goals x 4 tiers x 4 modalities = 64 potential cells. Engineers see the complete matrix and conclude they must defend against all cells. Track 7 gets configured with maximum primitives regardless of which cells the actual deployment is exposed to.

Consequence

Over-broad Track 7 configuration adds unnecessary latency (more squeezers, more consistency check variants) and raises false positive rate for non-applicable attack classes. A text-only deployment running image squeezers gets no security benefit and measurable latency cost.

Correct Approach

Filter the taxonomy to the cells that apply: determine the deployment modality, the realistic adversary access tier (based on API configuration), and the attack goals that adversaries have operational motivation to pursue. Configure Track 7 for those cells only. The taxonomy is a filter, not a checklist.

Mistake 2

Description

Treating confidence reduction (Goal 3) as undetectable because it does not change the argmax class

Why It Happens

Evaluation metrics for adversarial robustness focus on accuracy (does the argmax class change?). Confidence reduction that does not change argmax does not appear in standard adversarial robustness benchmarks and gets treated as a non-event.

Consequence

Systems that route low-confidence predictions to lower-scrutiny processing (human review queues, secondary classifiers) are bypassed by confidence reduction attacks without any alert. The adversary achieves a routing bypass without triggering any accuracy-based detection threshold.

Correct Approach

Monitor output probability distributions, not just argmax accuracy. The output entropy monitor from Section 9.10 applies here: flag requests whose output probability distribution is unusually flat relative to baseline. This requires soft-label output exposure -- if the API returns hard labels only, acknowledge Goal 3 as a coverage gap.

Mistake 3

Description

Configuring the adversarial detector classifier once and not retraining as new attack families emerge

Why It Happens

The adversarial detector classifier is trained on a fixed dataset of adversarial and natural examples. Once deployed, retraining cycles are expensive and the model performs well against known attack families, reducing urgency for retraining.

Consequence

Novel attack families not represented in training data are systematically underdetected. An adversary using a recently published attack method (or a custom variant) bypasses the adversarial classifier while being caught by the ensemble only to the extent that the squeezer and consistency checker cover that attack class independently.

Correct Approach

Treat the adversarial detector classifier as a model requiring active maintenance: retrain quarterly with adversarial examples generated from recently published attack methods. The classifier is the highest-coverage primitive but the most brittle to distribution shift in the attack family space.

Mistake 4

Description

Concluding from a high ensemble detection rate on CIFAR-10 benchmarks that production detection rates will match

Why It Happens

CIFAR-10 is the standard benchmark for adversarial ML research. Engineers validate Track 7 against CIFAR-10 adversarial examples, achieve 85-92% detection rates, and treat that as the production detection rate estimate.

Consequence

Production inputs are not CIFAR-10 images. Different input distributions, higher-dimensional feature spaces, domain-specific perturbation constraints, and adversaries who adapt to the specific deployed model all reduce detection rates relative to the benchmark. The production false negative rate is typically higher than benchmark false negative rate.

Correct Approach

Calibrate Track 7 detection thresholds against production-representative inputs, not benchmark inputs. Generate adversarial examples against the specific deployed model (or a recent distillation surrogate) using FGSM, PGD, and C&W. Use the Section 10.13 calibration harness. Treat benchmark numbers as upper bounds, not production estimates.

Mistake 5

Description

Ignoring the budget-success transition region and calibrating detection thresholds at extreme epsilon values

Why It Happens

Feature squeezer and consistency checker thresholds are easy to set at extreme epsilon: large-epsilon adversarial examples are obviously detectable. Calibration at extreme epsilon gives high detection rates with low false positives and produces a clean-looking ROC curve.

Consequence

The thresholds are too high to catch attacks in the transition region (moderate epsilon, high attack success, moderate perturbation). Production attacks do not use extreme epsilon -- they use the minimum epsilon for reliable attack success, which is in the transition region. The calibrated detector misses exactly the attacks most likely to appear in production.

Correct Approach

Calibrate Track 7 thresholds specifically at the epsilon values where attack success exceeds 50% -- the transition region. Use the budget_success_tradeoff.py curves from this section to identify that region, then calibrate squeezer disagreement thresholds and consistency check instability thresholds against adversarial examples generated at those epsilon values.

Section Summary

Compact

Section 10.2 formalises the Chapter 10 threat model into a three-axis taxonomy: four attack goals (untargeted, targeted, confidence reduction, detection evasion) by four access tiers (white-box, grey-box, black-box, physical/transfer) by four input modalities (image, text, tabular, audio). Each cell maps to a canonical technique covered in Sections 10.3-10.9 and to one or more Track 7 detection primitives. The detectability spectrum shows that no single primitive covers all cells: feature squeezing catches L-infinity attacks, consistency checking catches boundary-proximate attacks, and the adversarial classifier catches trained patterns but degrades on novel families. The three-primitive ensemble provides meaningful resistance against detection evasion (Goal 4). The defender decision tree converts observable signals into a taxonomy classification in under 60 seconds, enabling rapid incident triage and detection tuning priority decisions.

Key Takeaways

  • Four goals, not two: confidence reduction and detection evasion extend the threat model beyond targeted/untargeted and require distinct detection primitives
  • The budget-success transition region is where production attacks live: moderate epsilon, high success rate, moderate detectability
  • No single Track 7 primitive covers the full taxonomy: the ensemble is required for meaningful coverage, especially against Goal 4 (detection evasion)
  • Text modality breaks the image Lp framework: semantic consistency check replaces feature squeezing for text adversarial detection
  • The adversarial detector classifier is the highest-coverage primitive but the most brittle to novel attack families -- active retraining is required
  • The taxonomy is a filter for Track 7 configuration: defend the cells that apply to the deployment, not all 64 potential cells

Section 10.3: FGSM -- Fast Gradient Sign Method

Summary

Section 10.3 implements the foundational white-box adversarial attack: FGSM (Goodfellow et al. 2014). The algorithm is x_adv = x + epsilon * sign(nabla_x J(theta, x, y)) -- one forward- backward pass, exact L-infinity perturbation. The section covers the epsilon sweep (attack success rate across perturbation budgets, grounding the Section 10.2 curves in implementation), targeted vs untargeted FGSM (gradient reversal for targeted misclassification), transferability of FGSM adversarial examples to surrogate-matched victim models, and FGSM as a data augmentation primitive for adversarial training (Section 10.15 preview). FGSM occupies the white-box / untargeted / image cell of the taxonomy matrix and sets the gradient-sign primitive that PGD and C&W extend iteratively.
