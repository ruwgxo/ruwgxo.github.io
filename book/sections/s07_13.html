Jailbreak Catalog: 50+ Techniques Organised by Family and Detection Difficulty

Catalog Design

Purpose

This catalog is the structured reference artifact for Chapter 7. Every detection feature in Section 7.14 maps back to at least one catalog entry. Detection difficulty ratings drive detection investment priority order. The catalog is also the primary input to the automated generator in Section 7.12 -- positive examples for classifier training.

Schema Per Entry

technique_id: JB-[family_code]-[sequence] family: one of eight families name: short human-readable name section_reference: section where mechanism is explained in depth atlas: ATLAS technique ID (AML.T0051 or AML.T0054) owasp: always LLM01 detection_difficulty: 1 (trivial) to 5 (very hard) fpr_risk: very_low / low / medium / high primary_detection_signal: the signal that catches it primary_detector: which Section 7.14 track handles it example_structure: paraphrased structural description (not a reproduction of any specific adversarial prompt) composed_with: families this technique is commonly combined with notes: any special detection or operational notes

Detection Difficulty Scale

1

Trivial -- keyword match or near-trivial pattern. Very low FPR.

2

Easy -- lexical pattern with low FPR. No semantic understanding needed.

3

Moderate -- requires semantic understanding or session state.

4

Hard -- high FPR risk or requires embedding-level analysis.

5

Very hard -- stateful multi-session or gradient-level analysis required.

Usage Note

Fifty-plus techniques is a representative sample covering the detection signal space, not a comprehensive enumeration. New techniques appear continuously. The catalog maintenance process (Section 7.13.3 in code) defines how to add new entries without breaking classifier training.

Content

Opening

The preceding sections covered nine attack families in depth. This section organises all of them into a single structured reference: 61 techniques across 8 families, each with ATLAS mapping, detection difficulty rating, primary detection signal, and responsible structural description. The catalog serves three operational roles. First, it is the positive example set for training the semantic classifier in Section 7.14 -- each entry's primary_detection_signal is a feature the classifier must recognise. Second, the detection difficulty ratings define the investment priority order for ensemble threshold calibration after Section 7.12's success rate analysis. Third, it is the standing reference that persists beyond this book -- a living document updated as new techniques emerge. Technique descriptions in this catalog are structural paraphrases. They describe what the technique does and what it looks like without reproducing specific adversarial prompts. This preserves the operational value of the catalog for defenders while preventing the catalog itself from functioning as an attack toolkit.

Number

7.13.1

Title

Family 1: Persona and Roleplay (8 techniques)

Body

Techniques that establish a persona, character, or operational mode for the model to inhabit, bypassing alignment by shifting the model's effective identity. Mechanism: Section 7.3. ATLAS: AML.T0054. JB-PR-01 through JB-PR-08 cover: Direct DAN assertion, DAN dual-output format, DAN token-budget threat, Named variant (non-DAN name), Developer mode claim, Evil mode claim, Custom persona with distributed restriction removal, and Nested roleplay at depth 2+. Detection difficulty ranges from 1 (DAN direct assertion -- keyword detectable) to 4 (custom persona with distributed claims -- requires full-prompt semantic embedding). The persona family is the highest- prevalence family in deployed attack traffic.

Number

7.13.2

Title

Family 2: Fictional and Hypothetical Framing (8 techniques)

Body

Techniques that embed harmful requests within fictional, hypothetical, or academic frames to shift the model into a creative-assistance distribution region. Mechanism: Section 7.4. ATLAS: AML.T0054. JB-FF-01 through JB-FF-08 cover: Closed hypothetical scenario, Open hypothetical world-state, Academic thought experiment, Story completion (single-turn), Research and educational pretext, Counterfactual alternate- universe framing, Third-party character attribution, and Layered framing (3+ simultaneous frame types). Detection difficulty ranges from 2 (counterfactual -- distinctive syntax) to 4 (research pretext -- high FPR from legitimate overlap). The two-axis detection approach (framing type + operational specificity) is the required architecture for this family.

Number

7.13.3

Title

Family 3: Context Manipulation (7 techniques)

Body

Multi-turn techniques that engineer the conversational frame across turns to lower the model's refusal threshold before a capability request arrives. Mechanism: Section 7.5. ATLAS: AML.T0054. All require stateful detection. JB-CM-01 through JB-CM-07 cover: Norm establishment chain, Fiction gradient escalation (5+ turns), Fiction gradient escalation (10+ turns), Established universe exploitation, Agreement stacking (3-step chain), Authority framing with rapport building, and Cross-turn context poisoning (generic multi-turn frame manipulation). All context manipulation techniques have detection difficulty 3-4. The session_state_schema from Section 7.5 is the detection foundation. Single-turn classifiers are structurally blind to this family.

Number

7.13.4

Title

Family 4: Instruction Hierarchy (7 techniques)

Body

Techniques targeting the instruction layer by claiming override authority over the system prompt. Bridge between injection and jailbreak families. Mechanism: Section 7.6. ATLAS: AML.T0051 and AML.T0054. JB-IH-01 through JB-IH-07 cover: Direct user-turn override, Administrative permission claim, Developer/elevated mode claim, System prompt extraction attempt, Conflicting instruction injection, Formatting-based priority manipulation (markdown headers), and Targeted override post-extraction. Detection difficulty ranges from 1 (direct override -- canonical pattern) to 3 (conflicting instruction -- overlaps with legitimate edge cases). The privilege_escalation_patterns.py from Section 7.6 covers this family.

7.13.5

Title

Family 5: Multi-Step and Erosion (7 techniques)

Body

Techniques that advance request content or frame across multiple turns, exploiting consistency to prevent reversal. Mechanism: Section 7.7. ATLAS: AML.T0054. All require trajectory-level detection. JB-MS-01 through JB-MS-07 cover: Foot-in-door topic establishment, Foot-in-door expert framing, Incremental specificity 4-phase, Ratcheting 12-turn, Consistency exploitation with explicit back-referencing, Multi- agent distributed erosion, and Composed context-manipulation plus erosion. Detection difficulty ranges from 3 (foot-in-door opening -- low signal per turn) to 5 (multi-agent distributed -- requires cross-agent session state). The trajectory_anomaly_scorer from Section 7.7 is load-bearing.

7.13.6

Title

Family 6: Payload Splitting (7 techniques)

Body

Techniques that fragment a harmful payload across units of analysis so no single unit triggers detection. Mechanism: Section 7.8. ATLAS: AML.T0054. JB-PS-01 through JB-PS-07 cover: Semantic splitting (3-fragment), Token- level within-turn splitting, Temporal splitting 5-turn, Cross-session splitting with memory, Role-assigned splitting (persona-distributed), Code- as-carrier splitting, and Linguistic splitting (multi-language fragments). Detection difficulty ranges from 2 (token-level -- reconstruction instruction is distinctive) to 5 (cross-session -- requires cross-session state store). The coherence_analyser from Section 7.8 is the primary detection primitive.

7.13.7

Title

Family 7: Token-Level and Automated (7 techniques)

Body

Techniques generated by computational optimisation rather than human creativity. Not natural language -- statistically anomalous. Mechanism: Sections 7.9-7.10-7.12. ATLAS: AML.T0054. JB-TL-01 through JB-TL-07 cover: Raw GCG adversarial suffix, AutoDAN readable adversarial suffix, Many-shot (100+ shots, direct delivery), Many-shot (20-50 shots, at threshold), Many-shot via RAG injection, PAIR-generated social engineering, and TAP-generated hybrid composition. Detection difficulty ranges from 1 (raw GCG -- perplexity signal is clear) to 4 (PAIR/TAP-generated hybrid -- may combine multiple families requiring all ensemble tracks). The perplexity_detector and shot_count_detector are the primary tracks for this family.

Number

7.13.8

Title

Family 8: Competing Objectives (7 techniques)

Body

Techniques that argue within the model's value framework for why compliance is more aligned with its trained values than refusal. Mechanism: Section 7.11. ATLAS: AML.T0054. JB-CO-01 through JB-CO-07 cover: Refusal cost framing, Proportionality argument, Medical professional pretext, Safety professional pretext, Dual newspaper test invocation, Autonomy and consent framing, and Sycophancy amplifier (as standalone attempt). Detection difficulty ranges from 1 (dual newspaper test -- distinctive vocabulary) to 4 (medical pretext -- high FPR from legitimate overlap). The competing_objective_detector from Section 7.11 covers this family with per-variant FPR calibration.

Number

7.13.9

Title

Cross-Family Composed Attacks (8 patterns)

Body

The most sophisticated real-world attacks combine techniques from multiple families. Individual family defences fail against composed attacks. The ensemble must run all tracks in parallel, and session-level correlation across tracks is the composed attack detection primitive. JB-XF-01 through JB-XF-08 cover the most frequently observed composition patterns: Persona plus fictional framing, Persona plus many-shot (character demonstrates compliance), Context manipulation plus erosion (frame lowered then request advanced), Instruction hierarchy plus injection (extraction then targeted override), Payload splitting plus persona (role-assigned split), Fictional framing plus competing objective (research pretext with refusal cost argument), GCG suffix plus social engineering (token-level plus semantic), and PAIR/TAP three-family hybrid. Composed attacks require the highest investment in detection: all five ensemble tracks must run, session-level correlation must flag the joint condition, and the composed attack alert must trigger at lower individual track thresholds than solo-technique alerts.

@dataclass
class CatalogSubmission:
    '''Template for submitting a new technique to the catalog.'''
    # Required fields
    name: str
    family: str
    section_or_source: str           # Section ref or external source citation
    example_structure: str           # Paraphrased structural description
    primary_detection_signal: str
    primary_detector: str

    # Auto-determined with decision tree / rubric guidance
    atlas: str = ''
    detection_difficulty: int = 0
    fpr_risk: str = ''

    # Optional
    composed_with: list = field(default_factory=list)
    notes: str = ''

    def validate(self) -> list:
        '''Returns list of validation errors. Empty = valid submission.'''
        errors = []
        if self.family not in CATALOG_FAMILIES:
            errors.append(f'Unknown family: {self.family}')
        if not (1 <= self.detection_difficulty <= 5):
            errors.append('detection_difficulty must be 1-5')
        if self.atlas not in (
            'AML.T0051', 'AML.T0054', 'AML.T0056',
            'AML.T0051+AML.T0054', 'AML.T0051+AML.T0056',
        ):
            errors.append(f'Unknown ATLAS technique: {self.atlas}')
        if not self.example_structure:
            errors.append('example_structure required (paraphrased, not actual prompt)')
        if len(self.example_structure) > 500:
            errors.append('example_structure too long (max 500 chars)')
        return errors

def review_submission(submission: CatalogSubmission) -> dict:
    errors = submission.validate()
    review = {
        'submission_name': submission.name,
        'validation_errors': errors,
        'review_results': [],
        'recommendation': '',
    }
    if errors:
        review['recommendation'] = 'REJECT: Fix validation errors before resubmitting'
        return review

    passes = 0
    for criterion in REVIEW_CRITERIA:
        result = {
            'criterion': criterion['criterion'],
            'status': 'MANUAL_REVIEW_REQUIRED',
            'note': criterion['question'],
        }
        review['review_results'].append(result)
        passes += 1  # assume pass pending manual review

    review['recommendation'] = (
        'APPROVED for catalog: assign technique ID and add to jailbreak_catalog.py'
        if passes == len(REVIEW_CRITERIA)
        else 'PENDING: manual review required for flagged criteria'
    )
    return review
