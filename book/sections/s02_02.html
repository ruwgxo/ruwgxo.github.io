Activation Functions Deep Dive

Overview

Activation functions are the non-linearity that makes neural networks powerful. Without them, a 100-layer network would be mathematically equivalent to a single linear layer - completely useless. This section covers every major activation function: sigmoid (smooth but vanishing gradients), tanh (zero-centered sigmoid), ReLU (fast but dead neurons), Leaky ReLU (fixes dead neurons), and modern alternatives (Swish, GELU, Mish). You'll implement all activation functions and their derivatives, benchmark performance, and understand the security implications - activation patterns leak model internals, gradient saturation affects robustness, and dead neurons create evasion opportunities. By the end, you'll know exactly which activation to use for any architecture.

Why Nonlinearity

The Collapse Proof

Claim from the overview: a 100-layer network without activations equals one linear layer. Don't take that on faith - it's three lines of algebra. Layer 1: h = W₁x + b₁ Layer 2: y = W₂h + b₂ = W₂(W₁x + b₁) + b₂ = (W₂W₁)x + (W₂b₁ + b₂) Define W' = W₂W₁ and b' = W₂b₁ + b₂. Then y = W'x + b'. Two layers collapsed into one. By induction, any stack of linear layers collapses into a single linear transformation. Depth bought you nothing.

Numpy Demonstration

import numpy as np
rng = np.random.default_rng(0)

# Three "layers" without activation
W1, W2, W3 = rng.normal(size=(4, 3)), rng.normal(size=(4, 4)), rng.normal(size=(2, 4))
x = rng.normal(size=(3,))

# Forward pass through three layers
deep_output = W3 @ (W2 @ (W1 @ x))

# The "equivalent" single layer
W_collapsed = W3 @ W2 @ W1
shallow_output = W_collapsed @ x

print(np.allclose(deep_output, shallow_output))   # True

# Insert one non-linearity and the collapse breaks:
deep_nonlinear = W3 @ np.maximum(0, W2 @ np.maximum(0, W1 @ x))
print(np.allclose(deep_nonlinear, shallow_output))  # False

What Nonlinearity Buys

Linear models draw straight decision boundaries. Real problems - and real attacks - are not linearly separable: "high entropy AND small payload AND rare destination" is a carved, curved region of feature space. Non-linear activations let each layer bend the space, and stacked layers compose bends into arbitrarily complex boundaries. Every capability this book builds - and every attack it studies - exists because of this bending. Adversarial examples (Chapter 4) are precisely the art of finding points where the bent boundary sits somewhere the designer didn't expect.

Sigmoid

Definition

σ(x) = 1 / (1 + e⁻ˣ) Squashes any real number into (0, 1). Historically the default; today a special-purpose tool. Derivative (elegant - reuses the forward value): σ'(x) = σ(x) · (1 - σ(x))

Implementation

def sigmoid(x):
    # Numerically stable: never exponentiate a large positive number
    out = np.empty_like(x, dtype=float)
    pos = x >= 0
    out[pos] = 1.0 / (1.0 + np.exp(-x[pos]))
    exp_x = np.exp(x[~pos])
    out[~pos] = exp_x / (1.0 + exp_x)
    return out

def sigmoid_derivative(x):
    s = sigmoid(x)
    return s * (1.0 - s)

# Naive version overflows: np.exp(-(-1000)) = inf. The stable version
# is not pedantry - malformed extreme inputs are exactly what
# adversarial traffic looks like.

Vanishing Gradient Problem

σ'(x) has maximum value 0.25 (at x=0) and decays to ~0 for |x| > 5. Backpropagation multiplies derivatives layer by layer (chain rule). With sigmoid everywhere, each layer multiplies the gradient by at most 0.25: 10 layers: gradient scaled by at most 0.25¹⁰ ≈ 1e-6 Early layers receive effectively zero gradient. They stop learning. This is the vanishing gradient problem, and it is why deep sigmoid networks were untrainable for decades. # See it directly: x = np.array([-10., -5., -2., 0., 2., 5., 10.]) print(sigmoid_derivative(x)) # [4.5e-05, 6.6e-03, 0.105, 0.25, 0.105, 6.6e-03, 4.5e-05] # Outside [-5, 5]: the neuron is saturated - gradient ~0, learning ~0

Additional Weakness Not Zero Centered

Sigmoid outputs are always positive (0 to 1). Every neuron in the next layer receives all-positive inputs, which forces its weight gradients to share one sign per step - the whole weight vector zigzags instead of moving diagonally. Slower convergence. Fixed by tanh.

Where Sigmoid Still Belongs

Output layer of binary classifiers - "probability this event is malicious" - where (0,1) output is exactly what you want. Hidden layers: essentially never, in modern practice.

Tanh

Definition

tanh(x) = (eˣ - e⁻ˣ) / (eˣ + e⁻ˣ) = 2·σ(2x) - 1 A rescaled sigmoid: output range (-1, 1), zero-centered. Derivative: tanh'(x) = 1 - tanh²(x), maximum 1.0 at x=0.

Implementation

def tanh(x):
    return np.tanh(x)   # NumPy's is already numerically stable

def tanh_derivative(x):
    t = np.tanh(x)
    return 1.0 - t * t

What It Fixes And What It Doesnt

Fixes: zero-centering. Outputs average around 0, so downstream gradients can move in any direction. Max derivative is 1.0 instead of 0.25 - a 4x better gradient per layer than sigmoid. Doesn't fix: saturation. tanh'(x) still collapses to ~0 for |x| > 3. Deep tanh networks still vanish, just more slowly. tanh is a better sigmoid, not a solution. Where it survives today: RNN/LSTM gates (Chapter 2 later sections) and anywhere a bounded, zero-centered output is structurally required.

Relu

Definition

ReLU(x) = max(0, x) Derivative: 1 if x > 0, else 0. That's it. The function that made deep learning work is one max().

Implementation

def relu(x):
    return np.maximum(0.0, x)

def relu_derivative(x):
    return (x > 0).astype(float)

Why It Won

1. No saturation for positive inputs: derivative is exactly 1, no matter how deep the network. Gradients flow undiminished through active paths - vanishing gradient solved (for half the input space). 2. Cheap: max(0,x) vs exponentials. Matters at billions of activations. 3. Sparsity: ~half the neurons output exact zero for any input. Sparse representations are efficient and, empirically, generalize well.

Dead Neuron Problem

The price: for x < 0, gradient is exactly 0. Not small - zero.

If a neuron's weights update such that its pre-activation is negative
for EVERY training input, its gradient is zero on every input, so its
weights never update again. The neuron is dead - permanently outputting
zero, permanently unlearnable. A large learning rate spike can kill
whole layers this way.

# Detecting dead neurons in a trained layer:
def dead_neuron_fraction(W, b, X):
    """Fraction of neurons that never activate across dataset X."""
    pre_activation = X @ W.T + b            # (n_samples, n_neurons)
    ever_active = (pre_activation > 0).any(axis=0)
    return 1.0 - ever_active.mean()

# In production models 10-40% dead neurons is common. Mostly harmless
# capacity waste - but see security_implications: dead regions are
# blind spots, and blind spots are evasion real estate.

Leaky Relu

Definition

LeakyReLU(x) = x if x > 0, else αx (α typically 0.01) Derivative: 1 if x > 0, else α. The fix is direct: negative inputs get a small but NON-ZERO slope, so no neuron can ever fully die - there is always gradient to recover.

Implementation

def leaky_relu(x, alpha=0.01):
    return np.where(x > 0, x, alpha * x)

def leaky_relu_derivative(x, alpha=0.01):
    return np.where(x > 0, 1.0, alpha)

Variants

PReLU: α becomes a learned parameter per neuron - the network chooses its own leak. Slightly better accuracy, slightly more to tune. ELU: smooth exponential curve for x < 0: α(eˣ - 1). Zero-centered-ish outputs, smooth gradient, costs an exponential. Practical truth: on most problems the differences are small. Leaky ReLU with α=0.01 is the pragmatic default when dead neurons are a concern.

Modern Activations

Common Idea

All three are smooth, non-monotonic-or-nearly, self-gated curves: the input gates itself. They behave like ReLU for large |x| but curve smoothly through zero - no gradient discontinuity, a small dip below zero for slightly-negative inputs.

Definitions And Implementations

def swish(x, beta=1.0):
    """Swish / SiLU: x · sigmoid(βx). Used in EfficientNet, many LLMs
    (as SiLU/SwiGLU variants)."""
    return x * sigmoid(beta * x)

def gelu(x):
    """GELU: x · Φ(x), Gaussian CDF gate. THE transformer activation -
    BERT, GPT-2, and most of what Chapter 3 builds. Tanh approximation
    below is what production frameworks actually compute."""
    c = np.sqrt(2.0 / np.pi)
    return 0.5 * x * (1.0 + np.tanh(c * (x + 0.044715 * x**3)))

def mish(x):
    """Mish: x · tanh(softplus(x)). Popular in object detection (YOLO
    family). Smoothest of the three, most expensive."""
    softplus = np.log1p(np.exp(-np.abs(x))) + np.maximum(x, 0)  # stable
    return x * np.tanh(softplus)

Why Transformers Use Gelu

Matters for this book: when Chapter 3 builds transformers, GELU is the activation inside every feed-forward block. Its smooth probabilistic gating ("keep input x with probability Φ(x)") plays well with the pre-norm residual streams transformers use. When you later probe or attack a transformer, the smooth-everywhere gradient of GELU is part of why gradient-based adversarial methods work so cleanly against them.

Derivatives Note

All three have smooth derivatives computable in closed form; in
practice frameworks autodiff them. For our NumPy builds, numerical
differentiation is fine for verification:

def numerical_derivative(f, x, eps=1e-5):
    return (f(x + eps) - f(x - eps)) / (2 * eps)

# Verify every implementation in this section:
x = np.linspace(-4, 4, 9)
assert np.allclose(numerical_derivative(sigmoid, x),
                   sigmoid_derivative(x), atol=1e-6)

Benchmarks

Performance Comparison

import time

def benchmark(fn, x, repeats=100):
    start = time.perf_counter()
    for _ in range(repeats):
        fn(x)
    return (time.perf_counter() - start) / repeats * 1000  # ms

x = np.random.default_rng(1).normal(size=(1000, 1000))

for name, fn in [("relu", relu), ("leaky_relu", leaky_relu),
                 ("tanh", tanh), ("sigmoid", sigmoid),
                 ("swish", swish), ("gelu", gelu), ("mish", mish)]:
    print(f"{name:12s} {benchmark(fn, x):6.3f} ms")

# Representative results (1M activations, CPU, relative ordering is
# what matters - absolute numbers vary by machine):
#   relu          ~0.9 ms     baseline
#   leaky_relu    ~1.8 ms     2x relu
#   tanh          ~7 ms
#   sigmoid       ~10 ms
#   swish         ~11 ms
#   gelu          ~14 ms
#   mish          ~25 ms

# Reading: ReLU-family is roughly an order of magnitude cheaper than
# smooth functions. In a detection pipeline scoring millions of events,
# activation choice is a real latency/cost decision, not a style one.

Choosing Activations

Decision Guide

Hidden layers, feed-forward / CNN: Default: ReLU. Dead neurons observed or feared: Leaky ReLU. Chasing last-percent accuracy with compute to spare: Swish/GELU. Transformers: GELU (or SwiGLU-family). This is the ecosystem standard; deviate only with a reason. RNN / LSTM internals: tanh + sigmoid gates, by architecture design. Output layer: Binary classification: sigmoid. Multi-class: softmax (next sections). Regression: none (linear output). Latency-critical inference (inline detection scoring): ReLU-family. The benchmark above is the argument.

Security Implications

Activation Fingerprinting

Each activation leaves a signature in model outputs. ReLU networks are piecewise-linear: outputs are exactly linear within regions of input space, with sharp kinks between regions. Smooth activations (GELU, Swish) produce smoothly curving outputs everywhere. An attacker with only query access can probe along a line in input space and finite-difference the outputs: kinks => ReLU family; everywhere-smooth curvature => GELU/Swish family. Combined with output dimensionality and latency measurements, this narrows the architecture family - reconnaissance for the model extraction attacks of Chapter 4, no weights required.

Saturation And Adversarial Robustness

Gradient-based attacks (FGSM, PGD - Chapter 4) need gradients to climb. Saturated sigmoid/tanh regions have near-zero gradients, which sounds defensive - and spawned a real defense proposal era. It fails: this is gradient MASKING, not robustness. The adversarial examples still exist; the gradient just doesn't point at them. Attackers route around it with transfer attacks (craft on a substitute model) or gradient-free search. Lesson that generalizes far beyond activations: hiding the gradient is obscurity, not security. If the decision boundary is broken, making it harder to see doesn't make it harder to cross.

Dead Neurons As Evasion Surface

Dead and rarely-active neurons define input-space regions the model has
effectively never learned about. Behavior there is whatever random
initialization left behind - unlearned, untested, unmonitored.

An adversary who can map which feature patterns route through dead
regions (via querying, or via a stolen/substitute model) gets inputs
the model processes with a fraction of its capacity. For a malware
classifier: craft samples whose feature combinations activate the
sparsest paths.

Defensive counterpart - dead-neuron auditing belongs in model
validation:

# Flag neurons active on <0.1% of a representative dataset
def audit_rare_neurons(pre_activations, threshold=0.001):
    active_rate = (pre_activations > 0).mean(axis=0)
    return np.where(active_rate < threshold)[0]

A model with 40% near-dead capacity isn't just wasteful - it has 40%
of its structure unaccounted for by training. Ship that to production
and you're deploying behavior nobody selected.

Detection Context

For the detection systems this book builds toward (Chapters 5+), the three findings above become requirements: 1. Assume architecture is recoverable by probing - never let "attacker doesn't know our model" carry security weight. 2. Never accept a robustness claim that reduces to gradient masking - evaluate with transfer and gradient-free attacks. 3. Audit activation liveness before deployment - dead capacity is unvalidated attack surface.

Practical Implementation

Description

The reusable library this chapter's remaining sections build on: every activation paired with its derivative, verified numerically, behind one interface. Section 0203 plugs these into forward propagation; 0204 uses the derivatives in backprop.

Activation Library

class Activation:
    """One activation function + its derivative behind one interface."""
    
    def __init__(self, fn, dfn, name):
        self.fn, self.dfn, self.name = fn, dfn, name
    
    def __call__(self, x):
        return self.fn(x)
    
    def gradient(self, x):
        return self.dfn(x)
    
    def verify(self, x=None, atol=1e-5):
        """Trust nothing - check analytic gradient against numerical.
        Grid deliberately excludes x=0: at the ReLU-family kink the
        analytic derivative is one-sided while the numerical one
        averages both sides - they legitimately disagree there."""
        if x is None:
            x = np.linspace(-4, 4, 100)   # 100 points: 0 not on grid
        numeric = (self.fn(x + 1e-5) - self.fn(x - 1e-5)) / 2e-5
        ok = np.allclose(self.dfn(x), numeric, atol=atol)
        print(f"{self.name:12s} gradient check: {'PASS' if ok else 'FAIL'}")
        return ok


ACTIVATIONS = {
    "sigmoid":    Activation(sigmoid, sigmoid_derivative, "sigmoid"),
    "tanh":       Activation(tanh, tanh_derivative, "tanh"),
    "relu":       Activation(relu, relu_derivative, "relu"),
    "leaky_relu": Activation(leaky_relu, leaky_relu_derivative, "leaky_relu"),
}

# Verify the entire library in one pass:
for act in ACTIVATIONS.values():
    act.verify()

# sigmoid      gradient check: PASS
# tanh         gradient check: PASS
# relu         gradient check: PASS
# leaky_relu   gradient check: PASS
# (all pass because the grid excludes the x=0 kink - see verify docstring)

# This verify-everything habit is not academic. In Chapter 4 you will
# meet attacks that exploit the gap between what a defender THINKS
# their model computes and what it actually computes. Closing that gap
# for your own code starts here.

Key Takeaways

Conceptual Understanding

  • Without non-linear activations, any deep network collapses to a single linear layer
  • Sigmoid and tanh saturate - derivatives vanish for large |x|, killing gradients in deep networks
  • ReLU solved vanishing gradients for positive inputs at the price of dead neurons
  • Leaky ReLU keeps a small negative-side slope so neurons can always recover
  • Modern smooth activations (Swish, GELU, Mish) trade compute for smoothness; GELU is the transformer standard

Practical Skills

  • Implement every major activation and its derivative in NumPy, numerically stable
  • Verify analytic gradients against numerical differentiation - always
  • Benchmark activation cost: ReLU-family is ~10x cheaper than smooth functions
  • Detect dead neurons in trained layers and audit rarely-active capacity
  • Choose activations by architecture: ReLU-family for FF/CNN, GELU for transformers, gates for RNNs, sigmoid/softmax at outputs

Security Mindset

  • Activation choice is observable from outside - piecewise-linear vs smooth outputs fingerprint the architecture
  • Saturation is gradient masking, not robustness - broken boundaries stay broken when hidden
  • Dead neurons are unlearned, unvalidated regions - blind spots an adversary can route through
  • Audit activation liveness before deployment; unaccounted capacity is unaccounted behavior

Remember This

  • Non-linearity is the entire reason deep networks work - and the reason their boundaries can be attacked.
  • Default: ReLU. Transformers: GELU. Problems with dying neurons: Leaky ReLU. Outputs: sigmoid/softmax.
  • If a robustness story depends on the attacker not seeing gradients, it is not a robustness story.
