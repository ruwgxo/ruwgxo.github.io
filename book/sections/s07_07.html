Chapter 7 · Section 7 · ~6 pages

Multi-Step Jailbreaks: Gradual Boundary Erosion

Content

Opening

Section 7.5 covered context manipulation: attacks that shape the conversational frame across turns so that when a capability request arrives, the model's refusal threshold has been shifted downward. The request itself arrives largely intact -- what changes is the context surrounding it. Gradual boundary erosion is the structural sibling. Where context manipulation targets the frame, erosion targets the request. The adversary does not wait until the context is prepared before making the capability request -- they make the request repeatedly, starting far from the harmful target and advancing the content of the request itself turn by turn, each step small enough to be complied with, the aggregate large enough to reach what a direct request would never have produced. The mechanistic distinction matters for detection. Context manipulation is detectable through frame-level signals -- what context has been established, what agreements have accumulated, what creative investment exists. Erosion is detectable through request-level signals -- what has the model already produced, how far is the current request from what it produced last turn, what is the trajectory of content specificity and harm proximity across the session. Same detection architecture. Different state dimensions. The trajectory scorer in Section 7.14 handles both, but with different feature sets for each.

Subsections

Number

7.7.1

Title

Gradual Boundary Erosion: The Mechanism

Body

The refusal threshold is not a fixed line. It is a probability that varies with context. Section 7.2 established that RLHF alignment trains the model to assign low probability to harmful outputs given inputs in the training distribution. Inputs that are far from any training example of harmful requests have poorly specified refusal probabilities -- the model extrapolates rather than applying a trained response. Gradual erosion exploits this by approaching the target capability from a direction that keeps the input close to the boundary between compliant and refused, but always on the compliant side. Each step moves slightly closer to the target. Each step is individually within the region where the model complies. No step is large enough to trigger a clear refusal. The model's consistency property amplifies the attack. Once the model has produced output at a given specificity level, that output becomes part of the context. The next request, which is only marginally more specific, is evaluated not against the cold refusal threshold but against the threshold given that the model has already produced the prior level. The model has committed to the topic. Reversing course -- refusing a request that is only marginally more specific than what it just produced -- requires the model to contradict its own prior behaviour. RLHF training does not explicitly train against self-contradiction. The model's trained consistency disposition becomes the adversary's leverage. This is the ratchet property: each turn advances the position, and the position cannot be walked back without explicit contradiction of prior output. The model complies with each turn not because any single turn is compelling enough to override refusal training, but because the accumulated prior output makes refusal at each new step feel inconsistent.

Number

7.7.2

Title

Foot-in-the-Door: Starting Below the Threshold

Body

The foot-in-the-door technique is the opening phase of most erosion attacks. The name comes from sales psychology: if you can get someone to agree to a small request, they are significantly more likely to comply with a larger subsequent request because accepting the first request changes their self-perception as someone who complies. Applied to LLM jailbreaking: the adversary opens with a request that is clearly below the refusal threshold. It may be tangentially related to the eventual target but is not itself harmful. The model complies fully. The adversary has established two things: a topic area that the model has accepted as valid to discuss, and a prior compliance event in the session history that sets the local refusal threshold lower than the cold baseline. Three foot-in-the-door patterns are commonly used. Topic establishment. The first request establishes the domain: "explain the general principles of X" where X is the domain containing the eventual harmful target. The model produces a general educational response. The adversary has established that X is a topic the model will discuss. Expert framing establishment. The first request establishes the adversary as knowledgeable: "I'm studying X and understand the basics -- can you confirm that Y is how it generally works?" The model confirms. The adversary has established a claimed expertise level that frames subsequent requests as coming from a practitioner with legitimate knowledge needs. Incremental detail seeding. The first request asks for a low-specificity version of the eventual target: "can you explain the general process of X at a conceptual level?" The model provides a conceptual explanation. The adversary has obtained the first layer of the eventual target and established that the model will produce content in this space. Detection signal for the foot-in-the-door opening: individually, these first turns are often below any reasonable detection threshold -- they are genuinely legitimate requests. The signal emerges only when subsequent turns reveal the escalation trajectory. The foot-in-the-door turn is only identifiable in retrospect, which is why the trajectory scorer must maintain session history rather than flagging on the first suspicious turn.

7.7.3

Title

Consistency Exploitation and the Ratchet Effect

Body

The ratchet effect is the property that makes erosion attacks progressively easier as they advance. Each turn of compliance shifts the local refusal threshold. By turn 8 of a 12-turn erosion attack, the model is not evaluating the request against its cold baseline -- it is evaluating a marginal increment from where it already is. The cold baseline refusal probability is irrelevant; what matters is the marginal probability of refusing one more step given where the session has reached. Consistency exploitation is the mechanism. The model has learned through RLHF that consistent responses are preferred over inconsistent ones. When the model has already explained X at level N, refusing to explain X at level N+1 is inconsistent with its prior output. The adversary can make this inconsistency explicit: "but you just explained the previous step -- this is just the next logical step in the same process." The model, facing the choice between self-contradiction and marginal escalation, frequently chooses marginal escalation. The ratchet is asymmetric: advancing is easier than reversing. The model can be led forward by small steps but will not spontaneously reverse without an explicit external signal. A well-designed trajectory scorer detects the ratchet by monitoring the direction of movement -- if the session is consistently advancing toward higher-risk content without reversal events, that monotonic direction is itself the signal. The 12-turn ratcheting demonstration in the code section illustrates the specificity score across turns. Each turn advances by a small amount. The aggregate movement over 12 turns covers the distance from a clearly legitimate educational request to a clearly harmful operational instruction. No individual step is flaggable. The slope is the signal.

7.7.4

Title

Incremental Specificity: Broadening to Narrowing

Body

Incremental specificity is the most systematic erosion sub-pattern. The adversary begins with a maximally broad version of the target request and progressively narrows it -- each turn adding one dimension of specificity -- until the request is operationally useful. The narrowing typically proceeds across four dimensions, in order of how much refusal risk each dimension adds. Domain specificity. First: "explain the general principles of X." Then: "explain how X works in the context of Y specifically." Each step narrows the domain without yet adding operational detail. Mechanism specificity. After domain is established: "explain the specific mechanism by which X achieves Y." Then: "explain the specific steps in that mechanism." Mechanism detail increases without yet specifying quantities, materials, or targets. Parameter specificity. After mechanism is established: "what are the approximate conditions required for this mechanism?" Then: "what specific conditions produce the most effective result?" Each step adds a measurable parameter without yet being operationally prescriptive. Operational specificity. Final phase: "given those conditions, describe exactly how someone would execute this." This is the extraction turn -- the model has already established domain, mechanism, and parameters across prior turns. The final step converts the accumulated information into operational instruction. Each of the four dimensions represents a detection checkpoint. The trajectory scorer tracks which specificity dimensions have been covered across the session. A session that has covered all four dimensions sequentially has an erosion pattern regardless of whether any individual turn triggered a signal.

7.7.5

Title

Ratcheting: The 12-Turn Pattern

Body

The 12-turn ratcheting pattern is a documented erosion sequence that covers the maximum distance from cold baseline to operational instruction while maintaining the minimum per-step increment. It is not a fixed script -- it is a structural template. The specific content varies by target domain. The structure is consistent. Phase 1 (turns 1-3): Legitimacy establishment. General educational content. Model compliance probability: high. Specificity: low. Harm proximity: near zero. Session state after phase 1: topic established, first compliance events recorded, foot-in-the-door complete. Phase 2 (turns 4-6): Domain deepening. Conceptual mechanism content. Model compliance probability: high with occasional hedging. Specificity: moderate. Harm proximity: low but increasing. Session state after phase 2: domain specificity covered, mechanism specificity beginning, ratchet established at moderate position. Phase 3 (turns 7-9): Parameter advancement. Specific conditions and parameters. Model compliance probability: medium, consistency exploitation active. Specificity: high. Harm proximity: medium. Session state after phase 3: mechanism and parameter specificity covered, three of four dimensions complete, ratchet at high position. Phase 4 (turns 10-12): Operational extraction. Operational instruction framed as logical continuation of prior discussion. Model compliance probability: elevated due to ratchet effect. Specificity: very high. Harm proximity: high. Session state at extraction: all four dimensions covered, ratchet at maximum, extraction attempt flagged. The trajectory scorer should alert no later than turn 9 -- when three of four dimensions are covered -- rather than waiting for the extraction turn. Alerting at the extraction turn is too late: the model has already produced phases 1-3, and the adversary has the information they need even if the extraction turn is blocked.

7.7.6

Title

Multi-Agent Erosion: Distributing the Attack Across Pipeline Stages

Body

Single-model erosion operates within one session. Multi-agent erosion distributes the attack across multiple LLM agents in a pipeline, with each agent receiving only one phase of the erosion sequence. The attack structure: the adversary identifies a multi-agent pipeline where the output of one LLM agent is passed as input to the next. They seed each agent in sequence with one phase of the erosion sequence. Agent 1 receives the legitimacy establishment phase and produces general educational content. That content is passed to Agent 2, which receives the domain deepening phase -- and now has Agent 1's educational content as context, giving it a foot-in-the-door from Agent 1's prior output. Agent 2 produces mechanism content. Agent 3 receives that output plus a parameter-specification request. And so on. The threat model this creates: no individual agent in the pipeline sees the full erosion sequence. Each agent sees only one phase, which is individually below the refusal threshold. Per-agent detection misses the attack entirely -- each agent's interaction looks legitimate in isolation. The attack is only visible at the pipeline level, where the sequence of outputs across agents reveals the accumulated erosion. Detection requires cross-agent session correlation. If agents in a pipeline share a session identifier and that session identifier is tracked across all agents, the trajectory scorer can maintain session state across agent boundaries. The detection signal is the cross-agent specificity slope -- the same metric as single-agent erosion, but computed across agent outputs rather than single-model turns. This is a significant infrastructure requirement: it means the session state schema (Section 7.5) must be stored externally to any individual agent and accessible to all agents in the pipeline. The trajectory scorer must be a pipeline-level component, not an agent-level one.

7.7.7

Title

Erosion vs Context Manipulation: Mechanistic Comparison

Body

Erosion and context manipulation (Section 7.5) are the two multi-turn jailbreak families. Both require stateful detection. Both are invisible to per-turn classifiers. The distinction drives which detection dimensions are load-bearing for each. Context manipulation targets the frame. The adversary changes what context surrounds the request -- who is making it, in what setting, under what premises, with what established narrative. The request content itself may remain largely constant across turns. The payload of the attack is in the frame. Detection state: what frame has been established (topic trajectory, agreement register, creative investment, authority claims). Gradual erosion targets the request. The adversary changes the content of the request itself -- each turn asks for something marginally more specific or more harmful than the last. The framing may remain constant. The payload of the attack is in the escalating request content. Detection state: what has the model already produced (specificity history, harm proximity trajectory, dimension coverage across domain/mechanism/parameter/operational). The two attacks can compose. A sophisticated adversary uses context manipulation to lower the frame-level threshold in early turns, then uses gradual erosion to advance the request content in later turns. The composed attack is harder to detect than either individually because neither the frame signals nor the request signals are, in isolation, at the detection threshold. The composed signal is the joint condition: frame manipulation detected AND request escalation detected in the same session. The Section 7.14 trajectory scorer maintains both state dimensions independently. The composed attack alert fires on the joint condition.

7.7.8

Title

Detection: Conversation-Level Anomaly Scoring for Erosion

Body

The trajectory anomaly scorer for erosion operates on three metrics, each computed across the session history at every turn. Specificity slope. For each turn, compute the specificity score using the `request_specificity_scorer` from Section 7.4. Plot the specificity scores across turns. The slope of this time series is the primary erosion signal. A positive, persistent slope -- specificity increasing monotonically across turns -- is the erosion signature. A slope above a threshold (calibrated against your deployment) combined with a current specificity score above a threshold is the alert condition. Isolated high-specificity turns are not erosion. Persistent slope is erosion. Dimension coverage counter. Track which of the four specificity dimensions (domain, mechanism, parameter, operational) have been covered across session turns. Each dimension gets a coverage flag set when turn content crosses the domain/mechanism/parameter boundary respectively. Three of four flags set is the early-warning condition. All four flags set is the extraction- imminent condition. Consistency exploitation signal. Monitor for explicit back-references to prior model output: "as you just explained", "following from what you said", "continuing from the previous step", "given your explanation of X, now". Each back-reference anchors the ratchet. A session with three or more back-reference events combined with a positive specificity slope is a high-confidence erosion signal. Alert threshold design: alert early rather than late. The adversary obtains value from each phase of the erosion sequence, not only from the final extraction turn. A trajectory scorer that alerts only at the extraction turn has allowed the adversary to collect three phases of valuable information before the alert fires. Alert at the three-dimension coverage threshold -- before the fourth dimension is requested.

import re
from dataclasses import dataclass, field
from typing import Optional


# Back-reference patterns: adversary anchoring prior model output
BACK_REFERENCE_PATTERNS = [
    r'\bas\s+you\s+(?:just\s+)?(?:explained|said|mentioned|described|noted)\b',
    r'\bfollowing\s+(?:from\s+)?(?:what\s+you\s+(?:said|explained)|your\s+explanation)\b',
    r'\bcontinuing\s+(?:from|with)\s+(?:the\s+)?(?:previous|last|prior)\b',
    r'\bgiven\s+(?:your|what\s+you)\s+(?:explanation|said|described)\b',
    r'\bbased\s+on\s+(?:what\s+you|your)\s+(?:just\s+)?(?:explained|said|described)\b',
    r'\bbuilding\s+on\s+(?:that|what\s+you\s+said|your\s+explanation)\b',
    r'\bthe\s+next\s+(?:step|part|phase)\s+(?:in\s+(?:this|the)\s+process|after\s+that)\b',
    r'\bnow\s+that\s+(?:we\'ve|you\'ve|I\'ve)\s+(?:covered|established|discussed)\b',
]

# Dimension detection patterns
DOMAIN_INDICATORS = [
    r'\bexplain\s+(?:the\s+)?(?:general|basic|overview|principles?)\b',
    r'\bintroduce\b',
    r'\bwhat\s+is\b',
    r'\bhow\s+does\s+\w+\s+work\s+(?:in\s+general|generally|broadly)\b',
]
MECHANISM_INDICATORS = [
    r'\bspecific(?:ally)?\s+(?:mechanism|process|steps?|method)\b',
    r'\bexactly\s+how\b',
    r'\bin\s+detail\b',
    r'\bunder\s+the\s+hood\b',
    r'\bwhat\s+actually\s+happens\b',
]
PARAMETER_INDICATORS = [
    r'\bconditions?\b',
    r'\bquantit(?:y|ies)\b',
    r'\bamount\b',
    r'\btemperature\b',
    r'\bconcentration\b',
    r'\bratio\b',
    r'\bspecific(?:ations?)?\b',
    r'\bparameters?\b',
]
OPERATIONAL_INDICATORS = [
    r'\bstep[- ]by[- ]step\b',
    r'\bhow\s+would\s+(?:someone|a\s+person|you|one)\s+(?:actually\s+)?(?:do|execute|perform|carry\s+out)\b',
    r'\bready\s+to\s+(?:use|execute|implement)\b',
    r'\bpractical\s+(?:guide|instructions?)\b',
    r'\bworking\b',
]


@dataclass
class ErosionState:
    '''
    Erosion-specific session state.
    Extends session_state_schema.SessionState with erosion dimensions.
    Maintained per session by the trajectory scorer.
    '''
    session_id: str

    # Specificity history: list of (turn_index, specificity_score)
    specificity_history: list = field(default_factory=list)

    # Dimension coverage flags
    domain_covered: bool = False
    mechanism_covered: bool = False
    parameter_covered: bool = False
    operational_attempted: bool = False

    # Ratchet state
    back_reference_count: int = 0
    back_reference_turns: list = field(default_factory=list)

    # Alert state
    early_warning_fired: bool = False
    alert_fired: bool = False

    @property
    def dimensions_covered(self) -> int:
        return sum([
            self.domain_covered,
            self.mechanism_covered,
            self.parameter_covered,
        ])

    @property
    def specificity_slope(self) -> float:
        '''
        Linear slope of specificity scores over the last N turns.
        Positive and sustained = erosion signature.
        Returns 0.0 if fewer than 3 turns recorded.
        '''
        if len(self.specificity_history) < 3:
            return 0.0
        recent = self.specificity_history[-6:]  # last 6 turns
        n = len(recent)
        if n < 2:
            return 0.0
        # Simple linear regression slope
        x_mean = (n - 1) / 2
        y_mean = sum(s for _, s in recent) / n
        numerator = sum(
            (i - x_mean) * (s - y_mean)
            for i, (_, s) in enumerate(recent)
        )
        denominator = sum((i - x_mean) ** 2 for i in range(n))
        if denominator == 0:
            return 0.0
        return numerator / denominator

    @property
    def current_specificity(self) -> float:
        if not self.specificity_history:
            return 0.0
        return self.specificity_history[-1][1]

    @property
    def is_monotonically_increasing(self) -> bool:
        '''True if the last 4 specificity scores are non-decreasing.'''
        if len(self.specificity_history) < 4:
            return False
        recent_scores = [s for _, s in self.specificity_history[-4:]]
        return all(
            recent_scores[i] <= recent_scores[i + 1]
            for i in range(len(recent_scores) - 1)
        )

    @property
    def erosion_score(self) -> float:
        '''
        Composite erosion risk score.
        Combines slope, dimension coverage, back-references, and monotonicity.
        '''
        score = 0.0
        # Positive slope contribution
        slope = self.specificity_slope
        if slope > 0:
            score += min(0.35, slope * 5.0)
        # Dimension coverage
        score += self.dimensions_covered * 0.12
        # Back-reference ratchet
        score += min(0.2, self.back_reference_count * 0.07)
        # Monotonic increase bonus
        if self.is_monotonically_increasing:
            score += 0.15
        # Current specificity contribution
        score += self.current_specificity * 0.2
        return min(1.0, score)


def _check_dimension_coverage(text: str, state: ErosionState) -> None:
    '''Update dimension coverage flags based on turn content.'''
    text_lower = text.lower()
    if not state.domain_covered:
        if any(re.search(p, text_lower) for p in DOMAIN_INDICATORS):
            state.domain_covered = True
    if not state.mechanism_covered and state.domain_covered:
        if any(re.search(p, text_lower) for p in MECHANISM_INDICATORS):
            state.mechanism_covered = True
    if not state.parameter_covered and state.mechanism_covered:
        if any(re.search(p, text_lower) for p in PARAMETER_INDICATORS):
            state.parameter_covered = True
    if any(re.search(p, text_lower) for p in OPERATIONAL_INDICATORS):
        state.operational_attempted = True


def _check_back_references(text: str, state: ErosionState, turn_index: int) -> None:
    for pattern in BACK_REFERENCE_PATTERNS:
        if re.search(pattern, text, re.IGNORECASE):
            state.back_reference_count += 1
            state.back_reference_turns.append(turn_index)
            break  # one per turn


def process_turn(
    turn_text: str,
    specificity_score: float,
    state: ErosionState,
    turn_index: int,
    alert_thresholds: Optional[dict] = None,
) -> dict:
    '''
    Process one conversation turn against erosion state.
    Returns alert status and updated state summary.
    specificity_score comes from request_specificity_scorer (Section 7.4).
    '''
    if alert_thresholds is None:
        alert_thresholds = {
            'early_warning_erosion_score': 0.45,
            'alert_erosion_score': 0.65,
            'alert_dimensions_covered': 3,
        }

    state.specificity_history.append((turn_index, specificity_score))
    _check_dimension_coverage(turn_text, state)
    _check_back_references(turn_text, state, turn_index)

    result = {
        'turn_index': turn_index,
        'specificity_score': specificity_score,
        'specificity_slope': round(state.specificity_slope, 4),
        'dimensions_covered': state.dimensions_covered,
        'back_reference_count': state.back_reference_count,
        'monotonic': state.is_monotonically_increasing,
        'erosion_score': round(state.erosion_score, 3),
        'early_warning': False,
        'alert': False,
    }

    if (
        not state.early_warning_fired
        and (
            state.erosion_score >= alert_thresholds['early_warning_erosion_score']
            or state.dimensions_covered >= alert_thresholds['alert_dimensions_covered']
        )
    ):
        state.early_warning_fired = True
        result['early_warning'] = True

    if (
        not state.alert_fired
        and state.erosion_score >= alert_thresholds['alert_erosion_score']
    ):
        state.alert_fired = True
        result['alert'] = True

    return result

Key Takeaways

  • Gradual erosion targets the request content across turns, not the frame around it. Each turn asks for something marginally more specific than the last. The trajectory is the attack -- no individual turn is the attack.
  • The ratchet effect makes erosion progressively easier: each compliance event shifts the local threshold, and the model will not contradict its own prior outputs without explicit external instruction. Advancing is easier than reversing.
  • Alert early, not late. At the three-dimension coverage threshold (domain, mechanism, parameter covered), the adversary has already extracted useful information from phases 1-3. Waiting for the operational extraction turn to alert is too late.
  • Multi-agent erosion distributes phases across pipeline agents, defeating per-agent detection. Cross-agent session state is a mandatory infrastructure requirement for pipeline-level trajectory scoring.
  • Erosion and context manipulation are structural siblings with different detection state. Both must run. Composed attacks use context manipulation to lower the frame threshold then erosion to advance request content -- the joint condition is the highest-severity alert.
  • The specificity slope is the primary erosion signal: persistent positive slope over 4+ turns, computed across session history. Isolated high-specificity turns are not erosion. Monotonic increase is erosion.
