Chapter 16 · Section 5 · ~6 pages

Elastic Stack Integration: Logstash Pipelines

Section Overview

One Line Summary

The third platform connector: detections reach Elasticsearch through a Logstash pipeline that transforms them into ECS-aligned documents with an explicit field mapping, land in daily indices governed by a lifecycle policy, and become searchable and visualisable in Kibana -- with the generated Sigma rules deployed as Elastic detection rules.

Why This Section Exists

Splunk and Datadog both accepted structured events more or less as sent. The Elastic Stack introduces the piece the other two hid: an explicit transformation and indexing stage. Detections do not go straight into Elasticsearch; they pass through Logstash, which parses, transforms, and enriches each event before it is indexed, and the index has a mapping that declares each field's type. That transformation stage is the distinguishing feature of this connector, and getting it right is what makes the difference between detections Kibana can aggregate and detections it merely stores as text. The section builds both sides of the transform. On the delivery side, a connector pushes detection events to the Logstash HTTP input. On the definition side, it produces the transform itself -- as a testable Python function that maps the detection-event schema to an Elasticsearch document, and as the equivalent Logstash pipeline config that runs in production, plus the explicit Elasticsearch mapping that types the fields. It aligns the document with ECS, the Elastic Common Schema, so detections interoperate with the rest of a team's Elastic data, writes to daily time-based indices with an index lifecycle policy so the data does not grow without bound, and deploys the generated Sigma rules as Elastic detection rules so the portable logic runs on the platform. As with the other connectors, the transform and delivery are tested end to end on a stub.

Position In Chapter

Section 16.05 is the third and last of the platform connectors, completing the set (Splunk, Datadog, Elastic) before the custom webhook and enrichment of 16.06. It consumes the detection-event schema of 16.01, foregrounds the Logstash transformation stage the earlier connectors did not need, and deploys the Sigma rules of 16.02 as Elastic detection rules, so the portable core runs on its second named platform.

Prose Content

Part 1

Title

Logstash as the Transformation Stage

Body

The Elastic Stack does not ingest events the way Splunk's HEC or Datadog's Logs API do. Between the gateway and Elasticsearch sits Logstash, a pipeline that receives events, transforms them through a series of filters, and routes the result to an index. That extra stage is not overhead; it is the place where a raw detection becomes a well-formed Elasticsearch document -- where fields are renamed and nested, where the timestamp is normalised, where the ECS alignment is applied. The earlier connectors mapped the schema to a platform envelope in one step because the platform accepted it directly; Elastic makes the transform explicit and gives it its own stage, which is exactly why this section foregrounds it. The connector therefore has two faces. As a push integration it POSTs detection events to the Logstash HTTP input, owning delivery like the other connectors. But the substance of the integration is the transform Logstash applies, and the section builds that transform as a first-class, testable artifact rather than leaving it as opaque pipeline config. The transform is written once as a Python function and mirrored as a Logstash pipeline config, so the mapping can be unit-tested in isolation and also run in production. Everything that makes Elastic aggregate detections well lives in that transform.

Part 2

Title

Transforming the Schema into an Elasticsearch Document

Body

The transform maps the detection-event schema onto an Elasticsearch document with a specific shape. The schema's ISO timestamp becomes the document's @timestamp, the field Elastic and Kibana treat as the event time. The flat detection fields -- detector, verdict, severity, surface, score, confidence -- become top-level document fields. The request context nests into a request object holding the request id, session id, and source, so the document has a clean structure rather than a flat sprawl of prefixed keys. The evidence and labels carry over, and an ecs object records the schema version the document aligns to. The index is chosen in the transform too: the document's index is a daily index, a fixed prefix plus the date from the event's timestamp, so detections are partitioned by day. Aligning the document with ECS -- the Elastic Common Schema, the shared field vocabulary across Elastic's ecosystem -- is what lets these detections sit beside a team's other Elastic data and be queried with the same conventions. The transform is small and deterministic, which is deliberate: it is the single definition of what an indexed detection looks like, so it is written to be read and tested, not buried in pipeline plumbing.

Part 3

Title

The Explicit Mapping: Why Keyword Fields Matter

Body

Elasticsearch will happily index a document with no mapping, guessing each field's type from its first value. For detection data that default is a trap. A string field guessed as text is analysed -- broken into tokens for full-text search -- and an analysed field cannot be aggregated on cleanly, so a Kibana visualisation that tries to count detections by verdict or break them down by detector silently returns wrong or empty buckets. The fields a security team facets on must be keyword: stored whole, not analysed, aggregatable. The only way to guarantee that is to declare it. So the connector ships an explicit Elasticsearch mapping that types every field deliberately: detector, verdict, severity, and surface as keyword so they aggregate; @timestamp as date; score and confidence as float; the nested request fields as keyword; evidence as an object. The mapping is applied at index creation, before any detection lands, so the first document is typed correctly rather than fixing the type after the fact -- which Elasticsearch will not let you do without reindexing. This is the quiet, load-bearing part of the Elastic integration: the transform makes the document well-shaped, and the mapping makes its fields the right types, and without both, Kibana has data it cannot chart.

Part 4

Title

Daily Indices and Lifecycle Management

Body

Detection data accumulates forever if nothing stops it, and an Elasticsearch cluster with an ever-growing index degrades: queries slow, storage fills, and eventually the cluster is in trouble. The connector addresses this structurally by writing to daily time-based indices -- a new index per day, named by the date in the event's timestamp -- rather than one endless index. Daily indices make time-scoped queries efficient (a query for last week touches seven indices, not the whole history) and, crucially, make retirement possible: an old index can be dropped whole, which is cheap, instead of deleting documents from a live index, which is expensive. On top of the daily indices sits an index lifecycle management policy, and the connector treats it as part of the configuration rather than an afterthought. The policy rolls indices over and deletes them past a retention horizon, so the detection data has a bounded footprint by construction: it lives for the retention window and then ages out automatically. Making the lifecycle policy part of the config -- with a validated retention that must exceed the rollover period -- means an operator deploying the connector is deploying its data-retention story at the same time, not discovering months later that detections have quietly filled the cluster.

Part 5

Title

Sigma Detection Rules and End-to-End Testing

Body

As with Splunk, the events are half the integration and the logic is the other half. Elastic has a Sigma compiler, so the generated Sigma rules of Section 16.02 deploy into Elastic as detection rules that evaluate against the indexed detection documents, producing Elastic-native alerts. The portable logic runs on its second named platform, and because the rules are generated and versioned, keeping the Elastic-side detection rules in sync with the detectors is the same hash-driven redeploy as everywhere else -- no hand-edited Elastic rule to go stale. The connector is tested end to end on a stub Logstash transport. The tests assert the transform produces the right document: the daily index name derived from the timestamp, @timestamp set correctly, the nested request object populated, the full detection preserved, and the ECS version recorded. They check the explicit mapping types the facet fields as keyword and @timestamp as date, that delivery indexes every document in a batch, and that the emitted Logstash pipeline config has the input, filter, and output stages it needs. Testing the transform as a pure function -- separate from delivery -- is what the two-face design buys: the mapping that decides whether Kibana works is proven in isolation, and the delivery is proven against the stub. With the third connector complete, the platform set is done, and Section 16.06 builds the custom webhook for everything else and the enrichment that makes all these delivered detections actionable.

The Elastic Connector and Transform

elastic_integration.py

Description

Code

# elastic_integration.py
# Section 16.05: Elastic Stack Integration -- Logstash Pipelines
# 20260121 | AI Security Mastery -- Chapter 16 by Raghav Dinesh
# Single quotes throughout per book convention
#
# The third platform connector. Detections reach Elasticsearch through a Logstash
# pipeline that transforms them into ECS-aligned documents -- the transform is the
# heart of this connector. It builds both sides: the client that delivers events,
# and the pipeline/mapping definition that transforms them for Kibana.

import json
import time
from dataclasses import dataclass
from typing import Any, Dict, List, Optional


def sample_event() -> Dict[str, Any]:
    return {
        'schema_version': '1.0', 'event_id': 'req-3001:exfiltration_detector',
        'timestamp': '2026-01-21T12:30:00Z', 'detector': 'exfiltration_detector',
        'verdict': 'block', 'severity': 'critical', 'score': 0.95, 'confidence': 0.97,
        'latency_ms': 8.2, 'surface': 'output', 'request_id': 'req-3001',
        'session_id': 'sess-77', 'source': 'prod-gateway-1',
        'evidence': [{'source': 'aggregate', 'label': 'canary_triggered', 'detail': 'system prompt canary'}],
        'iocs': [], 'labels': {},
    }


def transform_to_es_document(event: Dict[str, Any], index_prefix: str = 'ai-detection') -> Dict[str, Any]:
    '''The transform a Logstash pipeline applies: a detection event becomes an
    Elasticsearch document with an @timestamp, keyword facet fields, a nested
    request object, and a daily index. This is the field mapping.'''
    return {
        '_index': f'{index_prefix}-{event["timestamp"][:10]}',
        '_id': event['event_id'],
        '@timestamp': event['timestamp'],
        'detector': event['detector'], 'verdict': event['verdict'],
        'severity': event['severity'], 'surface': event['surface'],
        'score': event['score'], 'confidence': event['confidence'],
        'request': {'request_id': event['request_id'], 'session_id': event['session_id'],
                    'source': event['source']},
        'evidence': event['evidence'], 'labels': event.get('labels', {}),
        'ecs': {'version': '8.11'},
    }


def elasticsearch_mapping() -> Dict[str, Any]:
    '''Explicit index mapping. Keyword fields aggregate in Kibana; a guessed text
    field would not. Applied at index creation, before any detection lands.'''
    return {'mappings': {'properties': {
        '@timestamp': {'type': 'date'}, 'detector': {'type': 'keyword'},
        'verdict': {'type': 'keyword'}, 'severity': {'type': 'keyword'},
        'surface': {'type': 'keyword'}, 'score': {'type': 'float'},
        'confidence': {'type': 'float'},
        'request': {'properties': {'request_id': {'type': 'keyword'},
                    'session_id': {'type': 'keyword'}, 'source': {'type': 'keyword'}}},
        'evidence': {'type': 'object', 'enabled': True}}}}


class LogstashTransport:
    def send(self, url: str, docs: List[Dict[str, Any]]) -> Dict[str, Any]:
        raise NotImplementedError


class StubLogstashTransport(LogstashTransport):
    def __init__(self) -> None:
        self.indexed: List[Dict[str, Any]] = []
    def send(self, url, docs):
        self.indexed.extend(docs); return {'errors': False, 'indexed': len(docs)}


@dataclass
class ElasticConfig:
    logstash_url: str = 'http://logstash.internal:8080'
    index_prefix: str = 'ai-detection'
    pipeline: str = 'ai_detection_pipeline'

    def validate(self) -> None:
        assert self.logstash_url.startswith('http'), 'logstash_url must be an http(s) URL'
        assert self.index_prefix and self.pipeline, 'index prefix and pipeline required'


class ElasticConnector:
    '''Push connector: POSTs transformed documents to the Logstash HTTP input.'''
    name = 'elastic'
    model = 'push'

    def __init__(self, transport: Optional[LogstashTransport] = None,
                 config: Optional[ElasticConfig] = None) -> None:
        self._transport = transport if transport is not None else StubLogstashTransport()
        self._cfg = config if config is not None else ElasticConfig()

    def send(self, events: List[Dict[str, Any]]) -> Dict[str, Any]:
        self._cfg.validate()
        docs = [transform_to_es_document(e, self._cfg.index_prefix) for e in events]
        resp = self._transport.send(self._cfg.logstash_url, docs)
        return {'indexed': resp.get('indexed', 0), 'ok': not resp.get('errors', True)}


def logstash_pipeline_config(cfg: ElasticConfig) -> str:
    '''Emit the equivalent Logstash pipeline config -- the artifact that runs in
    production. The Python transform and this config express the same mapping.'''
    return ('input {\n  http { port => 8080 codec => json }\n}\n'
            'filter {\n  date { match => ["timestamp", "ISO8601"] target => "@timestamp" }\n'
            '  mutate {\n    rename => { "source" => "[request][source]" }\n'
            '    add_field => { "[ecs][version]" => "8.11" }\n  }\n}\n'
            'output {\n  elasticsearch {\n'
            '    index => "' + cfg.index_prefix + '-%{+YYYY.MM.dd}"\n'
            '    pipeline => "' + cfg.pipeline + '"\n  }\n}\n')


if __name__ == '__main__':
    stub = StubLogstashTransport()
    conn = ElasticConnector(transport=stub)
    events = [sample_event(),
              {**sample_event(), 'detector': 'toxicity_detector', 'verdict': 'flag',
               'severity': 'medium', 'event_id': 'req-3002:tox', 'request_id': 'req-3002'}]
    result = conn.send(events)
    print('send result :', result)
    doc = stub.indexed[0]
    print('doc _index  :', doc['_index'])
    assert result['indexed'] == 2 and result['ok']
    assert doc['_index'] == 'ai-detection-2026-01-21'
    assert doc['@timestamp'] == '2026-01-21T12:30:00Z'
    assert elasticsearch_mapping()['mappings']['properties']['verdict']['type'] == 'keyword'
    assert doc['request']['session_id'] == 'sess-77'
    print('elastic transform + mapping + delivery: ok')

Code

# elastic_config.py
# Section 16.05: Elastic Stack Integration Configuration
# 20260121 | AI Security Mastery -- Chapter 16 by Raghav Dinesh
# Single quotes throughout per book convention
#
# Configuration for the Elastic connector. Detection data grows without bound, so
# an index lifecycle policy that rolls over and retires old indices is part of the
# config, not an afterthought.

import os
from dataclasses import dataclass, asdict
from typing import Any, Dict


@dataclass
class ElasticDeploymentConfig:
    logstash_url: str = 'http://logstash.internal:8080'
    index_prefix: str = 'ai-detection'
    pipeline: str = 'ai_detection_pipeline'
    ilm_rollover_days: int = 1
    ilm_retention_days: int = 90
    api_key_env_var: str = 'ELASTIC_API_KEY'

    def resolve_api_key(self) -> str:
        key = os.environ.get(self.api_key_env_var, '')
        assert key, f'{self.api_key_env_var} is not set -- Elastic API key required'
        return key

    def validate(self) -> None:
        assert self.logstash_url.startswith('http'), 'logstash_url must be an http(s) URL'
        assert self.index_prefix and self.pipeline, 'index prefix and pipeline required'
        assert self.ilm_retention_days >= self.ilm_rollover_days, 'retention must exceed rollover'

    def ilm_policy(self) -> Dict[str, Any]:
        return {'policy': {'phases': {
            'hot': {'actions': {'rollover': {'max_age': f'{self.ilm_rollover_days}d'}}},
            'delete': {'min_age': f'{self.ilm_retention_days}d', 'actions': {'delete': {}}}}}}

    def redacted(self) -> Dict[str, Any]:
        d = asdict(self); d['api_key'] = '(from ' + self.api_key_env_var + ')'; return d


PRODUCTION = ElasticDeploymentConfig()
SHORT_RETENTION = ElasticDeploymentConfig(ilm_retention_days=30)


if __name__ == '__main__':
    os.environ.setdefault('ELASTIC_API_KEY', 'demo-key-not-real')
    for name, cfg in [('production', PRODUCTION), ('short_retention', SHORT_RETENTION)]:
        cfg.validate()
        print(f'{name:16} retention={cfg.ilm_retention_days}d')
    print('ilm delete phase:', PRODUCTION.ilm_policy()['policy']['phases']['delete']['min_age'])
    print('api key resolves:', bool(PRODUCTION.resolve_api_key()))
    print('all elastic profiles valid')

Common Mistakes

Mistake 1

Description

Indexing detections with no explicit mapping and letting Elasticsearch guess field types

Why It Happens

Elasticsearch accepts documents without a mapping and appears to work, so declaring types feels unnecessary.

Consequence

Facet fields are guessed as analysed text and cannot be aggregated, so Kibana dashboards that count by detector or verdict return wrong or empty buckets.

Correct Approach

Ship an explicit mapping that types facet fields as keyword and apply it at index creation, so the first document is aggregatable and dashboards work.

Mistake 2

Description

Writing all detections to a single ever-growing index

Why It Happens

One index is simpler to name and query, and the growth problem is invisible until the cluster is large.

Consequence

Queries slow, storage fills, and retiring old data means expensive per-document deletes from a live index -- the cluster eventually degrades.

Correct Approach

Write to daily time-based indices governed by a lifecycle policy, so time-scoped queries are efficient and old indices are dropped whole.

Mistake 3

Description

Treating the Logstash transform as opaque config instead of a tested artifact

Why It Happens

Pipeline config lives in Logstash, not the codebase, so the transform is edited there and never unit-tested.

Consequence

The mapping that decides whether Kibana can aggregate is unverified, and a subtle transform error surfaces only as broken dashboards later.

Correct Approach

Express the transform as a pure, tested function mirrored by the Logstash config, so the schema-to-document mapping is proven in isolation.

Mistake 4

Description

Deploying the Elastic connector without an index lifecycle policy

Why It Happens

Retention feels like a later operational concern, separate from getting detections flowing into Elasticsearch.

Consequence

Detection indices grow without bound and quietly fill the cluster, and the retention gap is discovered only when storage runs out.

Correct Approach

Make the ILM policy part of the connector config with a validated retention horizon, so deploying the connector deploys its bounded-footprint story.

Section Summary

Compact

Section 16.05 builds the third and final platform connector, integrating the detector suite with the Elastic Stack, and it foregrounds the piece the Splunk and Datadog connectors hid: an explicit transformation and indexing stage. Detections do not go straight into Elasticsearch; they pass through Logstash, which transforms each event into a well-formed document before indexing. The connector builds that transform as a first-class, testable artifact -- a pure Python function mirrored by the equivalent Logstash pipeline config -- that maps the detection-event schema onto an ECS-aligned Elasticsearch document: the ISO timestamp becomes @timestamp, the flat detection fields become top-level facets, the request context nests into a request object, and the document lands in a daily time-based index. The quiet load-bearing part is the explicit Elasticsearch mapping: without it Elasticsearch guesses types, guesses string facets as analysed text, and silently breaks every Kibana aggregation, so the connector declares detector, verdict, severity, and surface as keyword, @timestamp as date, and the scores as float, applied at index creation before any detection lands. Detections write to daily indices under an index lifecycle policy that the connector treats as first-class config -- a rollover period and a retention horizon that bound the data footprint automatically, so detection indices cannot quietly fill the cluster. The generated Sigma rules deploy as Elastic detection rules over the indexed documents, and the whole path is tested on a stub Logstash transport, with the transform proven as a pure function in isolation from delivery. With Elastic complete, the platform set -- Splunk, Datadog, Elastic -- is done.
